# Web ChatGPT subagent

This route is **disabled for routine work until Owner explicitly enables it**. Owner-authorized trials may use GPT-5.6 tiers only. GPT-6 Pro is separately disabled until Owner explicitly enables that tier. The requirements are [the direction document](../../../docs/directions/2026-09-26-web-chatgpt-subagent-channel.md); this skill does not amend project routing or acceptance rules.

## Decide and prepare

Use this route only when all five conditions in direction §3 hold. Record a short estimate of Controller, Codex subagent, and web costs and why this route wins. Do not route local work, urgent repairs, or work that needs inherited context. Set a task-specific follow-up limit and a deadline before dispatch.

The Controller's dispatch work is limited to that §3 decision and assigning a **GPT-6 Luna subagent with no inherited task context**. Pass only task ID, GPT-5.6 tier, and the **absolute path** of the committed JSON task card so a projectless Luna can locate its repository. The Luna worker uses the repository-relative path for `prepare_dispatch.py`, follows the scripted route below, and returns one JSON line. Do not make the Controller operate the web page or repeatedly poll it.

Commit the self-contained task card to GitHub **before opening a new Chat conversation**. Include task ID, role, goal, repository, assigned branch, base SHA, exact read/write paths, success criteria, result path and the `docs/model-routing.md` result fields, applicable CI and task-class gates, return/stop conditions, and no main merge/publish/secret/signing authority. Use a fresh conversation outside Projects. The starter message contains only those routing fields; the task card is authoritative. Never send a prompt that relies on local files or private context. A web audit's write to its result file is only a reporting exception; it may not mutate the reviewed candidate.

Give every dispatch a distinct task ID. The ID identifies one logical prompt and one send attempt; never reuse it to send the same prompt again. Before staging, inspect the saved conversation for an existing turn with that ID. A lost tab or a journal error is a recovery problem, not a reason to resend.

Branch and path restrictions are instructions, not a proven connector permission sandbox. Verify the resulting GitHub commit's parent, branch, and changed paths. If a connector write returns an ambiguous transient error, re-read the assigned GitHub ref before considering a retry; honor any stronger task-specific stop rule. Existing high-risk audit slots, formal gates, and external final review remain in force. A matching model family does not prove equivalent role instructions, reasoning effort, tools, or audit acceptance.

## Browser and account boundary

Use only the Codex in-app browser. No tunnel, external/system browser, desktop Computer Use, private ChatGPT endpoint, cookie extraction, or `codex-with-chatgpt`. Observe the page directly. If sign-in, verification, permission, or account identity is in question, obey the foreground-browser invariant in the task's AGENTS.md. Stop at that boundary and report only the Owner login action when login is lost. Do not infer foreground visibility from a controlled tab.

**One web task and one ChatGPT tab at a time.** Before opening a tab, inspect the local ledger and count ChatGPT tabs in the Codex in-app browser's current inventory. If a web task is active, queue the new task or route it to a Codex subagent by the §3 cost test. If one ChatGPT tab already exists, do not open another. If more than one exists, do not send; verify which tasks have GitHub results, close their completed tabs, and inspect the inventory again. Before Send, require exactly one ChatGPT tab and confirm it belongs to this task. Never treat an automation tab as proof of foreground identity for a login or verification page.

If any ChatGPT page shows a “suspicious activity” warning or security verification, stop **all** web dispatches immediately. Run `python scripts/ledger.py cooldown --reason suspicious_activity` or `--reason security_verification`, notify Owner, and return every queued task to Codex for at least 24 hours. Do not retry, dismiss the warning, automate the verification page, or switch accounts. The cooldown survives restarts and does not clear automatically when its timestamp passes. After the full 24 hours, the Controller may manually verify the page is safe and run `clear-cooldown --observed-at ISO_TIME --evidence NOTE`; if verification is still shown, stop at the foreground-browser boundary. An ordinary logged-out page without a security challenge still stops at the Owner login boundary. Future cooldown demonstrations must set `LOCALAPPDATA` to a temporary test directory; `clear-trial-cooldown` only clears a legacy `trial_simulation` record and cannot clear a real warning early.

Immediately before each send, inspect the final composer on the same page: saved, non-Project conversation; intended task ID and GitHub routing fields; selected model family **and** thinking tier. Close menus and verify the resolved composer label, not a model merely listed in a menu or an ambiguous `Latest`. If any field differs, do not send. Never select GPT-6 Pro unless Owner has enabled it and the local ledger says it is enabled. If the page shows a limit or downgrade before sending, stop. After each send, look for the actual reply model and visible downgrade/limit notices. If it switched or a limit appears, mark the requested tier exhausted and record the page's displayed reset time if available; stop that tier. If the page exposes only the *next composer selection* and no per-reply served-model identity, record the reply model as **unverified** and do not assert that the planned tier actually served it. Do not silently accept a fallback model as the requested work product.

After clicking Send once, **never click Send again for that task ID**, even if the button, tab, or tool reports an error. A new user turn followed by a new assistant turn in the saved conversation is the confirmation that the prompt was submitted. A cleared composer, Stop button, click return, or URL alone is insufficient. If submission is uncertain, preserve the conversation and inspect it read-only; mark `uncertain_submission` and return to Codex if it cannot be resolved. If the reply's served model is unverified, charge the requested tier with `complete-unverified ID` and keep the served tier explicitly unknown; do not guess `actual-tier`. If the answer shows no new evidence for five minutes, mark `stalled` without resending. After about 20 minutes, observe at low frequency; a local wait timeout does not terminate the browser task. Report login loss as `needs_login`, separate from a timeout.

## Local ledger

The script at `scripts/ledger.py` stores state only at `%LOCALAPPDATA%\gogoke\web-chatgpt-subagent\state.json`. Its scope is messages sent by **this skill and the web construction seat from the ledger's start**. Earlier account usage and Owner's manual ChatGPT use are unknown and not counted. A new or lost state file blocks dispatch until the Controller runs `reconcile --source NOTE`, which records the current start time and known local ledger counts; no Owner history request is needed. All participating automated Chat seats must use this ledger from then on. Never commit state, account usage, reset timestamps, or conversation links to this public repository.

Use `python scripts/ledger.py status` to inspect caps, active web task, cooldown, and usage. `reserve --tier TIER --task TASK_ID --seat SEAT` atomically charges one message and claims the sole active web task. After a confirmed Send, `mark-sent ID --url URL`; after an uncertain click, `mark-uncertain ID --reason CODE`; only an unsent reservation may be `release`d. A sent reply with independently visible served-model evidence uses `complete ID --actual-tier TIER [--seconds N]`; a different actual tier **requires** `--switched` and charges both the requested and actual tiers conservatively while blocking the requested tier. A visible limit with no reply uses `limit-hit ID [--reset-at ISO_TIME]` and a Codex fallback. Record other Chat seat sends through this same ledger. Daily defaults: 6 Pro 25, 5.6 Sol Pro 120, Extra High 12, High 20, Medium 30; the two Pro tiers together have a 200/day ceiling. The script does not guess the vendor's reset time or unpublished limits. `reset-tier` requires an observed reset timestamp and a reason. `enable-6-pro` requires Owner's explicit decision recorded in a local note. The route itself remains disabled until Owner adopts this skill.

## Low-cost Luna dispatch

The documented in-app-browser tool cannot access `%LOCALAPPDATA%` or run shell commands in one call. Use three serialized tool calls from the **same Luna worker**: (1) run `python .agents/skills/web-chatgpt-subagent/scripts/prepare_dispatch.py --task ID --tier TIER --card REPO_RELATIVE_JSON`, which verifies the pushed card, reserves the tier, and emits ASCII-safe JSON containing the browser script; (2) pass its parsed `browser_code` unchanged to one `mcp__cua_repl.js` call; (3) run `python .agents/skills/web-chatgpt-subagent/scripts/finalize_dispatch.py --task ID --status RESULT [--clicked] [--url URL] [--reason EXACT_BROWSER_REASON]`. Pass through a refusal or failure reason exactly so the private receipt explains it. On the first use of CUA in a fresh worker, its mandatory one-call initialization comes before step 2. The worker returns only the final structured JSON line. A Luna subagent opens a background IAB tab; if login or security verification appears, stop at the foreground-browser boundary. Do not add manual Send clicks or re-run step 2 to repair an error.

Step 3 records sent, unsent, uncertain, login, or security outcomes and starts `scripts/watch_github_result.py` for a sent task. The watcher checks the assigned GitHub branch/file in a background Python process, uses a lower polling frequency after 20 minutes, and queues one candidate notice to the configured Controller chat. It never polls the browser or calls a model. The Controller verifies the GitHub commit, scope, CI, and local ledger; a Luna report or watcher notice is only a lead, never acceptance.

## Return and acceptance

Retrieve the result from GitHub only. An audit result names the reviewed commit SHA; construction uses its assigned branch and a checkpoint. Inspect the precise result, branch/commit identity, and real Actions run with nonzero tests. Read logs when the run is claimed as evidence. A web reply saying “done” does not count. Record local duration, tier/message count, Controller token cost when available, rework, and any downgrade/return.

For post-reply model inspection, the reply's own “retry / switch model” menu is read-only evidence **only if it states the model that served the existing reply**. A menu item saying “retry with 5.6 Sol” or “retry with 5.6 Pro” is a future choice, not identity proof. Do not click Retry or select a model. If no served-model field appears, record `reply_model_unverified` and use `complete-unverified`; a visible downgrade or limit still blocks the tier.

As soon as the GitHub result is confirmed, close that task's ChatGPT tab and verify the browser inventory has no ChatGPT tab. Then run `finish-task --task TASK_ID --result-commit FULL_SHA` to free the active slot. Do not free it merely because the reply ended, the tab vanished, or a local wait timed out. A task whose result is not yet confirmed keeps the active slot; other work queues or returns to Codex.

On timeout before Send, browser failure, exhausted tier, or model mismatch, stop this dispatch. Change tier only if the exact task card preauthorizes it and its task-class gates still hold; otherwise return to a Codex subagent. Do not repeat the same failed question beyond its follow-up limit. For a pre-send fallback, append a local event to `%LOCALAPPDATA%\gogoke\web-chatgpt-subagent\trial-events.jsonl` with task ID, timestamp, `web_not_sent`, exact reason, and the Codex subagent handoff identity. Release any unsent reservation. Keep the public trial summary free of account usage figures and conversation URLs. Owner alone decides formal enablement, `docs/model-routing.md` changes, and PR merge.
