# Web ChatGPT subagent

This skill is a **draft trial**, not an enabled project route. PR #48 stays draft and `docs/model-routing.md` is unchanged. The Owner's 2026-09-25 decision authorizes **one GPT-6 Pro Send trial**; WCS-22 and WCS-23 stopped before Send and did not consume that authorization. A pre-Send task-card or path correction may continue under the same task ID while its reservation is still live; if the ID has been released and retired, use a new ID for a distinct authorized trial. The no-follow-up rule applies after a message reaches GPT. GPT-5.6 is no longer a dispatch target. The Owner's later decision controls conflicts with the earlier direction document. OpenAI's [Help Center](https://help.openai.com/en/articles/20001354-gpt-56-and-gpt-6-pro-in-chatgpt) describes “GPT-6 Pro, powered by GPT-6 Astra” and warns that exhaustion may automatically switch to GPT-5.6 Thinking Medium. Pre-send selection cannot prove the model serving the reply. Formal adoption requires an Owner decision on that limit.

## Controller decision and task card

Before **each** task, establish all five conditions: (1) it would otherwise go to an Astra subagent and its Codex cost is clearly above the roughly $0.72 fixed web overhead observed in WCS-20; (2) one complete task card plus GitHub files suffice, without inherited context (`fork_turns`) or mid-task questions; (3) no local signing, Win11/Smart App Control test, real CLI integration, or local chore; (4) a half-hour wait does not block the critical path; (5) GitHub can prove the result by a fixed-SHA report or assigned branch **and real CI with more than zero executed tests**. Astra-class is necessary, not sufficient. Ordinary PR review, medium/small work, iterative diagnosis, and urgent work stay with Codex.

Record in the private ledger reservation **one line stating the economic reason and original Astra seat**. Prepare a self-contained task card with task ID, repository and immutable card SHA, fixed review SHA/base SHA, assigned branch, allowed read/write paths, result file, success criteria, deadline, and fallback. **Before committing each card**, run `python tools/check-public-source.py --file PATH_TO_CARD --self-test --quiet` and require `leaks=0`, then run `python tools/check-public-source.py --quiet` for the already committed tree. The default scanner reads HEAD and otherwise misses an uncommitted card; keep local user-profile paths out of the public card. Then commit and verify the card's remote full SHA. The card instructs GPT to send one reply/task only, ask no questions, and on missing information or blockage write the blocker in its result file, commit, and stop. Within that one task it may inspect CI and repair its assigned branch until green. The card must forbid pushes outside its assigned branch, main push/merge, releases, tags, publication, keys, secrets, and signing. Public main is unprotected: record main's SHA before dispatch and compare it afterward. An unexpected commit stops the route and is reported to Owner. A web audit may write only its result file, never the reviewed candidate.

The Controller dispatches one **Luna subagent without inherited context**, passing **only task ID and absolute task-card path**. The card has two distinct roles: `luna_action` is the courier procedure; `web_starter_message_template` is the text to send to ChatGPT. **Luna must not perform the web task, create its result branch, write its result file, or push the result.** WCS-22 demonstrated that a card describing only the reviewer role can cause Luna to do the audit itself without any web Send. Luna follows this skill step by step and returns one structured line. The Controller does not operate the ChatGPT dispatch page; the explicit exception is its safe-page inspection after a real 24-hour security cooldown. During Luna's page phase the Controller waits once with a long `wait_agent` timeout; Luna completion or abnormal stop wakes it immediately. Do not repeat progress messages while waiting.

## Browser and safety boundary

Use only the Codex in-app browser; no external browser, private ChatGPT endpoint, cookie extraction, local browser script, or visible desktop window. Luna reads fresh page state after each meaningful step. For login, authentication, MFA, QR/verification codes, passwords, permissions, or any user-interaction step, the **only** authoritative page is the user's currently focused Codex in-app-browser URL in the latest Owner ambient state. A controlled/background/matching tab is never proof of what Owner sees. Do not claim a page is visible, ready, or awaiting Owner input unless a later Owner turn reports that exact focused URL. Never request input in an automation-only tab or automate a sensitive page when foreground identity cannot be proved. Stop at that boundary, report the raw state, and do not continue after an identity mismatch. If Luna cannot see IAB again, record Luna's **raw** browser state and the Controller's **raw** browser state. Do not change task ID to bypass WCS-18's unexplained mismatch.

Only **one active web task and one ChatGPT tab** may exist in the entire IAB. Before reservation and before Send, count ChatGPT tabs and read the ledger. Do not open a new tab while one exists. If more than one exists, send nothing; identify completed tasks from GitHub, close those tabs, and recount. One task uses one tab, closed immediately after GitHub result confirmation. If a pre-existing tab cannot be identified safely, stop. A task awaiting GitHub remains active; queue new work or return it to Codex.

On any “suspicious activity” warning or security verification, Luna stops all web work and calls hidden `cooldown --reason suspicious_activity` or `security_verification`, then tells the Controller to notify Owner. State blocks all dispatches for at least 24 hours across restarts, with no retry or automatic recovery. After 24 hours only the Controller may verify a safe page and explicitly clear it. Demonstrations use temporary `LOCALAPPDATA`, never the real ledger.

## Luna's one Send

1. Read the task card from its **card branch at a verified immutable full commit SHA**; it may be absent from the older review/base SHA and from the not-yet-created result branch (WCS-13). Verify ID, branch, SHA, paths, stop rule, and prohibitions. Read hidden ledger `status` and IAB inventory. Require no cooldown, no active task, a reconciled baseline, GPT-6 Pro enabled for the authorized trial, and zero ChatGPT tabs before opening one. A zero-tab IAB is a valid starting state; the mere possibility of later login is not a reason to stop before opening (WCS-15). Reserve once: `Invoke-LedgerHidden.ps1 reserve --tier gpt-6-pro --task ID --seat web-channel --original-seat astra --economics "ONE-LINE REASON"`. Keep the reservation ID. Failed/released IDs are retired.
2. Open one fresh non-Project ChatGPT conversation **in the background**. In a Luna subagent, `cua.createBrowserTab("iab", "https://chatgpt.com/", {visible:false})` is the supported form; `visible:true` returns `IAB visibility is not supported in a subagent thread` (WCS-08, WCS-23). Confirm a blank conversation by its actual new-chat URL and **zero existing message turns**; do not require a legacy Chat radio button (WCS-09). On actual login or verification, stop. Preserve an unrelated draft and stop. Let the page settle and reread it if the model/tier pill is absent from the first accessibility state (WCS-10); do not treat one early missing pill as a permanent absence. If the pill initially reads `中`, open it and inspect `思考强度` and nested `选择模型` instead of assuming the model family (WCS-16). Move the thinking slider to the far right, then verify the **resolved composer label says `6 Pro`**. A menu option, `Latest`, or old title is insufficient. If the stable page still lacks the control, it is ambiguous, or the label differs, do not Send. Check limit/downgrade notices and any “已使用记忆” or similar memory-use indicator; report any such indicator. Paste the one complete starter message, verify exact ID/routing fields and `6 Pro` again, count exactly one ChatGPT tab, then click Send **once**.
3. After the click, never click Send again for that task even if the tool errors or the composer remains. A new user turn **and** new assistant turn in the saved conversation prove submission; then hidden `mark-sent ID --url URL`. If ambiguous, `mark-uncertain` and stop; no resend or alternate ID for the same work. If answer evidence stops changing for five minutes, mark stalled, not resent; after about 20 minutes observe infrequently. Report login expiry explicitly. A visible limit with no reply is `limit-hit`; visible automatic downgrade uses `complete --actual-tier DISPLAYED --switched`, blocks 6 Pro until observed reset, and cannot be accepted as a 6 Pro result. If no per-reply served-model identity appears, use `complete-unverified`; never infer identity from a future “Retry with...” choice. Never click Retry.
4. **Pre-Send abort:** if Luna entered text, that same Luna clears the composer immediately and reads it back empty **before** releasing reservation and closing tab. If it cannot verify empty, retain reservation and report blocker. If Luna never staged text, it may release and close. A task-card or helper-path mistake found before Send may be corrected and rechecked without asking web GPT or consuming the one authorized Send; do not click Send while the correction is unresolved. After confirmed Send, mark the **ChatGPT conversation tab** for handoff (not the earlier GitHub card tab, WCS-11/12/14) and start the hidden GitHub watcher with `gpt-6-pro`, assigned branch/file, base SHA, and Controller thread ID; return one JSON line. Do not wait for GitHub inside Luna's browser turn.

Every `ledger.py` call uses **`.agents/skills/web-chatgpt-subagent/scripts/Invoke-LedgerHidden.ps1` relative to repository root**; resolve its local absolute path from the checkout at runtime and never commit the user-profile path. It starts `pythonw.exe` with `CreateNoWindow=true` and `WindowStyle=Hidden`; require receipt `exit_code=0` and `console_window_present=false`. Start watcher with **`.agents/skills/web-chatgpt-subagent/scripts/Start-WatcherHidden.ps1`**; it uses `pythonw.exe` and launches `gh`/`codex queue` with `CREATE_NO_WINDOW`. There is no `scripts/` directory at repository root. Do not run `python.exe ledger.py` or normal visible `Start-Process`. Watcher checks 6 Pro every 90 seconds, then every five minutes after 20 minutes, and notifies the Controller on a GitHub candidate. Controller waits for that notice or one deadline-bound long wait; no 30-second model polls. Report progress only when sent, result verified, or abnormal stop.

## Controller verification and terminal result

Treat Luna's line and watcher notice as leads. Read the **real local ledger** and GitHub commit. Verify ID, assigned branch, exact reviewed SHA/base parent, allowed diff, report content, main's SHA, and a **real Actions run on the result commit with executed test count > 0**. A green badge with skipped/zero tests is insufficient. Read raw CI logs. If the watcher does not notify by the task deadline, inspect its private receipt once for an unannounced candidate, `notification_error`, or `watch_deadline_exceeded` (WCS-20); do not keep polling through the model. If the existing tab survives, assign the **same Luna** a read-only check of the reply's own model controls, then close that tab immediately after GitHub confirmation and report its inventory. The Controller does not inspect the ChatGPT reply or click its controls. Retry menu future choices do not identify served model. If the tab vanished before inspection, state that neither served model nor explicit close was verified. Hidden `approve-result --task ID --commit SHA` then `finish-task --task ID --result-commit SHA` run only after verification and close/inventory check.

If result blocked, incomplete, or unacceptable, **no follow-up and no new ID for the same work**. `finish-task --task ID --fallback-agent NAME --reason REASON` records one-shot failure; hand result file to a Codex subagent. For timeout add `--timed-out`; the ID is immediately void. Later commit is only `late-result --task ID --commit SHA`, never accepted, merged, or counted as success. Ledger records **one-shot task completion** separately from `served_model_status`. An approved result with `served_model_status=unverified` is task completion evidence, **not** proof that 6 Pro generated the reply. Repeated task failures narrow eligibility. Missing/uncertain send is a stop for Controller investigation, not Luna workaround.

The private ledger at `%LOCALAPPDATA%\gogoke\web-chatgpt-subagent` counts **only messages sent through this skill from its reconciled start**. Historical, Owner manual, and other web-seat use are unknown, though all share the account-wide weekly 6 Pro allowance described by OpenAI. New/lost `state.json` blocks reservation until Controller `reconcile --source NOTE` records “baseline begins now; earlier use unknown”; no Owner history request. `task-ids.jsonl` prevents ID reuse across state loss. Only dispatch counter is 6 Pro, capped at 25 skill messages per local day; this is a risk limit, not proof of provider allowance. A limit/downgrade blocks 6 Pro until a visible reset is recorded. Never commit private state, account usage figures, or conversation links to this public repo.
