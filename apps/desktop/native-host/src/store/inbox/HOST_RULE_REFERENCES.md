# C host rule escalation notice

## Direct product sources

- `seat/policy.rs` writes one E `INTENT` keyed by domain and trigger. The sealed host cause adds the original gate event, source seat incarnation, Owner route revision, and fixed notice body. New C enqueue and reserve revalidate that cause and matching original E intent. Root must compose E begin and C enqueue in one Owner transaction, so a policy change cannot strand an E-only intent without its original C body and route revision. Once reserve writes `PREPARED`, recording `UNKNOWN` is a fact about that same operation and reads the original C/E request instead of requiring the current route or a live recipient.
- `inbox/mod.rs` already owns the message and operation rows, exact request byte replay, pending/unknown/applied phases, and CAS revisions. The host path uses those same rows. Its pending `turn_id=''` and `generation=''` mean no vendor turn has been bound. `sender_seat_id='HOST_RULE'` identifies the actor; the source seat remains a fact in the original request and E chain.
- `session_transport/journal.rs::complete_codex_turn_request` issues `K-SESSION/send` `APPLIED` only after an original Codex `TurnStart` response is observed in A/RPC custody. `read_stdin_journal` checks that same stored request, ticket, generation, process custody, and receipt, including stopped historical readback. C also reads the original A/RPC step and raw response; it decodes the exact stored `TurnStart`, original thread and body, and typed turn response before binding the turn. Historical settlement reads the original C request, E INTENT/event, and H/A receipt; it does not require a newly valid route after the original send.
- `product_database/v37_inbox.rs` uses the User `cancel` operation without a live turn target, so Owner can cancel an unbound pending host notification with an original User CAS fact. Its User edit, requeue, deliver, and steer paths must reject `HOST_RULE` rows in the shared dispatcher. A cancelled row is never reserved by the host path.

## Adopted references and limits

- Historical `packages/room/src/server.ts` and `seat-runtime` delivery tracking, as indexed by `docs/research/gogo-ui-2026-09-13/研究覆盖与缺口.md`, demonstrate persistent queued delivery and unknown/retract semantics. They do not supply native C/H/E authority or an observed vendor turn receipt; this package keeps those checks in the existing product journals.
- `docs/research/2026-09-26-experiments-1-and-4.md` distinguishes busy queueing from idle sends and notes that automatically starting models may consume quota. The host rule only uses the Owner-authorized escalation category and E's fixed notice. The product coordinator chooses dispatch timing; C does not invent a scheduler or a new grant.
- `docs/research/2026-09-26-kernel-candidates-architecture.md` compares external inboxes. Their delivery algorithms are not proof that a GOGO recipient was reached; this path needs the exact original H ordinary-send receipt.

An H `APPLIED` without `createdTurn=true` and a `turnId` does not settle this Codex TurnStart binding. Other provider turn contracts require their own pinned, observed typed evidence. A process write, generic exit, `AppendWithoutTurn` ACK, model prose, or E intent alone cannot change C to `DELIVERED`. An original `UNKNOWN` stays bound to its single request ID and is not sent again merely because recovery has no receipt.

The shared H ingress must reserve the `hostsend-` request-ID namespace for the internal Owner/E/C path. A User or model `K-SESSION/send` with that ID would otherwise occupy H's one request journal before the host rule and misattribute a genuine provider turn to the wrong actor. A reserved prefix is a rejection rule at public ingress, never itself authority to send. A route to `OWNER` has no recipient seat session for this H binding and remains pending for the product's separate Owner notification path.
