# Credential metadata registry

This F module stores metadata and durable namespace/ACL intents on the verified
product connection. Production code opens no file and accepts no path, credential
content or content hash. Root/H verifies actual held source/parents, startup mode,
original native configuration response, current A/H authority and quiescence.

`initialize_credential_schema` is an explicit composition hook after the existing
instance initializer. Its independent `gogoke_v37_credential_` family accepts only
exact absence or four exact tables. Partial/changed families, TEMP shadows and
arbitrarily named side-effect triggers/indexes are refused without recreation.
F's existing six-table schema and migration remain unchanged.

Backend evidence retains the original STOPPED process operation, ticket, nonce,
generation, F home/pin/version and non-secret backend enum. Usability additionally
binds the original account/config observer to global custody with profile equal
to the registered instance; a stopped project model process is not that source.
Usability additionally
requires a separately verified `FILE_BOUND` startup selector. A configuration
response containing File alone is insufficient. Other/Unknown never converts to
File. `read_configured_credential_backend` returns the original enum/selector after
the same current pin/home and stopped-custody checks; it grants no usability.
Root checks a known File configuration before its new File-bound observer, and
only records usable evidence after actual account/presence success and STOPPED.
The source object first binds only at link count one. Replacement requires
an explicit old identity/revision plus all aliases removed, all profiles revoked
and no unresolved credential intent; Root supplies actual instance quiescence.

Alias/profile begin writes the original complete framed metadata fingerprint to
F's existing operation journal before Root/H performs a side effect. Only a New
receipt indicates a newly reserved operation. Pending/Unknown retains the same
operation for exact metadata reconciliation; another request cannot replace it.
Complete records only the original physical result and cannot grant new use.
It compares original source/scope/profile identities and the full registered alias
link count, including pending entries and excluding removed entries. An unknown
other alias cannot be omitted to make a successful receipt. New creation, alias
reactivation and profile grants recheck current backend and F bindings. Backend
changes cannot block accurate original receipt reconciliation, revoke or removal.

References: reuse `instance/private_history.rs` F identity/generation rows and
`instance/registry.rs` framed operation journaling; use the actual
`authority/process_custody.rs` schema fields rather than a guessed process table.
Root/H's credential witness supplies exact object/alias metadata and handles ACLs;
no general hard-link exception, second purpose/native-thread authority or wire
operation is introduced here. The earlier native F implementation remains the
source for schema refusal and commit/rollback uncertainty handling.

Tests invoke the product metadata APIs with an owned verified test DB and explicit
synthetic metadata receipts. They open no auth file and qualify no physical link,
credential refresh, real ACL or startup behavior. Native compilation/tests follow
`docs/governance/gogoke-build-and-release.md` in Windows cloud CI. Actual source,
alias, profile and installed Win11 qualification depend on Root/H integration.

R5/R6 cleanup boundaries: whole-instance original H/global custody must be
stopped before the no-source return. A later login can reconcile REMOVE_PENDING
only by reading the alias's original journal key, decoding exactly eight canonical
length-framed fields and checking its key, revision, registered source/home and
history identities. The original input reselects the existing pending receipt;
the later login request never replaces it. UNKNOWN remains retained. Physical
completion uses H's read-only removed-name/link-count witness and never retries
deletion. The two credential_launch cleanup tests exercise the actual SQL and an
empty exclusively owned synthetic file; no credential contents are read and no
real credential or native process qualification is claimed.
