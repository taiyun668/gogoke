# Private continuation directory binding

F owns registered-instance child directories and their durable creation receipts.
SESSION/CALL homes retain the existing temporary lifecycle. H owns the current
episode, STOPPED proof and provider continuation; A retains session purpose.
The native composition must check those original facts before constructing an
F resume selection and again before activating the child. Existing continuations
without the recorded F binding are refused and preserved.

The two new tables retain initial H binding/generation/open-request provenance,
domain/session/seat/incarnation, root/parent/instance/leaf identities, and exact
H physical-response source references for each generation. They never contain
purpose, native thread identity or credentials. A new initial binding always
gets a fresh child. Resume records a new generation against the selected existing
child and never creates another directory.

Creation follows F registry's durable-intent, physical-receipt, final-row order.
The name is a Host-derived framed hash, never an IPC path. A replay without a
committed physical receipt is refused even when the directory is absent. The
same unresolved operation cannot choose a new directory identity. DirectoryRoots
holds the existing shared namespace handles through actual child stop; only the
leaf is an execution mapping. The instance parent is retained solely for custody.

Schema initialization recognizes only exact empty, pre-cap three-table,
pre-history four-table and current six-table shapes. Migration adds missing
tables in one transaction and preserves existing instance rows and caps. Unknown,
partial, shadowed or side-effect schemas are refused without recreation.

## References

Adopted `instance/registry.rs` creation journaling and registered-home checks,
`instance/temporary.rs` framed request fingerprints and same-connection writes,
and `process/session/compat_module.rs` shared DirectoryRoots namespace custody.
The direct child layout avoids adding another shared container and its identity
journal. `session_transport/episodes.rs` and `rpc_journal.rs` remain the source
of H generation/response facts; `ledger/mod.rs::read_registered_session` remains
the current A source. The repository research on CliDeck lineage preserves native
identity distinctions but supplies no physical private-directory implementation.
The prior gogo-party/NaveHQ file inventories supplied no replacement for these
current native mechanisms; no historical authority implementation was imported.

Build and test execution follow `docs/governance/gogoke-build-and-release.md`:
native compilation and the four focused F safety tests run in Windows cloud CI.
They cover current identities/custody, exact generation source selection and
cross-scope refusals, missing physical commit preservation, and immutable response
source attachment. Instance schema tests additionally cover both known migrations
and unknown/shadow schema refusal. The focused F tests establish no H/A acceptance,
credential-alias qualification, or installed native end-to-end result; those
remain dependent on Controller integration and the stable candidate workflow.
