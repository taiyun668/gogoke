## Production paths and evidence limits

- HA-02: the former retained-Claude unit fixture was removed after direct cloud evidence showed a live child with no initialization frame, and source review showed that its fresh home had no real authentication or ordinary User turn. Claude has no thread identity until that ordinary turn. Synthetic LoggedIn presence and a made-up assistant frame cannot establish normal Claude behavior. `tools/e2e/m2-provider-readback.py` now checks the genuine Claude question/Write flow's original H terminal receipt and A raw bytes, and rejects any Codex-only health action or generation change in that actual session. Real authenticated Claude/model/Win11 execution remains **NOT_RUN**; the handshake's underlying cause is not inferred from its deadline.
- HA-03: `health_compact_late_original_ack_continues_without_second_write_or_new_request` enters the real sealed source hook and actual native compact writer. A TEMP trigger fails only the original compact OBSERVED transaction after its actual H writer succeeded, retaining the exact WRITTEN command and original A reply. After dropping the fault, the production continuation gate must reconcile original A before its ACK predicate, with unchanged request ID/raw hex, command bytes/ID and native RPC ordinal. ACK alone leaves ACKED, with no completion receipt. Direct cloud evidence established that the retained compact turn was still active: the old synthetic item named another turn and supplied no matching terminal. The corrected explicit A controls use the actual retained turn, assert that its item alone still fences generation stop, then supply that turn's terminal before native stop/resume and settlement. Production stop protection is unchanged. A TEMP audit counts successful production WRITTEN transitions immediately following OS write; the count remains one. These synthetic authority controls are not a model, pipe-golden or vendor-compaction claim. The actual no-model history append/resume and H step/receipt facts remain production operations.
- HA-04: `health_terminal_and_ordinary_ack_orders_keep_one_original_seal_and_no_work_resend` covers both ACK/receipt-before-terminal and terminal-before-ACK/receipt. In the latter, the terminal is already normalized/RESOLVED while its H ordinary receipt is absent; no seal is minted then. The delayed typed ACK retains the same `run.turn_id` as the actual Reply::Turn branch; production pending-output readback must clear that resurrected state from the original resolved terminal. Production H receipt recovery then completes the original request, and production `revisit_host_health_sources` creates exactly one E observation from the original source. Duplicate terminal and repeated revisit do not overwrite source, allocate IDs, resend work or create action permits.

The fixture reuses the existing test's real fixed CLI registration, actual worktree creation, H admission/open, native process/custody and current launch identity. Only LoggedIn presence is synthetic; this does not establish authentication or model readiness. Ordering source bytes and the ordinary send's WRITTEN/OBSERVED association are explicitly synthetic controls through the existing SQL seam/`install_sql_fixture_cursor`; no ordinary model prompt is written. H prepare/RPC prepare and production `recover_codex_turn_request` create/check the actual original request/receipt relation. No HostHealthProof constructor, alternate factory or manually inserted E health row is used. These are authority/permit source controls, not claims that a real model emitted these errors or that the injected frames crossed an actual CLI stdout pipe. Complete real-pipe/V13 evidence remains separate.

`revisit_host_health_sources` was made `pub(super)` by Controller solely to call the actual safe-point source work without triggering an action in the ordering controls. No new testing API or measurement field was added. Assertions inspect original A resolutions, E health rows, H generation raw request/phase, original RPC command and production WRITTEN transitions. They do not assert a hardcoded test implementation of health policy.
