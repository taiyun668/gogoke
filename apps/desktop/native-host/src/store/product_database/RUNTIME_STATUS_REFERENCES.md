# Current CLI error display facts

Reused historical gogo-party per-session `lastError`, the existing native H/A raw source and provider terminal decoders, and the current instance-list bridge. Research `reuse-blueprint.md` separates runtime observation from policy decisions; no runtime display fact is a model grant or automatic health decision.

The native instance list reads only episodes bound to that instance and the seat's current incarnation/generation. Every displayed source keeps its original process operation, ticket, custody epoch, session and cursor. Codex failed terminals and protocol error replies, Claude's strict boolean `is_error` result, and ACP protocol error replies provide the error text or canonical original error object. Assistant prose and permission cards do not set an error. A later successful terminal clears that same session's earlier display error. Unknown quota classifications remain ordinary CLI errors; no text matching claims that quota is exhausted.

The facts are Owner-private read results. They do not mutate login state, choose another instance, upgrade a CLI, open a credential file, send input, or issue a health action. The existing response-size bound still applies. Frontend preview is a K-UI fake and is not real provider evidence. Exact CLI-boundary/Win11 V13 behavior remains NOT_RUN until the stable candidate is tested.
