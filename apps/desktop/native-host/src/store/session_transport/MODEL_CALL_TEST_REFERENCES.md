# H/A model caller permission controls

The permission boundary is model output becoming a native seat caller: model arguments cannot select Owner or grant themselves rights, substitute another process/source/turn, or keep write authority after the original turn or process ends. These tests call the production factory and transaction revalidation directly; they never construct a test-only `NativeSeatCall` or reproduce its authorization checks.

References: historical gogo-party `experiments/process-supervisor/README.md` separates process probes from product acceptance, and `docs/research/source-audit/06-runtime-protocol-and-adapter-sources.md` keeps protocol fixtures inside adapters. This repository's `docs/research/2026-09-26-kernel-parts-harvest.md` assigns process custody to the Rust host. The current A `ledger::tests::raw_process_fixture` supplies the native signed-system-command/Job pattern; H `journal::tests::observed_codex_response_recovers_original_receipt_after_write_failure` supplies the historical RPC control.

Adopted: production schemas, actual `ProcessCustodian` stdout frames, `ledger::capture_raw_source`, production command encoding and original user receipt completion. Difference: system CMD relays synthetic JSON lines from a temporary text file so shell quoting cannot change the bytes. Synthetic H admission rows and OBSERVED RPC controls isolate the permissions predicate; they do not demonstrate fixed-CLI authentication, LPAC admission, model delivery or installed-product behavior.

Four Windows tests cover original H identity despite Owner claims; stable request identity under repeated raw cursors and distinct numeric/string RPC IDs; missing or foreign sources and wrong turns; conflicting raw bytes, completed turns, current claim/binding/incarnation changes, missing original user/start evidence and a real native stop proof. Each rejection has a valid positive control. Temporary rows changed in controls are rolled back or removed within the fixture only.
The current-claim control also uses H's original committed `stop_request_id`:
capturing a stopped process's tail remains required, but the stop intent already
ends that process's ability to mint or spend a model caller. This rejects new
effects before the later physical proof and durable STOPPED commit; ordinary
historical output capture and original RPC receipt observation remain separate.

The appended test module is included by the existing Windows full library command in `.github/workflows/gogoke-native-host.yml`: `cargo test --locked --manifest-path apps/desktop/native-host/Cargo.toml --lib -- --nocapture`. Per `docs/governance/gogoke-build-and-release.md`, no native compilation or execution is performed locally. Native tests and production mutation remain **NOT_RUN** until Controller runs the cloud checks on the integrated bytes; this delivery is not acceptance.

Later child release controls refer to `product_database/NATIVE_CHILD_CONTROL_REFERENCES.md` and the existing E takeover/scope/grant checks. The host Owner issuer is created by production bootstrap, the parent caller is sealed by the same real H/A factory, and the child stop is observed by a second `ProcessCustodian`, committed by `authority::mark_process_stopped` and bound by `admission::record_session_stop_in_transaction`. Synthetic child admission/settings rows isolate `runtime::release_native_with_origin`; the fixture does not demonstrate a real model dispatch or the gateway's wire framing.

Two release tests require BUSY to become IDLE with its generation advanced once; the exact old release bytes must then return REPLAYED without another state change. Stale child generation, foreign parent, expired Dispatch, copied-scope mismatch and absent physical StopFact must refuse and preserve the seats, H claims and H operation journal read directly before/after the callback. Original release replay deliberately retains its original generation: the release itself advances the seat generation, so requiring replay to match that new generation would contradict the existing E transition. No synthetic stop proof, test-only caller or production bypass is used. Cloud execution remains **NOT_RUN**.
