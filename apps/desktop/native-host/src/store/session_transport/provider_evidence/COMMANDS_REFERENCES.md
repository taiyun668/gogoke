# M2 provider command encoding references

This unconnected Rust file encodes vendor stdin data only. The native H owner must supply the observed pinned executable, process and session generation, current grant, original RPC ID and journal, framing write, and later origin bound stdout capture. An encoded line or successful stdin write is no vendor receipt. `session/cancel` is a notification; a correlated prompt response with `stopReason=cancelled` is required even to claim the model turn was cancelled, and H separately proves process stop.

## Claude first open and User ACK

The historical gogo-party Claude seat wrote its first User before observing `system/init` and treated `result` as a delivery event. The frozen B2 adapter did not accept that as a correlated delivery receipt. The [official Agent SDK Python client](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/client.py) invokes `Query.initialize()` before its first User; the [published Query implementation](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py) uses stdin `control_request` / stdout `control_response` and request IDs. This supports a model-free first-open handshake, with no invented native session ID. The fixed `2.1.196` help capture at `phase22/claude-fixed-help-original/result.json` advertises `--replay-user-messages` for stream-json input/output, so H requests that flag and admits a User echo only when its UUID and original text match the stored stdin command. The fixed result shape has `session_id`, `subtype`, and boolean `is_error`; [later SDK releases](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md) added `user_message_uuid` result correlation after this pin. H therefore requires one unresolved original User, a real A-captured `system/init` for the same native session and its exact echoed User in either order, followed by the first subsequent result in the same process source epoch. A result alone cannot prove delivery. The static protocol foundation is not a real CLI conformance or model run.

The same fixed help advertises `--model <model>` and `--effort <level>` (`low`, `medium`, `high`, `xhigh`, `max`), so `claude_launch_args` requires both selected values from the actual bound E seat. It also requests `--safe-mode`, which the fixed help lists as a startup switch. Neither a launch flag nor the existing auto-memory environment setting proves effective memory isolation; no real CLI/model run was made here. The actual product `LaunchEvidence::request` is Controller-owned and must call this helper instead of its old unqualified template.

The fixed OpenCode `v1.18.32` service returns `configOptions` from `session/new` and `session/set_config_option`. Its `model` handler resolves a provider/model selector; `effort` rejects a value absent from that selected model's variants. The fixed agent implements `setSessionConfigOption`; the official ACP v1 schema maps that handler to `session/set_config_option` with `sessionId`, `configId`, and string `value`. H checks the actual same-process session before writing and the response's exact requested `currentValue` before OBSERVED. A `session/update` notification is only output. Sources: https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/service.ts , https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/agent.ts , https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/config-option.ts , https://agentclientprotocol.com/protocol/v1/schema .

`rpc_journal::read_observed_acp_response` recovers an already observed metadata ACK from the exact original H step and A source. It does not re-read stdout or resend stdin. An INTENT, WRITTEN, or UNKNOWN setting remains unresolved and cannot be treated as applied.

Cold candidate ACP resume reuses the original K-SESSION generation-change/episode and H RPC rows. `acp_candidate_step_id` fixes the candidate initialize, session resume/load, and OpenCode model/effort step identities to the candidate process operation. Preparation admits only those commands while the original change is `OLD_STOPPED`, the old custody has a matching StopFact, and the new physical candidate matches the same instance, seat, home, digest, ticket and nonce. OpenCode 1.18.32 uses `session/resume` only after the same new process advertised `sessionCapabilities.resume`; Grok 1.0.41 uses `session/load` only after its own `loadSession:true`. The requested session ID is read from the old generation's original H/A acquisition; OpenCode's response may omit its ID, so it cannot replace that proof. `observed_thread_id` and `reconcile_written_resume_from_a` verify the new typed ACK against that old ID and original A source. Promotion also requires OpenCode model then effort ACKs with the bound E values in the new process, and their final config option state. No candidate prompt, replay write or new request may repair an UNKNOWN.

`rpc_journal::read_original_claude_initialize_ack` reads the original open operation, matching initial episode and physical custody, deterministic initialize command, and its captured A control ACK. It reports the actual success bit without deriving a native session ID or granting a new write. `journal::read_original_claude_send_completed` is a no-write historical readback from original User/H/A rows in ACTIVE, UNKNOWN, or STOPPED; STOPPED requires the original physical StopFact. It verifies the original User bytes, exact H echoed-User command and A frame, the same-session `system/init`, the first subsequent terminal A frame, and recomputed revision, receipt ID, source digest and APPLIED/FAILED status. It does not need a live `PreparedCustody` or promote FAILED to APPLIED. Other parseable `type:user` frames remain ordinary unhandled output and cannot become the original echo; if one intervenes between that echo and the terminal result, H declines to attribute the result to this User.

The same fixed release's `packages/opencode/src/index.ts` defines global `--pure` as "run without external plugins" and sets `OPENCODE_PURE=1`; the launch uses it before `acp`. This reduces plugin loading but is not proof that memory is disabled or that a requested model was selected. Source: https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/index.ts .

Grok Build 1.0.41 fixed exe `agent --help` reports `Usage: grok agent [OPTIONS] [COMMAND]`, parent options `-m, --model <MODEL>`, `--reasoning-effort <EFFORT>`, and `--no-leader`; `stdio --help` has only debug/leader-socket options. Root's no-login/no-model help capture is `phase22/grok-agent-fixed-help-original/result.json` with exe SHA-256 `ab5d2a424f08281798acbdbb06076166fe000d7995ede94a673417b805210a25` and exit 0. The launch now requests both values from bound seat settings before `stdio`. The historical gogo-party seat used analogous argv but is not treated as proof of the fixed binary. Requesting flags is not proof of effective model or effort; Root must gate open on actual provider readback or report Unsupported, never silently accept a CLI default.
