# M2 provider command encoding references

This unconnected Rust file encodes vendor stdin data only. The native H owner must supply the observed pinned executable, process and session generation, current grant, original RPC ID and journal, framing write, and later origin bound stdout capture. An encoded line or successful stdin write is no vendor receipt. `session/cancel` is a notification; a correlated prompt response with `stopReason=cancelled` is required even to claim the model turn was cancelled, and H separately proves process stop.

## Claude first open and User ACK

The historical gogo-party Claude seat wrote its first User before observing `system/init` and treated `result` as a delivery event. The frozen B2 adapter did not accept that as a correlated delivery receipt. The [official Agent SDK Python client](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/client.py) invokes `Query.initialize()` before its first User; the [published Query implementation](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py) uses stdin `control_request` / stdout `control_response` and request IDs. This supports a model-free first-open handshake, with no invented native session ID. The fixed `2.1.196` help capture at `phase22/claude-fixed-help-original/result.json` advertises `--replay-user-messages` for stream-json input/output, so H requests that flag and admits a User echo only when its UUID and original text match the stored stdin command. The fixed result shape has `session_id`, `subtype`, and boolean `is_error`; [later SDK releases](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md) added `user_message_uuid` result correlation after this pin. H therefore requires one unresolved original User, a real A-captured `system/init` for the same native session and its exact echoed User in either order, followed by the first subsequent result in the same process source epoch. A result alone cannot prove delivery. The static protocol foundation is not a real CLI conformance or model run.

The same fixed help advertises `--model <model>` and `--effort <level>` (`low`, `medium`, `high`, `xhigh`, `max`), so `claude_launch_args` requires both selected values from the actual bound E seat. It also requests `--safe-mode`, which the fixed help lists as a startup switch. Neither a launch flag nor the existing auto-memory environment setting proves effective memory isolation; no real CLI/model run was made here. The actual product `LaunchEvidence::request` is Controller-owned and must call this helper instead of its old unqualified template.

The fixed OpenCode `v1.18.32` service returns `configOptions` from `session/new` and `session/set_config_option`. Its `model` handler resolves a provider/model selector; `effort` rejects a value absent from that selected model's variants. The fixed agent implements `setSessionConfigOption`; the official ACP v1 schema maps that handler to `session/set_config_option` with `sessionId`, `configId`, and string `value`. H checks the actual same-process session before writing and the response's exact requested `currentValue` before OBSERVED. A `session/update` notification is only output. Sources: https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/service.ts , https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/agent.ts , https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/acp/config-option.ts , https://agentclientprotocol.com/protocol/v1/schema .

`rpc_journal::read_observed_acp_response` recovers an already observed metadata ACK from the exact original H step and A source. It does not re-read stdout or resend stdin. An INTENT, WRITTEN, or UNKNOWN setting remains unresolved and cannot be treated as applied.

Cold candidate ACP resume reuses the original K-SESSION episode and H RPC rows. `acp_candidate_step_id` fixes the candidate initialize, session resume/load, and OpenCode model/effort step identities to the candidate process operation. Preparation admits only those commands while the original old custody has a matching StopFact and the new physical candidate matches the same instance, seat, home, digest, ticket and nonce. Compact/renew candidates additionally require their original generation change at `OLD_STOPPED`. OpenCode 1.18.32 uses `session/resume` only after the same new process advertised `sessionCapabilities.resume`; Grok 1.0.41 uses `session/load` only after its own `loadSession:true`. The requested session ID is read from the old generation's original H/A acquisition; OpenCode's response may omit its ID, so it cannot replace that proof. `observed_thread_id` and `reconcile_written_resume_from_a` verify the new typed ACK against that old ID and original A source. Promotion also requires OpenCode model then effort ACKs with the bound E values in the new process, and their final config option state. No candidate prompt, replay write or new request may repair an UNKNOWN.

Public K-SESSION `resume` is a second candidate source: it writes the original resume episode and has no generation-change row. `plain_protocol_resume_episode` decodes that exact stored User frame, checks its request ID, target, revision and adjacent generation, current old claim plus physical StopFact, same pinned instance/digest, seat incarnation, new home/binding and candidate custody. Codex 0.160.0 and OpenCode/Grok metadata handshake steps use the same episode; any existing compact/renew change still requires its own `OLD_STOPPED` stage and uncancelled owner-stop state. `generation_episode_old`, candidate preparation, A reconciliation, `observed_thread_id` and promotion use the same original episode rather than manufacturing a change. Side-chat continuity selects ACP `session-resume` step and calls `observed_thread_id` for both old and new A source verification.

The fixed Codex 0.160.0 `item/tool/call` request shape is implemented in `codex_rpc::decode_dynamic_tool_call` from the pinned exe's ordinary schema export; the frozen t3code generated schema at `third_party/t3code/packages/effect-codex-app-server/src/_generated/schema.gen.ts` is corroboration, not authority for the pinned binary. `model_call::observe_model_call` requires an actual `OriginBoundFrame` captured first in A; `recover_model_call_from_source` reads that same A row under original custody without fabricating a frame. Both recheck the current H claim, E seat incarnation, process ticket/nonce/pin/home, original thread ACK and the exact H User turn-start receipt plus A response and `turn/started`. A captured `turn/completed` in any A state denies the call. Typed RPC ID, original raw bytes, call ID, tool name and arguments are rechecked on every E `current_caller`; an altered same-ID frame conflicts. The host request ID derives from physical operation/ticket/nonce and typed RPC ID, never an A cursor or model-supplied request ID. Only four finite tool names in the empty namespace can pass; arguments cannot supply a principal, grant or path authority.

`runtime::reserve_native_with_origin` and `commit_native_with_origin` use the Root OwnerIssuer to authenticate the same database, while `NativeLeadAdmission` carries the distinct H-proven model caller. E's existing child-dispatch context checks the current parent User layer, direct Lead child, takeover, scope and current DISPATCH grant. A first reserve changes the child from IDLE to BUSY in H's admission transaction; BUSY replay and commit require the original reservation, session, incarnation and generation binding. `runtime::observe_claim_bound` is a pure read of an already admitted child, so its later live validation does not depend on the parent's old turn. This package does not grant the model Owner authority or expose a User-origin fallback.

ACP and Claude FAILED H User receipts now include `providerFailureRawExcerpt` (the exact UTF-8 prefix of the captured A terminal frame, at most 16 KiB) and `providerFailureTruncated`. Their strong readback recomputes both from that A source. The existing raw SHA-256, source key and receipt ID formulas are unchanged. `K-SESSION output` already includes verified native input receipts in `nativeInputReceipts`; these fields make original error code/message/errors or Claude result diagnostics available there when they fall inside the bounded prefix. A full oversized frame remains in A, with the truncation bit true. This text never changes FAILED to APPLIED.

`rpc_journal::read_original_claude_initialize_ack` reads the original open operation, matching initial episode and physical custody, deterministic initialize command, and its captured A control ACK. It reports the actual success bit without deriving a native session ID or granting a new write. `journal::read_original_claude_send_completed` is a no-write historical readback from original User/H/A rows in ACTIVE, UNKNOWN, or STOPPED; STOPPED requires the original physical StopFact. It verifies the original User bytes, exact H echoed-User command and A frame, the same-session `system/init`, the first subsequent terminal A frame, and recomputed revision, receipt ID, source digest and APPLIED/FAILED status. It does not need a live `PreparedCustody` or promote FAILED to APPLIED. Other parseable `type:user` frames remain ordinary unhandled output and cannot become the original echo; an intervening User frame outside the known pure tool-result shape prevents terminal attribution.

The [official Python SDK streaming example](https://github.com/anthropics/claude-agent-sdk-python/blob/main/examples/streaming_mode.py) explicitly handles `ToolResultBlock` inside `UserMessage`. The frozen t3code Claude adapter at `third_party/t3code/apps/server/src/provider/Layers/ClaudeAdapter.ts` likewise treats a user message containing only `tool_result` blocks as distinct from a human turn start, even when `parent_tool_use_id` is null. `stream_json::is_claude_tool_result_line` recognizes only nonempty pure `tool_result` arrays with original `tool_use_id` and session ID; the decoder still reports an unhandled original `type:user` frame, so this never acknowledges stdin or proves success. The H causal scan permits only that recognized shape between exact Host echo and the first main-session result. The published source supports the shape; the pinned 2.1.196 binary still needs a real tool-use stream to confirm its emitted bytes.

The same fixed release's `packages/opencode/src/index.ts` defines global `--pure` as "run without external plugins" and sets `OPENCODE_PURE=1`; the launch uses it before `acp`. This reduces plugin loading but is not proof that memory is disabled or that a requested model was selected. Source: https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/index.ts .

Grok Build 1.0.41 fixed exe `agent --help` reports `Usage: grok agent [OPTIONS] [COMMAND]`, parent options `-m, --model <MODEL>`, `--reasoning-effort <EFFORT>`, and `--no-leader`; `stdio --help` has only debug/leader-socket options. Root's no-login/no-model help capture is `phase22/grok-agent-fixed-help-original/result.json` with exe SHA-256 `ab5d2a424f08281798acbdbb06076166fe000d7995ede94a673417b805210a25` and exit 0. The launch now requests both values from bound seat settings before `stdio`. The historical gogo-party seat used analogous argv but is not treated as proof of the fixed binary. Requesting flags is not proof of effective model or effort; Root must gate open on actual provider readback or report Unsupported, never silently accept a CLI default.
