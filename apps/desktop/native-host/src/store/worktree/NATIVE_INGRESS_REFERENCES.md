# F.2 native child worktree ingress

The existing public User `merge_worktree` and `register_created_worktree`
wrappers still decode the exact K-WORKTREE wire request. The native H ingress
uses `merge_worktree_request` with a typed `V37Request`: its `raw_bytes` remain
the original A `item/tool/call` frame bytes. F hashes and journals those bytes
directly, while its existing merge decision, reason, Git and lifecycle checks
remain shared with the public wrapper. The caller supplies a sealed
`NativeSeatCall`; the existing E merge authorization closure is evaluated
inside the original F transaction before reserving the merge effect.

`create_and_register_native_child_worktree` accepts a typed create request
and a direct child `Seat`. Its only payload fields are `repositoryId` and
`layout` (`SINGLE` or `MIXED`); the request target names that child, not a
filesystem path. F derives
the logical worktree ID from the original A bytes and selected identities;
the physical path, mixed space and detached Git branch remain generated by
the existing F create machinery. The same exact A bytes are stored in create
and register journals. A completed create can be read back to finish a lost
register response without repeating `git worktree add`; an uncertain create
remains fenced.

Each create INTENT transaction and physical registration transaction rechecks
`seat::authorize_child_dispatch` against the live caller and child. The
register lifecycle transaction rechecks it again. That E function enforces
the current direct User-parent to Idle Lead-child edge, current domain and
incarnation, takeover readiness, native scope and dispatch grant. The retained
OwnerIssuer only confirms product database ownership. Neither an earlier
authorization result nor an Owner-equivalent Boolean authorizes a later F
effect. No new table, wire contract, model path choice or provider process is
introduced.

An original `gogoke_seat dispatch` may return after H has reserved the child,
so an exact retry sees the same child as BUSY. That case is read-only: F takes
`host_request_id` only from the sealed `NativeSeatCall`, requires the typed
request ID to be exactly `{host_request_id}-worktree`, calls E's current child
dispatch context, and reads H's original APPLIED `admission-reserve` session.
H's existing lead `observe_claim` rechecks that same reserve against the
child incarnation/generation, session, active home and owner binding. F then
checks its exact create bytes/repository/seat/layout, the physical registered
binding, the one-generation transition, and its APPLIED register journal.
It returns the old binding without calling create, register or Git. A merely
BUSY child or a different model call cannot use this path; ordinary Idle
creation retains all three in-transaction E rechecks above.
The same checks are exposed as `recover_registered_native_child_worktree` so
Root can perform this completed-history read before resolving a Git pin.
The helper takes no program pin or ProcessCustodian and cannot start even a
Git version probe. The create/register entry delegates BUSY to this helper;
Root's native dispatcher must choose the helper before its own Git lookup.

Sources: existing `store/worktree/{mod,f2}.rs` create/register/merge journals,
`store/seat/orchestration.rs::authorize_child_dispatch`, and
`store/product_database/v37_session.rs::dispatch_native_worktree`. Root owns
the H/A gateway that constructs the typed request from an origin-bound frame;
this F package does not claim that gateway is wired or that native Win11,
Smart App Control or merge behavior has been executed.
