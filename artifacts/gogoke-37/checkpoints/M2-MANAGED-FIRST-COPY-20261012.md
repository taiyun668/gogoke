# 自管 CLI 首份副本资格

改动：首次安装与替换既有版本分开。只有还没有任何自管副本或来源关联、所有登记实例仍是同一固定版本与原镜像、安装进度的 pin 为空或完整相同，才属于首份副本；历史 UNKNOWN 原样保留。当前登录进程、PREPARED/ACTIVE、未证明停止的 STOPPED、本例 probe 和实例 H/F 占用继续拒绝。升级、替换和卸载保持原严格资格，不借首次安装绕开。

原失败恢复的 F-only 核验只读组合原 capture、确切 failed-child operation、REVOKED profile、原撤权回执、物理认证对象及原 admission-release。拒绝尚未释放、错范围、错原操作及篡改原回执；不产生 StopFact，不重写 UNKNOWN，不读凭据内容，不改 ACL。

结果：首次副本代码经全新 Sol 聚焦复核通过。本机开发检查不是候选证据。新增受影响云检选择只跑三条确切安全边界测试及生产库/主程序编译，完整原生、稳定更新链与真机自管来源均 NOT_RUN。现有服务重建的十二项云检及冻结签名通过；正常退休上一候选原退出零、原清理 DELETED、十三项保护和完整候选记录连续性相等。新候选安装和真实 Claude 冷恢复尚未完成，不计新增可运行能力。

归属：发现“两子模块未逐字列入 JSON”的前提是真的，但“所以需要新授权”的结论不成立。main PLAN 的必要同 DB 产品入口接线条款、F/H 持有者消失细节及已撤回多余触点的持久组合裁定共同约束这次最小依赖。独立复核确认由 Controller 持有 `store/product_database/v37_managed_cli.rs` 和 `v37_holder_disappearance.rs` 及原边界测试的接线；这不授予 H/F 工人一般子模块写域。工人先前提交了该两份组合草稿，Controller 已逐项审查并接管；后续该接缝只由 Controller 修改。

参照：原实例管理 progress/pin 表、原 F-only failed-resume capture、原 admission-release 和 revoke journal、main 的同次开机恢复条款。沿用这些原事实，不再要求已完成资源结算的历史 PID 重新出现同一身份；不把原 admission-release 误要求成不存在的 holder-gone-release。历史六路径组合记录不是无限授权。本次没有新增 writer、契约、权限、Owner 登录、发布或验收。
