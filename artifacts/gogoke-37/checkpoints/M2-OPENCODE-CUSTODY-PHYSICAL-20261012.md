# M2：OpenCode 原初始化拒绝与物理身份修复

## 改了什么与结果

- 已安装实验候选的 OpenCode 原生产 H 初始化失败，原错误为 `native OpenCode alias custody image differs from registered F program`。随后原 stop 无回执，宿主退出 1，原 stderr 为 `AccessDenied`；模型未发送。该次初始化与停止均不记通过。
- 原闭库 C 映像与 MANAGED 程序读回是同一 Volume/FileID。C 路径来自 QueryFullProcessImageNameW，F 路径来自验证数据库下的受管来源；两者没有路径字符串同形的契约。当前错误未记录失败时 F 路径原文，不把某种前缀差异单独当成已证实的全部原因。
- H 的 alias custody 绑定改为复用现有 catalog 校验：F 程序和 C 映像分别核对原 Volume/FileID、非重解析普通文件和原 profile 精确 RX/无继承见证。固定版本、字节、完整 C tuple、后续激活检查保留；不以仅哈希或字符串规范化放行。
- 安全边界测试补核普通/逐字 Windows 路径同一物理文件，以及相同字节的另一物理文件仍拒绝；原 hardlink、重解析和数据单链接检查保留。受影响云端选择加上该具名测试。
- 本机开发编译使用关闭状态的 SAC、D 盘产物与临时目录。第一次缺受控 Node 构建输入，原失败保留；补入原签名 Node 后编译完成，但测试在建立符号链接时返回 Windows 1314。未提权或修改系统设置，测试不记通过，由云端继续执行完整原用例。本机产物不进入候选，也不作为正式证据。
- 独立聚焦复核未发现这三处 diff 的阻塞。受影响云端原件确认五个具名过滤、合计七项通过；卫生通过，全量原生和完整稳定门槛未运行。它们不代替生产 H 初始化、停止、映射闭合或验收。

## 保全与下一步

原宿主已退出后，按既有同类处置授权正常点击原 shell 的关闭按钮；原任务持有的进程句柄观察到 shell 退出 0。没有强杀或补写 StopFact，OpenCode 停止仍记未确认。原 H COMMITTED、C PREPARED、alias PREPARE_STARTED、全部原回执与错误保留；不能将 holder 消失等同 STOPPED。

原关闭后十三项正式保护相等。原执行、正常关闭及只读诊断任务逐项核对、导出后清理并回读不存在。秘书长同次启动先取得独立真实停止事实，不与 OpenCode 未确认停止混淆。

受影响云检通过后，准备 0.1.64 轻候选，仅推进 Browser、许可证及单路冻结构建。相对已检源码，原生与受影响测试文件保持原 blob，版本声明同步推进；不为纯测量脚本改动换候选。包含真实 H 修复的新候选须重跑 OpenCode 初始化、真实 Grok 提问及停止，再推进 V08。常驻秘书长收尾与下一单轮模型的 D 盘执行包已并行准备，未来输入必须由实际闭库结果绑定。完整 M2/M3、稳定全链、SAC 强制实测和 Owner 验收均未完成。

宿主原退出已进一步定位为半准备内存会话在 ledger 注册前进入输出泵；这是本次失败链，不能据此声称此前 alias 恢复门会直接杀死下一次启动。新候选是否可运行仍以实际结果为准，旧 H 和映射未手动清理。
