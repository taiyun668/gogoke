# M2：服务连接重建

## 改动与结果

已安装实验候选的 Claude 新用例在启动时失败：`GOGOKE_PRODUCT_SERVICE_FAILED:1`，原 Node `openSync` 返回 `EBUSY`。尚未发送本例 USER E/F 操作或模型输入，原失败及日志保留。随后从实际 USER 读秘书长 H，取得真实 StopFact 和回读，再点原窗口关闭；原 shell/native 句柄退出均为零。闭库核对停止事实、旧记录、新 E/F 缺席及十三项保护通过。

第一次闭库仪器将 SQLite INTEGER revision 与 API 的十进制字符串直接比较，必定拒绝正确值。原失败保留，仅补有类型约束的规范字符串比较；没有修改产品、停止事实或其他检查条件。

直接原字节组件测量确认：首次认证成功，关闭后紧邻第二次连接得到 `ENOENT`。唯一服务管道在旧连接销毁与重新创建之间存在空档；这一结果不能单独证明已安装产品 `EBUSY` 的具体旧客户端。第一份组件测量把工作目录设为独占数据根，造成自身占用，原测量失败保留；更正工作目录后才取得上述原始结果。

修复保持一个实例、原 DACL、能力、User 证明和服务串行锁。在原 User 连接上确认宿主已重建监听器，并复核即时及延迟答复时的活体对象；Tauri 仅调用一次 `WaitNamedPipeW` 确认内核有待接收连接，扣除已用预算后才启动新 Node。不重试连接、不重发输入。监听事实不是连接预留，随后发生的原连接错误仍直接返回。

IPC 只把首个帧头字节前的 EOF 判为正常断开；截断帧头、帧体、超长帧和写失败保留原文并拒绝下一 Ready。新增真实 pipe 的边界检查接入明确的受影响云端选择，正式门槛未改。同步 User 控制读取仍沿用现有机制，没有声称其自身已获得硬截止期限；返回后耗时会扣减，预算耗尽拒绝启动 Node。

本机开发组件直接引用当前宿主源，验证十次连续认证、Node 从未连接即退出后的下一次认证、打开后未发送前导字节即退出的拒绝路径。最后一种未启动第二个 Node，并保留原 Win32 与 native stderr。此为独立开发数据根的诊断，不能当候选、真实 CLI 模型或 M2 通过。受影响云检及实际候选复现待执行。
