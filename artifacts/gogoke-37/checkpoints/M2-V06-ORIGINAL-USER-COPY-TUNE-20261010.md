# M2 V06：原 USER 模板复制与独立调整

## 改动与结果

- 原装候选的两个新项目域使用相同模板、各自不存在的新目标，实际创建两份 USER 席位。原创建回执保留，A 调整后修订推进，B 保持原模板设置；正常关闭退出零，闭库只读核对前后数据库字节相同，正式版五组保护事实相同。
- 原脚本误把配置对象当成已记录回执的结果对象，导致创建后读取结果失败。改为读取结果记录中的项目对象；原失败没有改成通过，也没有重发创建。补充原件仅接着执行一次新调整和两次状态读取。
- Native receipt 的外层没有 domainId。删除这个不存在字段的测试断言；请求原文、闭库查询与对象指纹仍验证原项目域。V08 的同类断言一并修正。
- 两次实测失败原件、补充原件和正常关闭事实全部保留；已完成的一次性任务逐项导出、核对后清理，并回读不存在。

## 限制与下一步

只证明 USER 模板复制与调整独立性。项目域到仓库的持久绑定、真实 MODEL 拒绝和 LEAD 调整/回收未由本例证明，完整 V06/M2/M3 未完成，未自行验收。继续新的单跨项目审批用例；新候选构建期间冻结受控分支头，资源签名完成后再推后续提交。

## 参照与判断

采用原 NativeUser 生产请求、原 seat-management 端到端入口、session_transport/wire.rs 的真实响应编码及现有闭库只读核对。补测复用原创建事实而不复用旧模型输入；原因是原创建已经成功，重发会测另一个对象。仅修仪器的对象来源和不存在字段，不改变产品权限或范围摘要。
