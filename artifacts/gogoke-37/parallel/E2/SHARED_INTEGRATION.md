## H admission and F.2 merge

- In H's existing `BEGIN IMMEDIATE` admission callback, call `seat::refresh_host_parallel_fact_in_transaction(db)` before `seat::read_effective_project_parallel_cap(db, domain_id)`. Use its effective value as `TrustedLimits.project_parallel`; keep F's existing instance cap. The host row records `std::thread::available_parallelism()` as the observed input and limit. Missing OS observation or Owner project cap denies admission. E never updates `gogoke_v37_seat_project_caps`; the persisted Owner value (currently 4) remains separate and authoritative. The Rust API is an estimate of default process parallelism, not a RAM or provider quota assertion.
- H's Lead entry still rejects all Lead reservations in the L0 shared runtime. Root must authenticate the live original H claim, seat binding, generation, process custody and turn, construct `seat::NativeSeatCall::from_verified_h_turn`, then call `seat::authorize_child_dispatch` before a child reserve. It checks current copied scope, completed takeover questions and current `DISPATCH` grant. E's existing Lead layer, parent and self-binding checks remain in seat mutations. A native seat snapshot alone is not an H authentication result.
- F.2's merge authorization closure takes `(db, domain_id, worktree_seat_id, worktree_id)` and must capture the same live H caller. Call `seat::authorize_merge_for_f2(db, &caller, worktree_seat_id)`; it returns the original turn ID only when the caller is that seat and its unexpired `MERGE`→`MAIN` grant is current. The F.2 worktree resolver remains responsible for exact worktree/repository/physical identity. Never substitute `Some(turn)` unconditionally.

- `render_codex_instruction` projects the copied `instruction` into candidate `AGENTS.md` bytes only. It writes no file and proves no CLI discovery. Root must choose a project-scoped placement that neither overwrites a repository rule nor leaks through the shared persistent instance home, then verify actual loaded instruction bytes in the real CLI. - H/adapter should pass only original observed health event IDs to `observe_health`. Its direct signal maps to `COMPACT`, `RENEW`, `ESCALATE` or `NONE`, with `UNKNOWN` producing no action. A replay returns `false`; ambiguous result must be reconciled by H, never resent under a new ID. `settle_health_receipt` is for a verified original K-SESSION receipt. ## K-POLICY and coordinator

- `initialize_policy` and Owner configuration calls install an explicit project stage, call grants, gate definitions and escalation routes; no call permission has a default. `current_call_permission_table` and `authorize_current_call` require the live native caller, matching domain, current target and unexpired grant. A Lead-layer seat cannot address `OWNER` directly. Root must bind the public read to that native observation and store the original raw request/receipt bytes in the existing v37 ledger.
- `gate_submit`, `gate_decide`, `stage_transition` record native events with original request fingerprints and compare policy/gate revisions. A rejection requires a reason; a configured reject cap produces `ESCALATION_REQUIRED`; only a passed gate advances its configured stage edge. Root/C must mirror final events to the project ledger and verify public receipt replay/collision.
- `begin_trigger_register` and `begin_trigger_cancel` reserve exactly one external coordinator action. Only `external_action_authorized=true` may call the existing coordinator; replay, `UNKNOWN`, recovery and settlement never schedule/cancel again. `settle_trigger`/`recover_trigger` require the coordinator's exact original readback. `begin_escalation` additionally requires the registered trigger and a configured reject-cap or stalled-health cause, then records one delivery intent. C/H delivers outside SQLite; `settle_escalation` accepts only the trusted original delivery receipt. A missing outcome is marked `UNKNOWN`, retained, and never redelivered. The typed evidence constructors validate shape only; Root must perform the real coordinator/C/H receipt verification before calling them. An app-server fake or caller field is not proof.
