# F.2 shared integration handoff

Source branch: `codex/gogoke-37-m2-f2`; base `546d4e9d573d90ecbfc5be6250aabbed6afbe45f`. F owns only the native `instance/` and `worktree/` modules. This note does not grant product acceptance.

## Existing native sources

- `instance::known_new_version(driver_id, registered_version)` compares the persisted version to the **running product's pinned catalog**. It returns only a known newer version, never a network claim or auto-upgrade. The shared `K-INSTANCE/version-and-new-version` read can include this optional `newVersion` while preserving the stored `version` and digest.
- Existing `instance::repin_program` verifies the manually installed CLI through native catalog identity, retains the original home and credentials, and sets login state to `UNKNOWN`. No capability assertion is carried over from the prior digest.
- After an exact repin, the shared product flow must use the new pinned CLI to read account state, open a properly bound native session, call its existing `K-SESSION/capability-probe`, and pass the **original applied request ID** to `instance::read_current_capability_reprobe`. This reader accepts only the durable original receipt bound to the current instance pin, H claim, generation, process custody and loaded feature flags. A missing receipt is `None`, not successful reprobe. The capability receipt explicitly keeps model behaviour `NOT_RUN`.

## Worktree calls to connect

- Existing M1 User `K-WORKTREE/create` can keep using `worktree::create_worktree`. The M2 create/register sequence calls `create_m2_single_worktree` or `create_mixed_worktree`, then `register_created_worktree` with the exact User register request. A trusted mixed-space identity comes from the host's project graph, never from a model path. Both create physically distinct, host-generated directories under the appropriate `single` or `mixed` parent; a newly created M2 tree cannot launch until registered. Existing M1 single rows remain immediately registered and readable after the exact four-table F.1 schema is extended.
- `worktree::graph_query` projects registered repository, project, worktree, seat, instance, baseline and merge result. `register_created_worktree` is an atomic native transition from CREATED revision 1 to REGISTERED revision 2 with no second Git command; Controller owns the public receipt mapping.
- `worktree::merge_worktree` accepts an exact `K-WORKTREE/merge` request and a mandatory closure that checks the **current E.2 merge grant and authenticated caller seat**, returning the bound turn ID. The closure receives `(domain, original_writer_seat, target_worktree)`; the writer seat is provenance metadata and need not be the currently authorized merger. Shared trusted ingress must bind the real current caller's H claim and turn, domain and MAIN/Merge grant. Never wire an unconditional grant. Historical replay calls this current-authority closure before returning any receipt. It checks stopped and released work, clean source and linked trees, records INTENT, performs only local `git merge --no-ff --no-commit` then a provenance-trailered commit, and records APPLIED or MERGE_UNKNOWN. It never fetches, pushes, reads a credential helper, or retries an uncertain merge.
- APPLIED merge records retain the complete canonical result in the existing lifecycle operation `cause` field (which has no error cause on success), including exact raw request bytes, hash, operation, target, original result revision and commit. Replay compares this immutable record and returns its original revision even after normal cleanup advances the lifecycle to CLEANED; it never resolves a physical tree or invokes Git. Existing APPLIED rows with empty `cause` keep their original commit/hash evidence, and the exact hash-bound request's expected revision plus one determines the original result revision. Nonempty incomplete records and every INTENT/UNKNOWN stay UNKNOWN. No schema or old evidence is rewritten.
- `worktree::cleanup_worktree` decodes the original H open request to identify each model episode's sealed worktree. Current H `LaunchEvidence::build` grants the resolved `worktree.path` as its workspace write root; F resolves each recorded ID through the existing graph member, canonical path, directory identity and Git pointer checks. Cleanup compares physical identity and both parent/child path directions, so a different ID inside a mixed parent still blocks, while a proven disjoint sibling does not. An unresolved historical model root fails closed; an unstarted reservation without an open target blocks when bound to the target seat. It requires exact native StopFacts for intersecting episodes and no intersecting active reservation. It records INTENT before plain `git worktree remove` (without `--force`), verifies physical absence, then settles APPLIED; any uncertain effect remains CLEANUP_UNKNOWN. It never removes a caller-selected path. If shared H ever grants a mixed parent or additional workspace write root beyond `worktree.path`, Controller must pass those sealed physical roots and identities to this gate before enabling that launch shape; F cannot infer extra roots from an ID and must keep cleanup denied until wired.
- `worktree::resolve_for_launch` refuses non-REGISTERED F.2 lifecycle states. A mixed space uses separate linked trees even when one repository serves several projects.
