# 首次引导：已知未验

日期：2026-08-24
范围：干净 Windows 沙盒走通 Grok 首次引导之后（`2c82939`）
性质：验收缺口。不是待修清单。下一个人不能把这些当成已经验过。

干净沙盒里 Grok 从欢迎页走到助手回话，是真的。下面四条当时没验到那个程度。

---

## 干净机只走了 Grok

Claude / Codex 的干净机首次引导没走。

三家垫片形状不同：Claude 是 `.exe`，Codex 是 `.js`，Grok 是无扩展名跳板。只测两家会漏第三家，这次已经在本机垫片解析里证明过。干净机端到端不能从 Grok 外推到另外两家。

## 「下一步」在检测中消失

检测未完成时不画「下一步：准备实例」，靠的是页面源码检查（`envAdvanceGate` + `check-page.mjs`）。没有在浏览器里亲手点开、确认按钮不在。属于「看起来对」。

## 「2～5 分钟」是观察不是测量

界面写 Node 安装向导常要 2～5 分钟、停在 Preparing to install 不是卡死。这个数字来自沙盒里一次很慢的安装，不是测出来的。人会拿界面上的时间当准。

## 垫片测试允许 exe 或跳板任一分支

`grok-acp-seat.test.ts` 里「显式 grok.cmd 且旁边只有跳板」允许走到 `grok.exe` 或 `node` + 跳板。这台开发机有 `~\.grok\bin\grok.exe`，测试可以不碰到「只有 grok.cmd、没有 exe」的那条新路径。干净机上真正会走的 spawn 路径，这条测试没强制覆盖。
