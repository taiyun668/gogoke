## 三、未修 —— 按严重度排

### ~~高：Grok 的登录判据缺省方向错~~ —— 已修（见文末）

`accounts.ts` 的 `probeHome`：

```ts
return spec.notLoggedInPattern.test(out)
  ? { loginState: "empty",  ... }
  : { loginState: "ready",  ... }   // ← 任何不匹配的输出都判成「已登录」
```

于是 **npm 更新提示、`ECONNREFUSED`、代理返回的 HTML 错误页、任何一句与登录
无关的话，全部被判成已登录。**

这是 `/Logged in/i` 匹配上 `Not logged in` 那个坑的**镜像**：
不是匹配错了，是**缺省方向错了**。现实里第三类输入（既非肯定串也非否定串）
才是最常见的，而它默认落进「成功」那一侧。

同一个错误在旧的 `AccountStore.probe`（`accounts.ts:788`）里也有一份：
`out.trim() !== "" && !pattern.test(out)`。那条路径的界面入口已经删了，
但函数还在。

**修法**：三家都要有**肯定串**判据，判不出来就报 `unknown`，不许默认成 ready。
Grok 的肯定串是 `logged in with`（`31-product-design.md` §6.2 已记录）。

### 中：Windows 路径的真实行为，稿子和代码都是空白

- `DATA_ROOT/seats/<id>/home/` 再叠上 CLI 自己的深层目录，260 字符限制下会撞
- `.cmd` 垫片解析用字符串匹配（`%dp0%`），路径含空格或非 ASCII 时没验证过
- 设计稿第 9 节的退路表里**没有任何一行是关于路径失败的**，
  而它在 Windows 上的表现同样是「找不到可执行文件」，与「没装」混成同一条提示

### 中：多开产品实例 / 多 worktree

`DATA_ROOT` 按仓库路径分开，但 `INSTANCE_ROOT` 是 `<盘符根>\gogo-party-instances`，
**全局共享**。两个房间进程同时跑时：

- 两边的全量写互相覆盖（改名、删除标记会被对方的旧快照抹掉）
- 一边 `remove()` 删了目录，另一边内存里那条记录还是 `ready`

孤儿检测（`c6a5bff` 之前那批）只解决了「上一轮进程还活着」，
没解决「同一时刻两个房间进程」。

### 中：`instances.json` 读不动时静默从空池开始

坏文件会被改名留证据，然后**从空池开始**。但磁盘上的实例目录（含凭据）还在，
界面显示零实例，人照着引导重建重登，旧目录成为永不清理的凭据垃圾 ——
而界面上一个字都没提。

### 中：实例目录不见了，被归成「未登录」

实例根在盘符根，可能被磁盘清理工具删掉、U 盘/网络盘盘符不在、企业策略清理。
`probeHome` 拿一个不存在的 HOME 去跑状态命令，CLI 当然说未登录 → `empty`
→ 界面「未登录，点登录」→ 人一点，`mkdirSync` 悄悄把目录重建成空的，
再走一遍 OAuth，全程以为是自己忘了登。

状态枚举里没有「目录不见了」这一项。

### 中：`adopt()` 目前没有 API 入口，一旦接上很危险

`assertOutsideRealHome` 只挡家目录。项目文件夹、`C:\Windows`、任何别的目录
都能被 adopt 成实例，然后被 `remove()` 递归删掉。
`31-product-design.md` §11 的「旧路径席位的迁移提示」正指向它。

### 低：`esc()` 不转义单引号

`index.html` 里多处把它的输出插进单引号的 `onclick`。现在安全**只是因为**
那些 id 都是内部生成的 —— 是巧合不是设计。而设计稿 §5.6（手填 CLI 路径）
和 §8（手填模型）都在往系统里引入人填的字符串。

### 低：实例页顶部四个数字既不互斥也不穷尽

「我建的 / 可用 / 席位占用中 / 待登录」：一个 `ready` 且被占用的实例同时进两栏；
`unknown` / `expired` / `timeout` 哪栏都不进。左侧栏的 `N/M` 里 N 和 M
分别是哪两个集合，从没定义过。

### 低：汇总数字不带时间

每张卡都显示「最后确认于 X」，而顶部的「可用」可能来自几小时前的一次探测。
人只看数字，看不到它有多旧。

## 四、这轮暴露的方法论问题

三条，都值得记住：

1. **「验法通过，不变量没成立」出现了三次。**
   空目录测试对 Grok 无效（判据挑中唯一被满足的那一维）、
   `killChild` 的守卫有时间窗、遮罩函数有用例但漏在调用点。
   **判据本身必须有反向用例，而且要逐维度断言，不能只看一个结果。**

2. **设计稿里「有测试」曾经是编的。**
   §10 给六条不变量各写了一句「怎么验」，读起来像既成事实，
   实际一条都不存在。已补 17 个用例，但**写「已实现」之前要先 grep**。

3. **拿源码正则钉一行代码的测试是脆的。**
   本轮有一个这样的断言匹配到了**注释里解释历史的文字**而变红。
   要么剥掉注释再判，要么把逻辑抽出来测真实输入。

## 五、补修记录

**2026-08-24 · 高危那条已修**（提交见 git log）

`probeHome` 与旧的 `AccountStore.probe` 都改成**三向判据**：
肯定串 → `ready`，否定串 → `empty`，**两个都不匹配 → `unknown`**。
判据抽成纯函数 `judgeStatusText`，可以直接喂真实输出测。

`PROVIDER_LOGIN` 新增 `loggedInPattern` 字段，Grok 的肯定串是 `logged in with`
（真机验证：`You are logged in with grok.com.`）。

新增 6 个用例，其中三条是这次真正要防的：

- **第三类输入一律 unknown**：npm 更新提示、`ECONNREFUSED`、
  代理的 407 HTML 页、`Downloading update...`、config 警告 ——
  旧判据把这些**全部**判成已登录
- **否定串优先于肯定串**：一段话里同时出现两者时判未登录
- **三家都必须成对给出肯定串与否定串** —— 只给否定串就等于把缺省方向指向
  `ready`。这条断言让下一个加厂商的人在忘记补肯定串时立刻红，
  而不是等到线上把噪音判成已登录

剩余 8 条未修条目不变。
