# 29 · 新用户第一次进来

## 0. 一句话

**席位那边只回答「用哪个实例」，登录、装 CLI、检测，全部在实例管理页完成。**

---

## 1. 现状（读码与实测确认，2026-08-23）

| 事实 | 出处 |
|---|---|
| 新建席位面板里混着「账号」「本机已登录的 CLI」「登录 / 换账号」 | `index.html` 新建面板 |
| `detectProviders()` 只用 `where` 判断 CLI 装没装，**不看版本** | `server.ts` |
| **模型列表硬编码在产品源码里** | `server.ts`，三家各一行 `models: [...]` |
| 安装引导只有一句文本，藏在 `why` 字段里 | 同上 |
| 本机三家版本 | codex 0.149.0 · claude 2.1.196 · grok 1.0.5 |

**能不能反过来问 CLI 支持哪些模型**（实测）：

| CLI | 能问吗 | 怎么问 |
|---|---|---|
| Grok | ✅ | `grok models` 直接列出，并标出默认 |
| Codex | ❌ | 只有 `-m/--model` 入参，没有列表命令 |
| Claude | ❌ | 同上，只提到「可以用别名」 |

这张表决定了第 5 节怎么写：**能问的就问，问不到的产品自己列 —— 但产品的列表
是建议，不是真相。真相在 CLI 那边，只有它跑起来才知道。**

## 2. 职责切开

| | 席位（新建 / 设置） | 实例管理页 |
|---|---|---|
| 选 CLI 厂商 | ✅ | |
| 选模型 | ✅ | |
| 角色、提示词、能力 | ✅ | |
| **选用哪个实例** | ✅ 只是挑一个现成的 | |
| 装 CLI | | ✅ |
| 建实例 | | ✅ |
| **登录 / 换账号** | ❌ 一个入口都不留 | ✅ |
| 检测登录状态 | | ✅ |
| 删除实例 | | ✅ |

席位那边看到的实例是**只读的一份清单**：名字、状态、被谁占着。
不能用的实例照样列出来，但**置灰并写明原因**，末尾给一条「去实例管理页」。

这样切的理由：登录是「这台机器上有哪些可用的 CLI 身份」，跟某一个席位无关。
把它放在席位里，人会以为登录属于这个席位 —— 而实际上换个席位它还在。
今天界面上「本机已登录的 CLI —— 与你共用上下文和额度」这句话就是这么来的：
它在解释一个本不该出现在这里的概念。

## 3. 新用户的主线

### 3.0 第一屏：他还不知道这是什么

以新用户身份做的审计，**最早三条都发生在走到「实例」之前**：

> 一打开是空房间，我不知道这是什么软件，也不知道「席位」要我建什么。
> 「房间」「席位」对我来说都是开会的词。

> 「主控 / 施工 / 审计 / worker」我一个都看不懂，不知道自己该选哪个。

> 要我选 Claude、Codex 还是 Grok，我只有 ChatGPT，对不上。

上一版从「新建席位」开始，默认了他知道自己要什么。他不知道。

#### 第一屏要回答三个问题

**1. 这是什么？** 一句话，用他的话，不用产品的词：

> 把几个 AI 助手拉进一个群聊，让它们围着你的项目一起干活。
> 你在中间看着、随时插话。

**2. 我需要准备什么？** 一句话说清代价，不藏：

> 需要至少一个 AI 编程助手的账号（ChatGPT、Claude 或 Grok）。
> 没有的话，先去开通一个再回来。

**3. 现在点哪？** **一个**按钮，不是一排：

> 〔开始：配第一个助手〕

#### 从「我有什么账号」问起，不是从「选哪个厂商」问起

「Claude / Codex / Grok」是**产品侧的词**。人心里装的是「我有一个 ChatGPT」。
所以第一步问的应该是：

```
你手上有哪个的账号？（有哪个用哪个，以后能再加）

  ChatGPT / OpenAI          → Codex
  Claude / Anthropic        → Claude Code
  Grok / X                  → Grok Build
  都没有 → 先去开通一个（给各家官网链接）
```

**左边是他认得的名字，右边才是要装的东西。** 他选左边，产品把右边的事办了。
「我只有 ChatGPT，对不上」这条就是这么消掉的 —— 不是让他学会对应关系，
是产品替他对应。

**这个列表由注册表生成，且只含已上架的厂商**（见 `30-provider-registry.md`）。

现在是三家。Google、DeepSeek、OpenCode、OpenClaw 都还没有运行层适配器、
隔离也没实测过，所以**一个字都不出现在这里** —— 在这里出现就等于承诺，
而人会照着去开通账号。让他为一个用不了的厂商开一个号，比不提它糟得多。

#### 角色先别问

「主控 / 施工 / 审计 / worker」是**这个产品的工作方式**，不是新用户第一分钟
需要理解的东西。第一个席位**直接给一个通用助手**，不问角色。

等他真的用起来、想加第二个人的时候，再解释分工 —— 那时他已经有具体感受，
「让另一个来审一遍」是句人话；而在第一屏，它只是四个陌生词。

#### 模型也别问

第一个席位用该厂商的默认模型。模型选择放进席位设置，给想调的人。
「gpt-5.6-sol」对第一次来的人是一串代号，问了只会让他随便选一个。

#### 走完之后要有一个「成了」的时刻

审计里另一条：「席位显示可启动之后，我不知道怎么证明它真的能用」。

所以引导的最后一步不是「建好了」，是**让它真的说一句话**：

> 助手已就绪。要不要先让它自我介绍一下？〔试一下〕

点了就在房间里发一条最小的消息，等它回话。**看见它回话，才算成了。**
在此之前的一切「✓ 完成」都是产品自己说的。

### 3.1 判定「这是第一次」

同时满足：实例池里没有任何 `managed` 实例、且没有任何席位绑定了实例。
**不看是不是第一次启动进程** —— 人可能重装、可能换机器、可能删光重来。

### 3.2 主线：从「我想要一个干活的人」开始

```
房间空的 → 「新建席位」
    ↓
选角色（主控 / 施工 / 审计 / worker）与厂商
    ↓
需要一个实例 ── 有可用的 ──▶ 选它 ──▶ 建好，席位可启动
    │
    └── 没有可用的 ──▶ 「去准备一个实例」──▶ 实例管理页
                                              ↓
                              ┌───────────────┴───────────────┐
                        本机已装该 CLI                  本机没装
                              ↓                            ↓
                    「发现本机 CLI」一键采用          安装引导（第 4 节）
                              ↓                            ↓
                        登录（或已登录）              装完 → 检测 → 登录
                              └───────────────┬───────────────┘
                                              ↓
                                    回到刚才那个席位，自动选中
```

**入口是新建席位，不是实例页。** 人来这儿是要一个干活的人，不是来管 CLI 的。
实例是他为了那件事必须先办的手续，产品应当**在他撞上时才把他领过去，
办完自动送回来**，而不是一进门先甩一页配置。

### 3.3 「自动送回来」怎么做

跳去实例页时带上来源（哪个席位草稿、缺哪个 provider）。实例可用之后：

- 实例卡上多一条「回到 @xxx 的创建」
- 席位草稿保留在原地，不因为跳走而丢

**草稿丢失是这类引导最常见的失败**，而人不会重来第二遍。

### 3.4 一个都不装怎么办

**不阻塞，但也不能让他以为成了。**

允许把席位建出来、停在「等待实例」。理由不变：装 CLI 要下载、要授权，
把这一段做成必须当场完成的闸，等于让第一次使用有一半概率断在半路。

但审计指出了上一版的漏洞：

> 没实例也能先把席位建出来，停在「等待实例」—— 我以为建好了，其实还不能用。

所以这种席位在房间里**不能长得跟正常席位一样**：

- 卡片明确显示「还不能用 —— 缺一个实例」，并带一条〔去准备〕
- @ 它时立刻回一句「我还没准备好，缺一个实例」，而不是石沉大海
- 房间顶部有一条常驻提醒，直到它能用为止

**「建好了」和「能用了」是两个状态，界面上必须分得开。**

### 3.5 一席一实例：这条乘法必须一上来就说清楚

**同一时刻，一个实例只服务一个席位**（INV-INST-1，已实现：绑定这一步就挡）。

所以：**3 个席位 = 3 个实例 = 3 次登录**。而本机 CLI 只有一份，
**最多只能给一个席位用**。

这不是限制，是 `claude-code#48786` 那件事的直接后果：多个进程共用一份凭据，
token 过期时一起去刷新，因为 refresh token 会轮转，只有第一个成功，其余全部掉线。
把两个席位塞进同一个实例，等于把这个故障内置进产品。

#### 引导上的后果

**第一次只引导建一个席位。** 建完、能回话了，再提第二个。一上来让人配三个，
他会在第二个席位那里撞上「本机 CLI 已被 @xxx 占用」，而那时他还没建立
「实例」这个概念，只会觉得产品坏了。

**第二个席位的引导里必须先说代价**，再让他选：

> @builder 已经在用本机 Claude 了。再加一个 Claude 席位需要一个新实例 ——
> 也就是**再登录一次**（可以是同一个账号，也可以是另一个账号）。
> 〔新建实例并登录〕〔换成别的厂商〕〔先不加〕

「可以是同一个账号」这句要写：产品不限制、也不承诺一个账号能登几个实例
（见 26 稿第 2 节），但人至少要知道他不是非得再买一个账号。

#### 席位列表里怎么显示

被占用的实例照样列出来，**置灰并写明是谁在用** —— 不能直接隐藏。
隐藏会让人以为「我的实例不见了」，而看见「@builder 正在用」他立刻就懂了。

#### 现有配置的迁移

今天的席位走的是旧路径（`accountId = __host__`），三个席位全都指向本机 CLI，
**独占对它们不生效 —— 它们此刻正共用同一份凭据目录**。这正是 #48786 那种共用，
只是旧路径没拦。

迁移不能默默进行，否则人一觉醒来发现两个席位起不来。做法：

1. 检测到「多个席位走旧路径且指向同一个 CLI」时，在实例页顶部给一条提示，
   如实说明它们正在共用一份登录、可能互相踢下线
2. 提供一键：把其中一个留在本机 CLI，其余的**逐个**引导建实例
3. **不自动改任何席位** —— 那会在人没准备好的时候让房间停摆

## 4. 装 CLI —— 产品自己装

> **这一节推翻了本稿上一版的「产品不代替人安装」。**
> 推翻它的是两件事：新用户审计的第一条结论，和同类产品的既有做法。

### 4.0 为什么改

上一版写「产品不代替人执行安装命令，那是往人的机器上装全局软件，必须他自己动手」。
理由本身站得住，结论却把人挡在门外：

- 以新用户身份做的审计，最致命的一条就是这个 ——
  「我不会写代码、没有终端，这条边界等于把第一次使用最关键的一步推到产品外面。
  卡住两次我会关掉，不会再打开。」
- **本机没有相关 CLI 就完全用不了本产品。** 这不是体验问题，是产品能不能被用起来的问题。
- 同类产品早就在这么做：CC Switch 的「本地环境检查」给每个 CLI 一张卡，
  显示当前版本 / 最新版本，直接有〔安装〕〔升级〕〔全部升级〕〔诊断安装冲突〕；
  Grok UI 的「CLI / 运行时」还能切 stable/alpha 通道、装指定版本。

**实测（2026-08-23）：三家都是 npm 包**，一套机制装得完：

```
@anthropic-ai/claude-code@2.1.196
@openai/codex@0.149.0
@xai-official/grok@1.0.3
```

既然没有技术障碍，「不代劳」就只是把难处转嫁给了最不该承担它的人。

### 4.1 本地环境检查

实例页顶部一块「本地环境」，每个厂商一张卡：

```
Claude Code        已安装 2.1.196 → 最新 2.1.241     〔升级〕
Codex              已安装 0.149.0 · 已是最新          ✓
Grok Build         未安装                             〔安装〕
```

- **当前版本**：跑 `<cli> --version` 拿到
- **最新版本**：查 npm registry（只查版本号，不下载）
- 状态三种：`未安装` / `可升级` / `已就绪`

### 4.2 安装与升级

统一走 `npm install -g <包名>`。产品**代为执行**，但全过程可见：

1. 点〔安装〕→ 先把**将要执行的命令原样显示出来**，人确认
2. 执行，**实时把 npm 的输出显示在卡片里**（不是转圈圈）
3. 完成后自动跑一次 `--version` 验证，把结果写在卡上
4. 失败：保留完整输出，给〔重试〕和〔改为手动安装〕

**升级同理，但永远是人点的**，产品不自动升。理由不变：升级会在运行中改变行为、
也可能改写实例目录 —— 产品甚至显式关掉了 CLI 自带的自动更新
（`GROK_DISABLE_AUTOUPDATER=1`）。自动装和自动升是两回事：
**第一次装是让人能用上，自动升是在人背后改变他脚下的地面。**

### 4.3 唯一真正需要人动手的一步：Node

`npm` 不在，三家都装不了。这是这条链上唯一产品无法代劳的环节。

所以**先检测 Node**，没有就先解决它：

- 检测不到时，环境检查最上面单独一条：「需要先装 Node.js（一次，之后都不用管）」
- 给**官方下载页链接**和**当前系统对应的安装包**指引，让人下载点两下就完
- 装完点〔重新检测〕
- **在此之前，三张 CLI 卡上的〔安装〕按钮是禁用的，并写明「等 Node 装好」**
  —— 不能让人点了才发现失败

### 4.4 装在别处的 CLI

有人的 CLI 不在 PATH 上（装在 WSL、装在自定义目录、用别的包管理器装的）。
所以环境检查里要能**手填可执行文件路径**，填完立刻验证并显示版本 ——
这也是 Grok UI 那个「CLI 路径」输入框在做的事。

检测不到就直接说「没装」，会把这批人误伤成「装不上」。

### 4.5 「手动安装命令」保留

折叠在下面，给愿意自己动手的人。**它是补充，不是主路径。**
上一版把它当成唯一路径，那正是问题所在。

### 4.6 「发现本机 CLI」

已经装了、但还没被产品用起来的 CLI，单独一条：

> 检测到本机已安装 claude 2.1.196，**已登录**。
> 可以直接拿它建第一个席位 —— 它跟你自己在终端里用的是同一份登录和同一份额度。
> 〔用它建席位〕〔改为新建一个独立实例〕

## 5. 版本与模型的对应

这是 Owner 明确点名的一条：**CLI 可以自己升级，而产品前端的模型列表是写死的。**
两边一定会错开，问题只是什么时候。

### 5.1 三条规则

1. **能问 CLI 就问 CLI。** Grok 有 `grok models`，那就以它为准，
   产品列表只作排序与显示名。
2. **问不到的，产品列表只是建议。** Codex 和 Claude 没有列表命令，
   产品给出已知模型，但**必须允许人手填一个产品没列的模型 id**。
   CLI 认不认，跑起来才知道 —— 那时如实转述它的原话。
3. **记录并显示 CLI 版本。** 每个实例卡上写明它跑的是哪个版本，
   建实例时探一次、之后每次检测顺带更新。

### 5.2 错开时怎么办

| 情况 | 产品怎么做 |
|---|---|
| CLI 更新了，出了产品没列的新模型 | 模型下拉最后一项永远是「手填其它模型…」。Grok 那边直接从 `grok models` 拿到，自动就有 |
| 产品列了某模型，而这个 CLI 版本不支持 | 席位启动时 CLI 会报错。**原样转述**（过密钥遮罩），并在实例卡上标出版本，让人能对上号 |
| CLI 版本低于产品验证过的下限 | 实例卡上提示「这个版本比我们验证过的旧，可能有些功能用不了」，**不阻止使用** |

### 5.3 不做的事

- **不做版本白名单。** 卡死版本会让人在厂商正常升级之后无法使用产品，
  而升级是他自己机器上的事，我们没有资格拦。
- **不自动升级 CLI。** 升级会在运行中改变行为，也可能改写实例目录 ——
  产品反而显式关掉了自动更新（`GROK_DISABLE_AUTOUPDATER=1`）。
- **不猜模型能不能用。** 只有跑起来才知道。猜错的代价是人对着一个
  产品编出来的理由，找不到真问题。

## 6. 席位那边具体长什么样

新建席位面板里，「运行实例」这一段变成：

```
运行实例
┌──────────────────────────────────────────────┐
│ ○ 本机 claude CLI     已登录 · 2.1.196        │
│ ○ 审计用              已登录 · 与你的账号不同  │
│ ○ 备用号              未登录（去实例页登录）   │  ← 置灰
│ ○ 施工席位占用中       @builder 正在用         │  ← 置灰
└──────────────────────────────────────────────┘
没有可用的？〔去实例管理页准备一个 →〕
```

被占用的那条**不隐藏、只置灰**：人要能看见「它还在，只是被谁用着」。
一个实例同时只服务一个席位，所以**多一个席位就要多一个实例、多一次登录** ——
这句话要出现在这一屏上，不能等他点下去才发现。

**这一段里没有任何「登录」按钮。** 它只回答「用哪个」。

席位设置（已建好的席位）同理：只有一个下拉，加一条「去实例管理页」。

## 7. 失败与退路

| 卡在哪 | 人看到什么 | 出路 |
|---|---|---|
| 没装 CLI | 环境检查卡：〔安装〕按钮 + 实时输出 | 产品代装，装完自动验证 |
| 没装 Node | 单独一条：下载链接 + 重新检测；CLI 的安装按钮禁用并说明 | 装 Node，这是唯一要自己动手的一步 |
| 装了没登录 | 实例卡「未登录」+ 登录按钮 | 就地登录 |
| 登录中途放弃 | 实例停在「未完成登录」，目录保留 | 继续登 / 删掉 |
| 浏览器没弹出来 | 进度区里给可点的授权链接 | 手动打开 |
| 建了席位但没实例 | 席位显示「等待实例」，房间里如实标注 | 随时回来补 |
| 模型 CLI 不认 | 原样转述 CLI 的话 + 实例版本 | 换模型或升级 CLI |

**每一条都要有出路，且出路必须是界面上点得到的。** 使用者没有终端。

---

## 8. 明确不做

- 席位那边不出现任何登录入口
- 不自动升级 CLI（安装与升级都由人点，产品只负责执行与显示）
- 不做模型/版本白名单，不猜模型可用性
- 不因为「没有实例」就阻止建席位
- 不在跳去实例页时丢掉席位草稿
