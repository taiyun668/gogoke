# 30 · 厂商注册表：不止三家

状态：**已整合进 31-product-design.md**（保留作为该决定的推导记录）
日期：2026-08-23
决策人：Owner
起因：产品目前把 Claude / Codex / Grok 三家写死在源码里。Owner 要求把用户量
较大的都囊括进来 —— Google、DeepSeek、OpenCode、OpenClaw 等。

---

## 1. 一个必须先说清的分层

**「能在实例页里被装、被登录、被看状态」和「能真的跑一个席位」是两件事。**

| 层 | 做什么 | 扩一家的成本 |
|---|---|---|
| **配置层** | 检测装没装、装、升级、登录、查状态、显示版本 | **一条数据** |
| **运行层** | 席位真的跑起来：起进程、说协议、流式、中途插话、沙箱 | **一份适配器代码** |

三家现有的运行层长得完全不一样：

- Codex：`codex app-server --stdio`，自有 JSON-RPC
- Grok：ACP 协议，`agent … stdio`
- Claude：`-p --input-format stream-json --output-format stream-json`

**没有共同协议。** 所以新增一家，配置层是填表，运行层是写代码。

分层是为了让人看清成本差距，**不是为了允许只做一半就上架**：

> **INV-PROV-1**　一个厂商，只有在**配置层与运行层都做完、且隔离经过反向验收**
> 之后，才进注册表。在那之前，它**在产品里的任何地方都不出现** ——
> 不出现在实例页、不能被安装、不能被登录、不出现在第一屏的账号清单里。
>
> **产品里不存在「半支持」这个状态。**

曾经想过一个折中：先让它出现在实例页，能装能登，只是席位那边不给选，
并标注「暂不支持建席位」。**这是错的** —— 人会照着装、照着登，
花完一整套功夫之后才发现建不了席位。那不是「有限支持」，是白折腾一场，
而且是产品亲手把他领过去的。

这条同时是给未来的自己写的：注册表一旦数据驱动，往里加一行的诱惑非常大。
加一行是十分钟，写适配器加实测隔离是几天 —— 而界面不会替你区分这两者。

## 2. 注册表长什么样

```ts
interface ProviderEntry {
  id: string;                 // "claude" | "codex" | "grok" | "gemini" | ...
  label: string;              // 界面上显示的名字
  vendor: string;             // 「Anthropic」「OpenAI」「xAI」「Google」…

  // —— 配置层：填表就能扩 ——
  install: { npm: string } | { url: string };   // npm 包名，或只能去官网下
  bin: string;                // PATH 上的可执行文件名
  versionArgs: string[];      // 通常 ["--version"]
  home: { env: string; rel: string };   // 隔离变量 + 凭据文件相对路径
  login: { args: string[] };            // 登录命令
  status: {                             // 免费状态命令与判据
    args: string[];
    loggedIn: (out: string, code: number) => boolean;
    loggedOut: (out: string, code: number) => boolean;
  };
  modelsArgs?: string[];      // 能问 CLI 要模型列表的才有（目前只有 grok）
  models?: string[];          // 问不到时的建议列表

  // —— 运行层：必填。没有适配器的厂商根本进不了这张表 ——
  seat: { adapter: "codex-app-server" | "grok-acp" | "claude-stream-json" };
}
```

**`seat` 是必填的。** 这是 INV-PROV-1 在类型上的执行面 —— 想加一家而没有
适配器，类型检查就过不去，加不进来。规矩写在文档里会被忘掉，写进类型里不会。

## 4. 「最新版本」从哪来

查 npm registry 的版本号（只查版本，不下载）。这正是 CC Switch 在做的事 ——
它显示 Claude Code「当前 2.1.196 / 最新 2.1.241」，我们查到的最新也是 2.1.241，
两边对得上。

非 npm 分发的（若有）只显示当前版本，不显示「最新」，也不给升级按钮 ——
**不知道就不要装作知道**。

---

## 5. 判据必须一家一份，而且都要有反向用例

三家的判据已经互不相同，且踩过坑：

| 厂商 | 已登录 | 未登录 |
|---|---|---|
| Claude | JSON `"loggedIn": true` | `"loggedIn": false` |
| Codex | **exit 0 且无输出** | exit 1 + `Not logged in` |
| Grok | 含 `logged in with` | 含 `not authenticated` |

Codex 那条今天才修好：它登录成功时**什么都不打印**，原判据在找文字，
于是正在用的账号一直显示「未登录」。

> **INV-PROBE-2（重申）**　每加一家，判据必须同时通过「肯定串」和「否定串」
> 两个用例。`/Logged in/i` 会匹配上 `Not logged in` —— 这个坑在本项目里骗过两轮。

新加一家时，**先手动跑一遍它的状态命令、把两种输出都记下来**，再写判据。
不许照着别家抄。

---

## 6. 隔离变量也得一家一查

已知：Claude 认 `CLAUDE_CONFIG_DIR`、Codex 认 `CODEX_HOME`、**Grok 只认
`GROK_HOME`、完全不看 `HOME`**。

新加一家时必须实测它认哪个变量，验收方式是固定的：

> 把变量指向一个**已初始化但从没登录过**的目录，状态命令必须报未登录。

这条不做，隔离就是纸面上的 —— Grok 那次就是这样藏了很久。

候选厂商**不出现在这里**，也不出现在第一屏的账号清单、席位的厂商下拉里。
产品里没有「装了但用不了」这种东西。

### 想让人知道「以后会支持谁」怎么办

如果确实想透露路线，那是**产品官网或更新日志**的事，不是实例页的事。
在实例页出现，就意味着「这里可以操作」；而候选厂商在这里没有任何
有意义的操作可做。

## 8. 上架一家的清单

**这是一份完整清单，不是分两批。** 全部做完才进注册表，做完之前它在产品里
不存在。

配置层：

1. 确认真实的分发方式（npm 包名 / 官网下载），**查得到才填**
2. 手动跑一遍 `--version` 与状态命令的两种情形，记下真实输出
3. 写判据，配肯定 / 否定两个用例（INV-PROBE-2）

隔离 —— 这一步和现有三家同等对待，不许因为「先上了再说」而跳过：

4. 实测它认哪个隔离变量（别照抄别家，Grok 就不认 `HOME`）
5. 反向验收：变量指向**已初始化但从没登录过**的目录，状态命令必须报未登录
6. 查清它会不会有跨实例共享的东西（Grok 的 leader socket 就是一个 ——
   不带 `--no-leader` 隔离直接作废），以及有没有能从环境放宽沙箱的变量
   （`GROK_SANDBOX` 那种）

运行层：

7. 读它的协议文档，写适配器：起进程、说协议、流式、中途插话、干净收尾
8. 把沙箱与能力边界映射成**启动参数**（不是配置文件），并配反向用例 ——
   Codex 的 sandbox 传 camelCase 会静默退回只读，这类错必须测出来
9. 补席位启停与流式的测试

**九步做完才上架。** 少任何一步，人拿到的都是一个会在半路失败的东西。

---

## 9. 明确不做

- 不把没查证的厂商写进注册表
- **不让没有适配器、没做过隔离验收的厂商出现在产品的任何地方**
- 不做「先上配置层、运行层以后补」的半支持形态
- 不给非 npm 分发的厂商显示「最新版本」和升级按钮
- 不照着别家抄判据
