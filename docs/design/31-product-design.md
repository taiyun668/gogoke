## 1. 这个产品是什么

把几个 AI 助手拉进一个群聊，让它们围着你的项目一起干活。你在中间看着、随时插话。

三条贯穿全篇的前提：

- **使用者不写代码，也没有终端。** 产品自己也不提供终端。凡是「你去命令行里
  跑一下」的设计，对他等于没有设计
- **每个助手背后是一个厂商 CLI**，跑在这台机器上，用他自己的账号
- **本机没有相关 CLI 就完全用不了本产品** —— 所以装 CLI 是产品的事，不是他的事

## 2. 四个概念

```
项目                      总上下文
  ├── 房间 A / 房间 B      各是项目里某个板块的上下文
  └── 席位                 房间里的一个位置，有 @id、角色、历史
        └── 实例           它跑在哪个 CLI 登录上
```

| 概念 | 一句话 | 归谁 |
|---|---|---|
| **项目** | 总上下文 | — |
| **房间** | 某个板块的上下文；席位在房间之间进出 | 项目 |
| **席位** | 群聊里的一个位置。身份是 @id 和它的历史，不是它跑在哪 | 项目 |
| **实例** | 一份独立的 CLI 登录，装在它自己的目录里 | 全局，跨项目 |

### 2.1 一席一实例

**同一时刻，一个实例只服务一个席位。**（已实现）

所以 **3 个席位 = 3 个实例 = 3 次登录**，而本机 CLI 只有一份，最多给一个席位用。

这不是产品的选择，是 [claude-code#48786](https://github.com/anthropics/claude-code/issues/48786)
逼出来的：多个进程共用一份凭据，token 过期时一起去刷新，因为 refresh token
会轮转，只有第一个成功、其余全部掉线。

**所以这件事要在第一屏就讲**（4.2），而不是等他建第二个席位时才撞上。

### 2.2 「占用」是什么意思

审计问：占用指绑定还是进程在跑？**两个都算，但含义不同：**

| | 什么时候发生 | 界面上怎么说 | 怎么解开 |
|---|---|---|---|
| **绑定占用** | 席位选了这个实例，还没启动 | 「已绑给 @xxx」 | 到那个席位改选别的实例，或解绑 |
| **运行占用** | 席位正在跑 | 「@xxx 正在用」 | 停掉那个席位 |

**两种都禁止第二个席位绑上来**，但给出的出路不同 —— 上一版只写「停掉那个席位」，
而绑定占用根本没有进程可停。

## 3. 页面结构

```
房间（主界面）
  ├── 左侧栏：项目 / 房间列表，底部「本机 · 实例 N/M 可用」→ 菜单
  ├── 中间：时间线 + 输入框
  └── 右侧抽屉：席位详情 / 项目设置

设置（整页覆盖，返回不打断任何席位）
  ├── 概览
  ├── 实例       ← 核心页，本地环境检查也在这里
  ├── 席位
  ├── 房间
  ├── 外观
  ├── 环境
  └── 关于
```

**本地环境检查（装 CLI、装 Node）放在实例页顶部**，不单独开页 ——
它是「准备实例」的前置，不是另一件事。

### 3.1 职责切开

| | 席位（新建 / 设置） | 实例页 |
|---|---|---|
| 选厂商、模型、角色、能力 | ✅ | |
| **选用哪个实例** | ✅ 只是挑一个现成的 | |
| 装 / 升级 CLI、装 Node | | ✅ |
| 建实例 | | ✅ |
| **登录 / 换账号** | ❌ 一个入口都不留 | ✅ |
| 检测状态、删除实例 | | ✅ |

**席位那边看到的实例是一份只读清单。** 不能用的照样列出来，置灰并写明原因，
末尾给一条「去实例页」。

> 审计指出：4.8 的〔新建实例并登录〕与这条冲突。**解法：那个按钮不在席位里
> 执行登录，它只是「带着上下文跳到实例页」的入口。** 席位里没有登录逻辑，
> 只有一条去实例页的路 —— 这与第一次引导（4.5）是同一条路。

## 4. 第一次进来

### 4.1 判定

实例池里没有任何自建实例，且没有任何席位绑定实例。**不看是不是第一次启动进程**
—— 人可能重装、换机器、删光重来。

**中途放弃的人怎么回来**：只要还没有「能用的席位」，入口就一直在 ——
房间顶部一条「继续配置第一个助手」，以及左下角「本机」菜单里的「产品导览」。
关掉第一屏（Esc / 先离开）或跳过「试一下」都不能把这条路收掉。
审计原话：「中途关窗口再回来，只要我留过实例，就不把我当第一次 —— 我找不到刚才那条路。」

### 4.2 第一屏

**1. 这是什么？**

> 把几个 AI 助手拉进一个群聊，让它们围着你的项目一起干活。你在中间看着、随时插话。

**2. 需要准备什么？** 三件事一次说完，不挤牙膏：

> - 一个 AI 编程助手的账号：**ChatGPT、Claude 或 Grok**（目前支持这三家）
> - 你要一起干活的那个项目文件夹
> - 大约 5 分钟：产品会帮你把需要的东西装好
>
> 想让多个助手同时干活的话，**每个助手要一个自己的账号登录** ——
> 可以是同一个账号登多次，也可以是不同账号。先配一个，跑起来再说。

**3. 现在点哪？** 一个按钮：〔开始〕

### 4.3 从「你有哪个账号」问起

```
你手上有哪个的账号？

  ChatGPT / OpenAI     → 会用 OpenAI 的 Codex
  Claude / Anthropic   → 会用 Anthropic 的 Claude Code
  Grok / X             → 会用 xAI 的 Grok Build

  我有别家的（Gemini、DeepSeek…）
  我一个都没有
```

**左边是他认得的名字，右边说清这等于要用什么** —— 审计原话：「我选了 ChatGPT，
并不知道这等于要登 Codex。」

#### 选了「我有别家的」

**如实说，不装作他没有账号**：

> 目前只支持 ChatGPT、Claude、Grok 三家 —— 因为每一家都要单独做适配和隔离，
> 没做完的我们不会放上来让你白折腾。
>
> Gemini、DeepSeek 等在计划中。你可以先用上面三家里的一个，或者过段时间再来。

审计原话：「我手上明明有 AI 账号，产品让我去再开一个 —— 我会以为这软件
认不得我的账号，直接关掉。」**认不得和还没支持是两回事，要说清楚。**

#### 选了「一个都没有」

给三家的开通页链接，并说明**哪个有免费额度**、大概多少钱。开完回来点〔我开好了〕。

### 4.4 问项目文件夹

审计：「第一屏说围着『我的项目』干活，但从来没问项目在哪。」

选完账号之后、装东西之前，问一次：

> 要一起干活的项目在哪个文件夹？〔选择文件夹〕
>
> 助手会读写这个文件夹里的东西。可以之后再改。

**这一步不能省** —— 席位启动需要工作区，没有它整条链走不完。

### 4.5 第一个席位不问角色、不问模型

「主控 / 施工 / 审计 / worker」是这个产品的工作方式，不是第一分钟要理解的东西；
`gpt-5.6-sol` 对他就是一串代号。

**第一个席位固定为**：角色 = 通用助手（可读写所选项目文件夹）、模型 = 该厂商默认。
等他想加第二个人时再解释分工。

### 4.6 主线

```
第一屏 → 选账号 → 选项目文件夹
    ↓
本地环境检查（第 5 节）：Node? CLI?
    ↓
建实例 → 登录
    ↓
建席位并绑定
    ↓
**让它说一句话** ←── 这一步才叫「成了」（4.7）
```

跳去实例页时带上来源。实例可用后自动回到席位创建，草稿原地保留 ——
**草稿丢失是这类引导最常见的失败**，而人不会重来第二遍。

### 4.7 收尾：让它真的说一句话

审计：「席位显示可启动之后，我不知道怎么证明它真的能用。」

所以最后一步不是「建好了」，是：

> 助手已就绪。先让它打个招呼，确认一切正常？〔试一下〕〔跳过〕

**定义清楚**（审计指出上一版这一步没有任何标准）：

| | |
|---|---|
| **触发** | 只有人点〔试一下〕才发生。**不自动跑** |
| **内容** | 房间里以人的身份发一条固定的短消息，@ 这个席位 |
| **成功** | 席位在超时内回了任意内容 → 显示「它回话了，可以开始了」 |
| **失败** | 超时或 CLI 报错 → **原样转述 CLI 的话**（过密钥遮罩），并给〔重试〕〔去实例页检查〕 |
| **花费** | 这是一次真实调用。按钮上直接写明：「会用掉一点点额度」 |
| **跳过** | 允许。跳过后席位卡上留一条「还没验证过」，随时能点 |

### 4.8 装不了也不阻塞，但不能让他以为成了

允许席位停在「等待实例」。但这种席位**不能长得跟正常席位一样**：

- 卡片是**虚线边框 + 灰色头像**，写明「还不能用 —— 缺一个实例」，带〔去准备〕
- @ 它时，**房间里由系统身份**回一条：「@xxx 还没准备好，缺一个实例。〔去准备〕」
  —— 这条进房间历史，其它席位也看得见（否则它们会以为没人回应）
- 房间顶部常驻提醒，直到它能用

**「建好了」和「能用了」是两个状态，界面上必须分得开。**

### 4.9 第二个席位

> @builder 已经在用本机 Claude 了。再加一个 Claude 席位需要一个新实例 ——
> 也就是**再登录一次**（可以是同一个账号，也可以是另一个账号）。
> 〔去准备一个实例〕〔换成别的厂商〕〔先不加〕

第一屏（4.2）已经预告过这件事，这里是兑现，不是突然袭击。

## 5. 本地环境：产品自己装

**本机没有 CLI 就完全用不了本产品，所以这一步不能推给用户。**

同类产品早就在代劳（CC Switch 的「本地环境检查」有〔安装〕〔升级〕〔全部升级〕；
Grok UI 还能切通道、装指定版本），而且没有技术障碍 —— 三家都是 npm 包。

### 5.1 顺序：先 Node，再 CLI

```
① Node.js         未检测到          〔安装 Node〕
   ─────────────────────────────────────────────
② Claude Code     等 Node 装好       〔安装〕(禁用)
   Codex          等 Node 装好       〔安装〕(禁用)
   Grok Build     等 Node 装好       〔安装〕(禁用)
```

**Node 没装好之前，CLI 的安装按钮禁用并写明原因** —— 不能让人点了才发现失败。

### 5.2 Node 怎么装

审计指出上一版最大的自相矛盾：**「装 CLI 不能推给用户」和「Node 你自己装」
是同一问题的两套答案**。

Node 确实无法用 npm 装（它就是 npm 本身），但**「无法用同一种方式装」不等于
「甩给用户」**。这一步要走完：

| 步 | 产品做什么 |
|---|---|
| 检测 | 跑 `node --version`，要求 ≥ 产品声明的最低版本 |
| 下载 | **给出当前系统对应的安装包直链**（Windows x64 → `.msi`），不是官网首页 |
| 引导 | 一句话：「下载后双击安装，一路下一步即可，不需要改任何设置」 |
| 装完 | 〔我装好了，重新检测〕 |
| **PATH 没刷新** | 检测不到但用户说装好了 → **提示需要重启本产品**，并给〔重启〕按钮。这是 Windows 上装完 msi 最常见的情形，上一版完全没写 |
| **公司电脑装不了** | 检测到安装被策略阻止时，如实说：「你的电脑限制了安装。需要联系 IT，或换一台机器」—— 给一条明确的死路，好过让他反复重试 |

### 5.3 CLI 怎么装

统一 `npm install -g <包名>`，产品执行。

**进度显示分两层**（审计：「实时 npm 输出对我没有帮助，只让我更不敢动」）：

```
正在安装 Claude Code…  这通常要半分钟
                                          〔查看详细日志 ▾〕
```

- **默认给人话**：正在安装 / 已完成 / 失败了
- **原始 npm 输出默认折叠**，出错时自动展开 —— 因为那时它是唯一的线索

### 5.4 装失败怎么办

上一版只写了「〔重试〕和〔改为手动安装〕」，而「手动」对没有终端的人等于没有出路。
分情况给：

| 情况 | 怎么识别 | 出路 |
|---|---|---|
| 网络问题 | npm 报 ETIMEDOUT / ENOTFOUND | 〔重试〕；提示可能需要代理 |
| 权限不够 | EACCES / EPERM | **不提权**。会装到你自己的文件夹；提权会装到管理员目录，这边找不到。prefix 不在用户目录下时提前说明并给〔复制修正命令〕，不判成公司禁装 |
| 磁盘满 | ENOSPC | 如实说，给出需要的空间 |
| 公司策略阻止 | 反复权限失败 | 明确的死路 + 「联系 IT」，并给出可复制的命令让 IT 代劳 |
| 装到一半中断 | 验证时 `--version` 失败 | 〔清理并重装〕（先 `npm uninstall -g` 再装） |
| 都不是 | 其它 | 保留完整输出，给〔重试〕与〔复制日志〕 |

**「复制日志」是给他找人帮忙用的**，不是让他自己看懂。这跟「让他去终端」不同 ——
前者他做得到。

### 5.5 升级永远由人点

**产品不自动升级。** 自动装和自动升是两回事：**第一次装是让人能用上；
自动升是在人背后改变他脚下的地面。** 后者会在运行中改变行为、也可能改写实例目录
—— 产品甚至显式关掉了 CLI 自带的自动更新。

### 5.6 装在别处的 CLI

有人的 CLI 不在 PATH 上（WSL、自定义目录、别的包管理器）。要能**手填可执行文件
路径**，填完立刻验证并显示版本。检测不到就说「没装」，会把这批人误伤成「装不上」。

## 6. 实例

### 6.1 一个实例是什么

一份独立的 CLI 登录，装在它自己的目录里。**产品不搬凭据**：登录由厂商自己的
OAuth 写进那个目录，产品只做三件事 —— 备目录、发起登录、用免费状态命令看登没登。

### 6.2 「免费状态命令」是什么

审计指出：这个词在上一版里从头用到尾，却从没定义过，而第 10 节的探测不变量全靠它。

> **免费状态命令**：该 CLI 提供的、**能判断登录状态且不调用模型、不消耗额度**
> 的命令。

各家实测所得：

| 厂商 | 命令 | 已登录 | 未登录 |
|---|---|---|---|
| Claude | `claude auth status` | JSON `"loggedIn": true` | `"loggedIn": false` |
| Codex | `codex login status` | **exit 0 且无输出** | exit 1 + `Not logged in` |
| Grok | `grok models` | 含 `logged in with` | 含 `not authenticated` |

**Codex 那条今天才修好**：它登录成功时什么都不打印，原判据在找文字，
于是正在用的账号一直显示「未登录」。

**每家的判据必须一家一测、一家一写，且同时有肯定与否定用例**（第 10 节）。

### 6.3 实例的状态

审计指出上一版少了一个：**「未完成登录」是第 5 个状态，却不在枚举里。**

| 状态 | 含义 | 怎么进入 |
|---|---|---|
| `未登录` | 目录建好了，没登过 | 建实例后 |
| `登录中` | 登录进程正在跑 | 点了登录 |
| **`未完成登录`** | 登录起过但没走完（人关了浏览器 / 放弃了） | 登录进程退出而状态仍是未登录 |
| `已登录` | 可用 | 状态命令确认 |
| `需重新登录` | 凭据过期 | 状态命令或运行时认证错误 |
| `未知` | **还没看过**，不是「坏了」 | 刚重启、从没探过 |

`未知` 在被用到之前会顺手探一次（免费命令，不花额度）。

### 6.4 实例页

按厂商分组，每张卡：标签（可就地改名）、目录、状态徽章 +「最后确认于 X」、
CLI 版本、当前被哪个席位占着（区分绑定 / 运行，见 2.2）。
操作：登录 / 检测 / 重命名 / 删除。

顶部四个数字：我建的实例 / 可用 / 席位占用中 / 待登录。

**本机 CLI 也在列表里**，排在每个厂商最前面，但不能删除（它的目录就是你的
家目录）、不能改名，且卡上写明：在它上面登录会写进你本人的凭据。

### 6.5 不显示剩余额度

要那个数字得拿 token 去问厂商接口，而产品不读凭据内容。用完了就显示用完了。

### 6.6 登录

无窗口跑厂商 OAuth。审计：「点登录之后没有窗口，我以为死机了。」

**所以点下去的第一时间就要说清楚会发生什么**：

> 正在打开浏览器让你授权。**这里不会弹出黑色窗口，这是正常的。**
> 浏览器没自动打开的话，用下面这个链接。

进度直接长在卡片里 —— 登录进程没有可见窗口，人看不见它，所以它说的每一行都
搬上来（上屏前过密钥遮罩），抓到授权链接就给一个可点入口。

**中途放弃**：状态变 `未完成登录`，目录保留，卡上给〔继续登录〕〔删掉重来〕。

## 7. 支持哪些厂商

### 7.1 分层与准入

「能在实例页里被装、被登录」和「能真的跑一个席位」是两件事：配置层扩一家是
一条数据，运行层是一份适配器代码。三家现有协议完全不同，**没有共同协议**。

> **一个厂商只有在配置层与运行层都做完、且隔离经过反向验收之后才进注册表。
> 在那之前，它在产品的任何地方都不出现。产品里不存在「半支持」。**

人会照着装、照着登、甚至为它开通一个账号，最后才发现建不了席位 ——
那不是「有限支持」，是白折腾一场，而且是产品亲手把他领过去的。

**执行面放进类型**：注册表条目的 `seat` 字段必填，没有适配器就加不进来。

**但第一屏要如实说支持范围**（4.3）—— 不出现在功能里，和不告诉他，是两回事。

## 8. 版本与模型

**CLI 会自己升级，而产品的模型列表是写死的。两边一定会错开。**

只有 Grok 能反问 CLI 要模型列表（`grok models`），Codex 与 Claude 都只有
`--model` 入参。所以：能问就问；问不到的产品列表只是建议，**必须允许手填**；
每个实例卡显示它跑的 CLI 版本。

| 情况 | 产品怎么做 |
|---|---|
| CLI 出了产品没列的新模型 | 下拉最后一项永远是「手填其它模型…」 |
| 产品列了而这个版本不支持 | 启动时 CLI 会报错，**原样转述**并标出实例版本 |
| 版本比验证过的旧 | 卡上提示，**不阻止使用** |

**不做版本白名单** —— 卡死版本会让人在厂商正常升级之后用不了产品。

## 9. 失败与退路

**每一条出路都必须是界面上点得到的动作。** 使用者没有终端。

| 卡在哪 | 他看到什么 | 出路（界面动作） |
|---|---|---|
| 没装 Node | 下载直链 + 一句话说明 | 〔安装 Node〕→〔我装好了，重新检测〕 |
| 装完仍检测不到 | 「可能需要重启本产品」 | 〔重启产品〕 |
| 公司电脑禁装 | 明确说是策略限制 | 〔复制命令给 IT〕（明确的死路，不让他空转） |
| 装 CLI 失败 | 分情况的原因 + 折叠日志。**不提权**，装到你自己的文件夹；prefix 不在用户目录下时提前说明，不判成公司禁装 | 〔重试〕/〔清理并重装〕/〔复制日志〕/〔复制 prefix 修正命令〕 |
| 装了没登录 | 实例卡「未登录」 | 〔登录〕 |
| 点了登录没窗口 | **提前说明：不会有窗口** | 〔用这个链接授权〕 |
| 登录中途放弃 | 「未完成登录」 | 〔继续登录〕/〔删掉重来〕 |
| 建了席位但没实例 | 虚线卡「还不能用」+ 房间顶部提醒 | 〔去准备〕 |
| 实例被别人绑着 | 「已绑给 @xxx」 | 〔去 @xxx 改选〕 |
| 实例正被跑着 | 「@xxx 正在用」 | 〔停掉 @xxx〕 |
| 模型 CLI 不认 | 原样转述 + 实例版本 | 〔换模型〕/〔升级 CLI〕 |
| 试跑失败 | 原样转述 CLI 的话 | 〔重试〕/〔去实例页检查〕 |
| 路径建目录就失败（单节 > 255） | 「这个路径 Windows 建不出来」 | 〔换一个更浅的文件夹〕 |
| 目录建得了，助手写会话文件会越 260 | 「文件夹能建，但助手写记录时会失败」 | 〔换一个更浅的文件夹〕/〔复制开长路径的命令给 IT〕 |
| 路径 ≥ 260，Node 建得成、助手进不去 | 「路径看起来建好了，其实助手进不去」 | 〔换一个更浅的文件夹〕。**不要说成没装** |

## 10. 不变量

每条都要有可执行的判定，否则它只是句口号。

| 不变量 | 怎么验 |
|---|---|
| 产品不读 / 写 / 复制 / 移动凭据 | 代码里除删除实例外，没有任何读写凭据路径的调用；测试断言 |
| 凭据内容不上屏 | 所有第三方输出经过遮罩函数；遮罩函数有针对 JWT / `sk-` / `ghp_` / URL query 的用例 |
| 目录只在人确认后创建 | 「列出实例」「打开设置」之后磁盘无新目录 —— 有测试 |
| 一个实例同时只有一个使用者 | 第二个席位绑定 / 启动时被拒，有测试 |
| 按 pid 操作进程必须校验创建时间 | 代码里不存在只凭 pid 的 kill；grep 断言 |
| 隔离必须经统一入口 | 所有启动 CLI 的路径都调同一个函数；每家一条「空目录必须报未登录」的测试 |
| **判据本身有反向用例** | 每家的 `loggedIn` / `loggedOut` 各有肯定串与否定串的用例 |
| 没适配的厂商不出现 | 注册表 `seat` 字段必填 —— 类型检查即执行面 |

最后两条都是被真实事故换来的：`/Logged in/i` 会匹配上 `Not logged in`，
这个坑骗过两轮；按记下的 pid 强杀，误杀过 Claude 桌面端。

## 12. 明确不做

- 席位那边不出现任何登录入口（去实例页的跳转不算）
- 不自动升级 CLI
- 不显示剩余额度
- 不做模型 / 版本白名单，不猜模型可用性
- 不让没适配的厂商出现在产品功能里；但会如实告诉人目前支持哪几家
- 不因为「没有实例」就阻止建席位，但也不让他以为已经能用
- 不自动跑试跑验证（要花钱的事由人点）
- 不在跳去实例页时丢掉席位草稿
- 不代替人在厂商侧注销账号
