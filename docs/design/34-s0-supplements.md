## ① 过渡期实例独占归谁 —— 现在是一个真空

回执写「Room 的 `claim` 不再是最终权威，Room 只显示占用情况，无权释放或覆盖」。

**但 Host 存在之前，Room 必须继续持有它。** 否则这段时间独占闸是空的 ——
而这正是审计里那句「两边都保证会漂移，都不保证就漏」。

需要一条明确的交接规则写进 S0：

> S1–S2 期间，Room 仍是实例独占的唯一权威。
> Host 上线的那一刻起，Room 的 `claim` / `release` 改为只读转发。
> **交接是一次性切换，不存在两边同时有权的窗口。**

Room 侧现有的写入点只有 5 处（`ensureSeat` 的 claim、`closeAndRelease` 与
移出席位的 release、bind-instance 的换绑 release），切换面很小。
但不写这条，中间这段时间就是靠「大家都知道」在维持。

## ② 迁移期间产品还能不能用

回执没提现有的 `timeline.json`、`seats.json`、`instances.json` 在 S1 之后怎么办。
三种可能后果完全不同：

| 形态 | 后果 |
|---|---|
| 双写（Room 写 JSON，也写 Store） | 两份数据会漂移，且漂移时没人报错 |
| 只写 Store，JSON 变只读历史 | 需要一次真实迁移，且不可逆 |
| Store 旁路运行、只记录不裁决 | 安全，但那就还不是「唯一权威」 |

**建议第三种作为 S1 的验收形态**：Store 先影子运行，记录但不裁决；
等它和 Room 的判断在真实使用中连续一致一段时间，再切成权威。

这样切换前就有证据，而不是切换后才发现不一致。
判据可以很朴素：同一段时间里，Store 认为「谁占着哪个实例」「哪个 Run 在跑」
与 Room 的实际行为逐条对得上，不一致就记一条差异。

## ③ Host 自己的生命周期，是刚踩过的那个坑

「用户级后台单实例、UI 关闭只断开连接」方向对。但请注意实测结论：

> **Windows 上后台进程没有控制台，收不到任何信号。**
> `taskkill` 不加 `/F` 会被直接拒绝。

Room 的退出收口为此重写过一遍，最后靠的**不是优雅退出**，
而是下一轮启动时按 pid + 创建时间判断上一轮的进程还活着没有。
真机验证过两次：房间被强杀之后，它启动的 `grok.exe` 仍然活着、
pid 与创建时间都没变；新一轮启动如实拒绝把实例交出去。

Host 会原样继承这个问题，而且更严重 —— 它是常驻的、单实例的。
S2 的验收里必须包含：

1. Host 被强杀之后，它派生的 CLI 进程会怎样（大概率变孤儿）
2. 下一次启动怎么发现它们（同一套 pid + 创建时间判据）
3. 「单实例」怎么保证 —— 互斥锁还是端口占用？
   **注意锁文件在强杀之后不会被清理**，所以「锁文件存在」不能等于
   「另一个实例还活着」，判据同样要落到进程身份上

## ④ 判据搬过去要重新验一次

`proc.ts` 与 `instances.ts` 的判断迁进 Runner/Host 侧是对的。
但**搬家等于重写，判据必须重新配反向用例**。

这个项目已经栽过两次：

- `/Logged in/i` 会匹配上 `Not logged in` —— 骗过两轮
- 「空目录必须报未登录」这条验法对 Grok **完全无效**：
  Grok 只认 `GROK_HOME`，而那恰好是唯一被设对的一维。
  判据挑中了唯一被满足的维度，于是隔离早就漏了而测试一直全绿

所以搬过去之后至少要有这三条：

| 情形 | 期望 |
|---|---|
| pid 存在，创建时间对得上 | 放行 |
| pid 存在，创建时间对不上 | **拒绝下手**（这个号已经是别人的了） |
| 记了身份但查不到当前值 | **拒绝下手**（宁可留一个孤儿，也不再误杀一次） |

TS 侧的 `mayKillProcess` 是纯函数，可以直接对着写用例。

## 关于垂直切片的一个范围建议

切片定义同意，但建议再削一刀：

> 用户 `@Grok` → Store 原子创建 → Host 派发 → 现有 seat-runtime 执行
> → 返回终态证据 → ~~时间线显示成果~~

**最后一步第一刀先不做投影改造**，让 Room 照现在的方式显示，
Store 那边只保证记录正确。

理由：UI 投影一改，出问题时就分不清是内核错了还是投影错了。
先让内核在真实使用里跑对，再谈投影。
