## 1. 纠正

上一版把中间列收成「只跟主控说话」，审计变成右侧只读审查、没有输入。那是 CodeFleet/Cindy「一个伙伴」的壳，不是这套产品。

NaveHQ：Owner 能质询。35：审计是独立席。你要的是**能跟主控谈目标、跟审计问缺口、跟秘书要整理**——不是三个对等群聊，也不是只能跟一个人说。

市面里对的那一块改成：Cindy 的**多任务窗**（可并排、可把别的会话丢进输入当引用）；CodeFleet 的 **split**（最多并排，不当默认首页）。不借 AgentsRoom 网格、不借 2×2 瓷砖当家。

## 2. 一屏

```
┌──────────┬──────────────────────────────────────┬──────────┐
│ 左轨     │ 舞台条：主控 | 审计 | 秘书 | 施工 chip │ 图标轨   │
│ 项目     │──────────────────────────────────────│ Files    │
│ 房间     │                                      │ Git      │
│ 本段目标 │     当前角色的会话（全宽 thread）       │ Diff     │
│ （halt   │     可把另一角色窗撕到右侧并排          │          │
│  对话）  │                                      │          │
│          │──────────────────────────────────────│          │
│ 本机实例 │ composer：对当前聚焦席                 │          │
│          │ 状态条 · [对账]（只属于这段目标）        │          │
└──────────┴──────────────────────────────────────┴──────────┘
```

**左轨列的是目标（`conversationId`），不是席位。** 未验收置顶。点一项 = 进入这段目标。舞台条再选**这段里跟谁说话**。

| 角色 | 点舞台条 | composer | 写仓库 | 写对账栏③ | 验收 |
|---|---|---|---|---|---|
| 主控 | 谈目标、听派活 | 默认；无 `@` 的新目标也是它 | 计划可以，不当施工主体 | 否 | 否（按钮在 CONTROL） |
| 审计 | 质询缺口、问为什么 | 有，只读仓库 | 否 | 是（它自己的 RESPONSE，不是你代填） | 否 |
| 秘书 | 要摘要、提醒、人话复盘 | 有，只读仓库 | 否 | 否 | 否 |
| 施工 | 打开 Run dock / 插话 | 仅插话或 Steer，不当「开新目标」 | 是 | 否 | 否 |

没有秘书不挡闭环。没有审计则 `[对账]` 409 `NO_INDEPENDENT_AUDITOR`。

## 3. 一段目标，多个角色会话

同一 `conversationId`：

- **halt / 锚点 / 对账 / `acceptedAt`** 一份。
- **每个可会话角色一份 transcript**（已有 `GET /api/seat/:id`）。中间 thread 渲染的是「当前聚焦席 × 当前目标」的交集：Owner↔该席的话，加上这段里与该席有关的派出卡、对账卡。
- 切舞台条 = 换 `recipient`，**不** `POST /api/send` 开新窗口。
- 新目标 = 无聚焦或已验收后再发，才 `/api/send`。

Composer 对**舞台条当前位**。默认进房间时位在主控。不要自动点亮 chip。

`[对账]` / 验收 / 继续 / 改向永远作用在左轨这条目标上，不论你正看着审计还是秘书。跟审计说「这段过了」**不会**验收。

并排（Cindy 拖窗 / CodeFleet split）：允许主控 | 审计，或主控 | 秘书。最多两列，不当 2×2 工人墙。并排时只有一条 composer，属于**焦点列**。可把审计会话链贴进主控输入（引用，不是把审计变成主控）。

施工在跑：舞台条施工位呼吸；Run dock 显示此刻。点施工 = dock + 必要时插话，不把工人升成第三个规划会。

主控 `@builder` 之后 **composer 不转圈锁死**（Cindy：主会话不空等）。可继续对主控说，可插施工。

CONTROL 卡增加 **派出清单**（CodeFleet journal）：本段 `@` 过谁、在跑/已回/失败、一句任务。不是 kanban。

Diff 轨按 Conductor/Cindy：列出 hunk，可标记「看见了」；不在 UI 里改 git（房间仍是唯一 committer）。

实例/席位旁只读展示同厂商 `next_up` 额度（Claudexor），不当路由按钮。

## 4. 战场还在

主控 `@builder` 仍在**主控会话**里显示派出卡和 diff 摘要。切到审计时，thread 换成你与审计的问答，对账 CONTROL 钉在该列顶部（只读字段 + 若 `reportable` 则验收按钮仍在，避免切走主控就找不到收口）。

右侧图标轨：Files / Git / Diff。审计的「审查」不再独占右侧——审计是舞台条上的一等会话。Diff 仍是材料面。
