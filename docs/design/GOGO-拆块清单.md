# GOGO 拆块清单（全量）

把研究里全部要求拆成可施工的块。来源：`<local>\gogo-ui-research\2026-09-13` 的五份研究 + 覆盖清单（M01–M22、C01–C12、S01–S06、U01–U18、D01–D09）+ 改版总图 + 整合方案十五节 + 独立审阅 + 双模式方案（冻结部分单列）。
每块四段：**要什么**（带出处）、**现在有什么**（gogoke 与房间的真实文件，逐个核过）、**差什么**、**怎么算做到了**。

**"现在有什么"里的房间（`packages/room`）是参考实现，不是要接上的后端。** gogoke 与房间底层不是一个东西（Owner 2026-09-16）：那边的逻辑和接口形状可以照抄，事实一律要由 gogoke 自己产生。见《GOGO-统筹设计》第〇节。

冻结说明：Owner 2026-09-14 决定把双模式（通用生产、多格式成果）先剥离。本清单第 15 节单列它，其余各节只写软件线。

## 第一部分：主路径七样

### 1. 一件工作

**要什么。** 前台的稳定入口是"一件工作"，不是房间、席位、回合。内部派发、审计进程、每一轮都不该在侧栏长出平级入口。（主路径 §3；M01；C01；整合方案 §1.1 左栏"不放主控拆出的内部任务"）

**现在有什么。** `features/app/components/Sidebar.tsx` 工作区分组 + 对话列表；`ThreadRow.tsx` 带未读、置顶、搜索；`WorkspaceGroup.tsx` 可折叠。

**差什么。** 没有"工作"这个对象；行上没有归栏；同一件事的多条线会平铺成多行；没有"等我验收"的筛选。

**怎么算做到了。** 昨天那件今天一眼找回；一件工作无论跑了多少轮只占一行；选中与未读是两回事（C01）。

### 2. 一条主对话

**要什么。** 你只跟主控说话；席位的问题先交给主控，它自己答或派人答，定不了才问你。正文轻量，过程和依据按需展开。（五家研究 §8、D01；C02；M09）

**现在有什么。** `features/messages/`（约 3700 行）完整单 agent 消息流：推理折叠、工具行、流式渲染。

**差什么。** 没有主控与席位之分；席位提问现在直接渲染给你（`RequestUserInputMessage.tsx`）；没有"主控替你答掉了"的轻量说明行。

**怎么算做到了。** 界面任何位置都不会出现某席位直接对你说话；普通消息不套大卡（C02）。

### 3. 正在进行

**要什么。** 一块常驻编组：谁在做什么、做到哪、谁卡住。永远在主控输出最下方。跑着显示最近一个动作，收口后换成交回的第一句结论，失败显示问题加出路。过程默认折叠。（主路径 §9；五家研究 §7；呈现形态照 Aster `AgentGroup.tsx`，Owner 2026-09-16 指定）

**现在有什么。** `Messages.tsx` 的 `tool-group` 折叠组 + `tool-inline` 行（completed/processing/failed 三态样式齐）；`working-spinner`、`working-shimmer`、`turn-complete`。

**差什么。** 行上没有执行者；摘要是"几个工具调用"不是席位计数；没有分叉线（房间的 `branchId` 已有父子关系）；位置不固定在最下；没有"改动就绪／等主控处理／待核对"。

**怎么算做到了。** 一次派三个席位就是三条线；折起来只剩一行；席位带材料回来时它那行收口、父行计数变；整块永远在最后。

### 4. 要你定的一下

**要什么。** 只有两种配占你注意力：CLI 真实问题、房间真实闸门。问题要原文原选项，位置稳定，先选后提交（D02），收起不代答，提交状态不保存答案正文（D03）。权限请求走独立通道，保留上游操作、范围与原选项标识，不加"推荐允许"（C06）。闸门种类：low-progress / reconciliation / conversation-cost / daily-cost / owner-stop。

**现在有什么。** `RequestUserInputMessage.tsx`（多题排队、选项带说明、补充输入、统一提交）；`ApprovalToasts.tsx` 命令审批浮条。

**差什么。** 来源接的是 Codex app-server，不是房间 CLI_INPUT；问题在消息流里会被推走；权限浮条只有同意/拒绝；**闸门整类没有**。

**怎么算做到了。** 原题原选项一字不改；两席同题不串答（U05）；CLI 没有跳过选项时界面不自行补出（U06）；中文输入法按 Enter 不误发（U07）；到对账点停住，点"停"先显示"已请求停止"（U11）。

### 5. 成果

**要什么。** 成果入口显示名称、类型、**具体版本**和直接打开（C08）。查看器有"查看／反馈／版本对比"；进入反馈模式不触发被查看页面的提交动作（U09）。**批注位置是记录的一部分，不是发送时的当前选择**：每条批注有独立 ID 和不可变位置快照（C09；整合方案 §9.1）。查看器头部"下载原件"取的是当前所看版本，不暗换最新。

**现在有什么。** `features/files/`（文件树 + 预览气泡）、`features/git/`（45 个文件：diff 面板、diff 查看器、图片 diff、PR 摘要）。

**差什么。** 入口是仓库路径不是成果+版本；没有运行预览、没有指向反馈；diff 与"这一轮产生了什么"没有绑定。

**怎么算做到了。** 不报文件名能完成一次反馈；报告 v2 第一段写完保存、再点第三段，旧批注仍引用第一段（U08）；旧版本不被暗换。

### 6. 一眼看全

**要什么。** 同一批对象的不同投影：列表看得快，关系看得懂；布局不改变任务状态（M08；U15、U16）。归栏五态由事实推出，不手填。

**现在有什么。** gogoke：无。房间：`packages/room/public/work-canvas.js`（43 KB，节点、边、SVG 连线、五种状态）。

**差什么。** 全部。按 Owner 2026-09-16 决定，不做独立看板模块，而是"正在进行"那棵树收到第一层的样子；关系画布留作扩展点。

**怎么算做到了。** 收起来一眼扫出哪几件等你；就地展开不切页面；空白取消选中可达、不拖动也能操作（U15、U16）。

### 7. 侧边聊条与递话

**要什么。** 主动抓一个人问几句，共享当前工作上下文；只递选中的那一句，带出处；排队或插话；送达状态如实。闸门期只能跟只读的审计／秘书说话，它们不能改工作区、不能接力、不能动目标。（上下文研究 §3；主路径 §7；M07）

**现在有什么。** 房间后台齐全：`/api/conversations/:id/transfer`（来源校验、包一层出处、queue/interject、跨目标插话拒绝）、闩锁期只读旁聊、花费闸门；旧网页前端 `sidechatRepliesHtml`／`transferSidechat`／六种送达状态。gogoke：有右侧面板骨架（`PanelShell.tsx`、`PanelTabs.tsx`），没有第二条对话通道。

**差什么。** 右侧面板语义要换成"当前查看对象"并容纳一条对话；旁聊本身、两个递话按钮、送达状态文字，前端要新写；主对话要能标出"这条是你从旁聊递来的"并点回原处。

**怎么算做到了。** 问三句只递第三句；对账锁住时主对话发不出、侧边还能问只读席位；每条递话都有回执，未确认显示"待核对"。

## 第二部分：让它真能用的八块

### 8. 角色管理（项目里）与实例管理（设置里）

**要什么。** 按 Owner 2026-09-16：**角色管理放在项目里，实例管理放在设置里，两个面分开**，不糊成一个"团队与连接"。角色不绑 CLI——角色 → 席位 → 实例 → 进程四层解耦；同一实例服务不同项目的席位时项目级隔离照做。主控能在授权范围内自己拉席位、拉角色。账号、实例、席位、角色是四件事，界面要摆出真实绑定，而不是糊成一个"模型设置"。连接状态要分开：已保存 ≠ 已验证 ≠ 占用中 ≠ 需登录。账号提供调用身份，实例、原生历史、记忆各有范围。（设置研究 §3、§4；上下文研究 §3；S02、S03）

**现在有什么。** 房间：四种角色定死（`role-policy.ts`：主控／施工／审计／秘书，主控与施工可写工作区，审计与秘书只读）；建席位、改厂商、探测、绑实例、换实例、删席位接口齐全；账号与实例分开管；独立性按 provider family 判定。gogoke：`SettingsAgentsSection`、`SettingsEnvironmentsSection` 有 CLI 与环境配置。

**差什么。** gogoke 没有席位、没有角色、没有账号与实例的区分，也没有"这个目标的团队是谁"；两个管理面都还不存在；主控自主拉席位这条授权整个没有。

**怎么算做到了。** 你看得懂"连的是谁、用在哪"；换审计席时界面说明独立性会不会变；实例同一时刻只被一个席位占用这件事看得见；不自动做账号操作（S02）。

### 9. 输入与发送控制

**要什么。** 底部输入稳定，附件与收件人和任务同域，发送中不跳尺寸（C03）。收件人是紧凑菜单，角色与能力分开，切换保留各自草稿（C04）。默认排队；有匹配回合才显示插话；撤回只删未开始的；停止分"已请求停止"和"已停止"。（M03、M05；主路径 §4）

**现在有什么。** `Composer.tsx`、`ComposerQueue.tsx`（队列可编辑可删除）、`ComposerMetaBar.tsx`（模型、强度、协作模式）、`turn_interrupt`。

**差什么。** 收件人选的是模型不是席位；没有"发给谁"的角色与只读能力区分；撤回、插话没有接房间的语义。

**怎么算做到了。** 施工运行中排队再撤回：该任务未开始、原消息标已撤回、没有派发失败卡（U03）；回合结束边界点插话按实际归属处理、不跨目标（U04）。

### 10. 草稿与阅读位置

**要什么。** 两件工作各留各的草稿，来回切不丢文字、附件、收件人（U01）。新回复进来不重建输入控件、不清草稿、不抢阅读位置（M06）。

**现在有什么。** gogoke 有草稿保存；房间旧网页有按项目/工作/收件人分域的草稿实现可参考。

**差什么。** 没有按"工作 + 收件人"分域；成果批注草稿没有持久化。

**怎么算做到了。** U01 通过；收到新消息时正在打的字不动、阅读位置不跳。

### 11. 资料与已确认决定

**要什么。** 资料栏三段：**项目资料 / 已确认决定 / 本次引用**。条目显示名称、用途、出处，细节再展开路径与版本。核心边界：**可查阅 ≠ 已加入本次输入 ≠ 有实际读取证据**。已确认决定必须有 Owner 的原消息或动作、适用范围和版本；模型建议和草稿不能自动升级成决定。资料更新为 v4 时，正基于 v3 执行的任务保留 v3。（上下文研究 §2、§5；M15；整合方案 §7.1）

**现在有什么。** 房间有仓库文件读取与预览、重要文件本地置顶；gogoke 有文件树。

**差什么。** 三段结构、决定登记、"本次引用"那一行，全没有。

**怎么算做到了。** 删掉一条"本次引用"只影响还没发的输入，不假装删掉模型先前收到的内容；界面不因为文件在项目里就显示已读取。

### 12. 交接记录与团队抽屉

**要什么。** 团队抽屉回答"谁在做什么、拿到了什么、交回了什么"。只展示真实任务、运行和交接记录，不用轮数算百分比。交接至少带：目标、允许修改范围、禁止事项、引用版本、成功条件、该项目的必要 gate。生产者不能把自述升级为 Owner 确认。（整合方案 §4.3、§5；主路径 §7）

**现在有什么。** 房间的接力已经按这个做：交出去的是仓库引用（工作区、commit、改动文件），并明写"不要只依据下面这段话下判断"。

**差什么。** 前端没有任何呈现。

**怎么算做到了。** 展开任一席位能看到它接到的原文、核对的版本、交回的材料；主控结论与原始证据分层。

### 13. 交付清单与验收

**要什么。** "本轮交付"是一份看得见的清单：绑定本轮的精确版本集合，显示每项的审查状态。审查不通过时把整批发现集中列出并定位到各自成果与版本；修订回来对照旧集合显示改了哪几项；**Owner 在清单底部点一次确认**，这是对当前候选集合的原子核对，不是系统自动判定。确认之后旧集合保留历史，新一轮按新事实归栏，不继承旧完成。（整合方案 §4.4；M17；U13）

**现在有什么。** 房间有 halt / verify / acceptedAt 与对账闩锁；gogoke 什么都没有。

**怎么算做到了。** 审计通过后又改了被审代码，旧结论标明对应旧成果、不直接继续通过（U13）；确认前新版到达时旧集合不能确认。

### 14. 未读与提醒

**要什么。** "跑完了但你还没看"是独立状态，不是业务验收。区分"需要你关注"和"普通更新"。通知优先级来自真实请求与事件，不从模型措辞猜。正常执行保持安静；工具日志不逐条播报。（五家研究 Herdr 状态表；整合方案 §11；主路径 §9）

**现在有什么。** gogoke 有通知、托盘、`useAgentResponseRequiredNotifications`。

**差什么。** 没有"完成未看"这一层；没有需要关注与普通更新的分离。

**怎么算做到了。** 打开该目标才清除未看，不因筛选或悬停清除；需要你回答的事件才占注意力。

### 15. 断线、恢复与导出

**要什么。** 断线保留正文、草稿、当前成果和最后更新时间，发送结果未知单独标示；恢复后先读服务端的真实任务与回执，不自动重发。停止不回退文件。查看旧版不等于恢复；恢复只覆盖声明范围，并说明聊天、外部数据库、发布状态不随文件一起回退。导出成果与对外发布分开。（M21；主路径 §6；U10、U11、U12；整合方案 §11）

**现在有什么。** 房间有持久化与进程身份；gogoke 有更新与重连机制。

**差什么。** 送达未知的表达、重连核对、导出范围说明。

**怎么算做到了。** 服务器收到但浏览器丢回执时，重连核对原任务、不重复派发（U10）；代码回退但外部数据库改过时，不宣称一起恢复（U12）。

### 16. 设置六组、能力目录与花费

**要什么。** 六组：界面与输入 / 连接与模型 / 项目与团队 / 工具与扩展 / 数据与隐私 / 诊断与关于。每行显示当前值、默认来源与覆盖、作用范围、生效时机；简单偏好即时保存，多字段绑定显式保存且失败保稿。能力按"能取得原件 / 能预览 / 能定位反馈 / 能生成编辑 / 能专业核查"分别记录——**检测到可执行文件不等于能用**，Controller 能调用某个 skill 不等于席位有同一能力。花费：未知标未知，调用次数不是钱，不推断余额。（设置研究 §4；S01–S06；M18、M19、M20；U14）

**现在有什么。** gogoke 有 16 个设置分区（显示、输入、快捷键、听写、代理、环境、项目、Git、服务、关于、调试等）。

**差什么。** 没有按作用范围和生效时机组织；没有能力目录；没有花费表达。

**怎么算做到了。** 设置搜索能按功能和别名定位到行；保存失败保留编辑内容；未生效不冒称已切换；Provider 没返回用量时显示未知而不是零（U14）。

### 17. 首次使用与可达性

**要什么。** 第一次打开是项目空态和同一个底部输入框，没有预置成果、团队或"已审查"。引导出现在真正需要的地方：选文件夹 → 连一个助手（列出真实发现的连接与状态，点"使用此连接"才绑定）→ 最小团队（一个主控就能先讨论）→ 发第一条请求 → 看第一条回执。未发现连接时保留文件夹、项目名和草稿，发送旁写"先连接一个助手"。可达性：窄窗、键盘可达、200% 缩放下答案与发送不被遮挡、不依赖拖动、焦点可见、触屏命中区。（M22、M02；整合方案 §12.1；U16、U17、U18；C12）

**现在有什么。** gogoke 有首启流程和空态；有 `useUiScaleShortcuts`；有移动端布局。

**差什么。** 空态不是从"空文件夹 + 一个主控"起步；没有连接状态的如实表达；可达性未验。

**怎么算做到了。** **U18 必须由真实非程序员完成**，并能说出"改哪里、发给谁、是否开始、结果在哪"；agent 自动点击不算数。

### 18. 项目与工作边界

**要什么。** 切项目先关掉运行中的席位再换数据根，正在执行时限制切换；默认不引入别的项目的资料、记忆、目录或权限；显式引用要带出处。"侧栏换了项目名称"不算隔离证据。模式属于具体工作、不属于整个项目，也不由文件后缀推断。（上下文研究 §3、§4；整合方案 §8）

**现在有什么。** 房间：`server.ts:2159–2264`、`projects.ts:237` 已经这么做。gogoke：只有工作区概念。

**差什么。** 前端对这些边界没有任何表达。

**怎么算做到了。** 同名文件、同席位在切项目后不串输入、不串完成记录、不串草稿。

### 19. 独立审计与会话隔离

**要什么。** 正式审计必须建立无施工续接的运行上下文，并核对实际进程、thread、任务、版本与磁盘记忆继承；**没有证据就标"独立性未确认"**，不能只凭角色名、模型不同或 purpose 字段声称独立。日常旁聊咨询可以续接，正式审计不行。（上下文研究 §3、§4；M16；整合方案 §7.2）

**现在有什么。** 房间按席位复用会话（`ensureSeat`），审计席只按 provider family 选择；独立性由房间记录、不采信审计席自述——这一半是对的。

**差什么。** fresh 会话没有运行时保证。**这是前后台一起的缺口**：界面上出现"独立审计"之前，底下得先真独立。

**怎么算做到了。** 每次正式审计有新建原生会话的证据；拿不到证据时界面显示"独立性未确认"而不是通过。

9. 不重造 Office／图像／剪辑编辑器；查看与反馈仍在设计范围内。
