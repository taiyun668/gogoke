## 一、不可回退的十条

1. **席位向主控负责，你只是监督查看。** 席位卡住、失败、重试由主控处置；界面如实显示，不变成你的待办。
2. **只有 CLI 的真实问题能占用你。** 其余一律安静。闸门（对账／花费／低进展）首版不做。
3. **施工抓不到。** 旁聊只对秘书长和本项目审计开；施工的事一律走主控。
4. **正文里的 `@` 只是文本**，不触发派工。模型不能自封 Owner 权限。
5. **角色不绑 CLI。** 角色 → 席位 → 实例 → 进程，四层解耦。
6. **项目级隔离照做。** 同一个实例服务不同项目的席位，资料、记忆、执行权一概不共享。但**项目隔离 ≠ 每个项目有独立物理容量**（老 GOGO `21`）——共享稀缺资源要先拿到原子、可恢复的许可。
7. **不存在「半支持」**（老 GOGO `31` §7.1）。一个厂商必须配置层与运行层都做完、隔离过反向验收才进注册表；注册表条目 `seat` 字段必填。但**第一屏要如实说支持范围**——不出现在功能里，和不告诉他，是两回事。
8. **不动 gogoke 现有 UI，只加。** 中顶、设置十六节、面板三个 tab 一律保留。
9. **不知道就写不知道。** `待核对`（送达没回执）、`未知`（用量没返回）、`已请求停止`（还没收到停止事实）。**本地累计用量不冒充官方剩余额度**（V0.12 §5.3）。
10. **产品不替模型出题，也不替你做决定。** 暂停、开工、把改动并进来都是动作，不是系统生成的选择题。**没有验收动作。**

11. **设计与计划是两类成果，不是强制阶段**（上下文研究 §二）。某个项目可以要求设计先审、计划再审，另一个项目一句话说清就开工；由主控按该项目已定的要求组织，产品不把「设计 → 计划 → 施工」固化成所有项目的阶段。

**首版只做代码生产。** 长期愿景是说一句「做一个生产级系统」就一路跑到交付；首版不按这个尺度设计，但**任何一处都不得假设 Owner 一直看着**。

## 二、对象模型

```
秘书长                        ← 全局，左栏独一个位置；跨项目，服务 Owner 本人

项目（工作区）── 资料 · 已确认决定 · 角色与席位名册 · 文件
 ├ 主控 / 审计                ← 固定绑定，各一个；绑在项目上，不绑在对话上
 ├ 对话（= 一件工作，多条；左栏点开的就是它）
 │    ├ 回合 ── 席位任务 ── 动作 ── 材料（commit / 改动文件）
 │    └ 交付集合              （本轮的精确版本集合 + 审查结论 + 改动落在哪）
 └ 旁聊                       ← 右侧面板里；只找秘书长或本项目审计

设置 ── 实例（账号 + CLI 安装 + 登录），跨项目共用
```

**定死的：**

- **一条对话就是一件工作。** 左栏点开的是对话，不是项目——跟 Codex、Claude Code 一样。一个项目下多条对话**都由同一个主控答**。
- **主控和审计绑在项目上。** 目标不跨项目。
- **不是「一席一实例」**（Owner 2026-09-17）。老 GOGO `31` §2.1 那条**不适用于 gogoke**——它与「同一个实例可以服务不同项目的席位」直接打架。
  **一个实例可以服务多个席位**，靠隔离与占用协调保证互不干扰；**能不能同时服务几个，取决于那家 CLI 实测的并发能力，不由产品规定**（ADR-0006：按证据声明能力）。
- **主控在授权范围内自己拉席位、拉角色**，不必回来问 Owner。它不能自增权限、不能删监督者、不能改他人的审计记录。
- **秘书长是全局对象**，可以被拉进某个项目的旁聊，但记忆与归属仍在全局。
- **材料属于回合**，不属于对话。交接交的是材料引用，不是上一位的转述。
- **席位怎么干活由主控定夺**——直接改工作区，还是开分支／worktree 交回来，**产品不定死**。产品只如实写改动落在哪。
- **每次执行绑一个精确、可审计、不可静默替换的目标**（老 GOGO `19`）——不自动换号、换模型、换 Harness。
- **ID**：项目沿用 gogoke 工作区登记，对话沿用 gogoke 现有 thread id。不引入 `roomId`。
- **切走不等于停下。** 切到别的对话或项目，原来那条的草稿和正在跑的活全部保留。
- **关窗 ≠ 退出**（老 GOGO `20`、V0.12 §2.3）：关侧栏只关视图，关桌面只断 UI，真正退出全部运行另走停止流程。桌面窗口是客户端，不是生命周期所有者。

## 三、词汇（对外只用这一套）

| 用这个 | 意思 | 不要用 |
|---|---|---|
| 对话（= 一件工作） | 你要的一个结果，左栏点开的那一条 | 房间、thread、任务、目标 |
| 项目（工作区） | 一个主控和一个审计固定服务的那一摊 | 空间、workspace（对外） |
| 秘书长 | 全局那一位，服务你本人 | 助理、管家 |
| 主控 | 组织这件事的那一个 | leader、orchestrator |
| 审计 | 本项目那一位独立核对的 | reviewer（对外） |
| 席位 | 项目里担某个角色的一位，**改造后 = 一个独立 CLI 进程 + 它自己的会话**（§8.5） | agent、worker、成员实例、线程 |
| 角色 | 主控／审计／施工／秘书长 | agent 类型、模型 |
| 实例 | 一个账号加一份 CLI 安装 | 模型、厂商、provider |
| 回合 | 一位席位的一次执行 | turn、迭代 |
| 材料 | 这一轮真留在仓库里的东西 | 产出、结果 |
| 状态字 | 折起来那一行和左栏对话行上的那个词 | 归栏、阶段、进度、看板列 |
| 旁聊 · 递话 | 侧边问秘书长或本项目审计；把选中的一句给主控 | 私聊、转发 |
| 右侧面板 | 现有 Git／Files／Prompts 之外再加旁聊／角色管理 | 侧边窗口、抽屉、drawer |

**这几个「完成」永不混用（措辞规矩，不是几个按钮）：**
`回合结束`（一位席位跑完了）→ `改动就绪`（材料交回了）→ 改动落在哪（`已在你的工作区` 或 `还在 xxx 分支`）。
界面上禁止出现光秃秃的「完成」「通过」，也禁止出现「待验收」这种等你盖章的说法。

## 四、折起来那一行写什么（从上往下命中首条）

「正在进行」归一折成一行之后，那一行右边写一个状态字。**左栏那条对话行显示的就是同一个字。没有五列，没有看板，没有第二个投影。**

这个字是三样真事实的只读投影，不新增状态机：**有没有待答的 `userInput`**（gogoke 已有 `pendingUserInputKeys`）、**有没有在跑的回合**（已有）、**改动交回了没有、落在哪**（要后端补）。

| 优先 | 条件 | 状态字 | 这一行还写什么 |
|---:|---|---|---|
| 1 | CLI 有真实问题在等你答 | 待处理 | 原题来自哪一位、哪一回合 |
| 2 | 本轮有排队或运行记录 | 在运行 | 真实动作：排队中 / 制作中 / 审计中 |
| 3 | 材料齐、检查通过、无待答问题 | 改动就绪 | 落在哪：「N 个 commit · 已在你的工作区」或「N 个 commit · 在 `feat/x` 上」 |
| 4 | 其余 | 不写字 | 没活动就是没活动，不用一个词去描述它 |

**「待处理」只有一个来源：CLI 弹出来的真实问题**（Owner 2026-09-17）。这跟 §6「只有一种东西可以主动占用你」是同一条规则的两个面——**能占用你的只有它，能让行上写「待处理」的也只有它。**

**改动还在分支上不算「待处理」。** 活已经干完了，改动就在那儿——那是**改动就绪**，只是落点在分支上。
「把它并进来」是那一行上**可以做的一个动作**，不是一个在等你的状态：你看一眼，想并就说一句。

**状态字挂在对话上，不挂在项目上。** 工作区那一行显示它下面最要紧的那条（按上表优先级）。

**状态字只出现在归一折起来那一行，席位那几行一个都没有。** 席位向主控负责，你只是看得见——席位行跑着写它最近做了什么，收口写它交回的第一句结论。

**「完成未看」是另一维**，不占状态字：**打开那条对话就清**，不因筛选或悬停清除。这就是「一眼看全」——哪条你还没看过。

## 五、窗口职责（只说加什么、不动什么）

| 位置 | 第一眼 | 你主动展开 | 永远不放 |
|---|---|---|---|
| 左栏 | **秘书长（独一个位置）**、项目工作区；工作区下面是它的对话，**每行带状态字**；搜索、新建 | 项目资料、文件、归档、「只看待处理」 | 主控拆出的内部任务、每个审计进程、阶段横条 |
| 中顶 | **保留现有**：工作区名、分支、worktree 信息弹层（改名／upstream／复制命令）；**加**当前对话名与开面板的按钮 | 现有弹层照旧 | 常驻的「设计中／施工中」标签、对话／看板切换 |
| 中正文 | 你的原话、主控的结论、成果入口（点开到 Git／Files） | 本轮过程、原始依据、更多操作 | 每条消息一个大卡、堆栈、反复确认卡 |
| 中正文末尾 | **正在进行**（永远最后一块）；收起来就是第一层，发散、收敛、归一都在这里 | 某席位的动作、材料、交接原文 | 把它插在历史中间、另开一个看板页 |
| 中底 | 输入、**收件人固定是本项目主控**、附件与「本次引用」、发送 | 发送方式、真实待答问题 | 一排要你管理的成员 chip、阶段向导 |
| 右侧面板 | **保留现有三个 tab**：Git / Files / Prompts；**只加两个**：旁聊、角色管理 | 版本、反馈、固定查看 | 悄悄改变主输入的收件人、施工席位的旁聊入口、**另开一个「成果」tab** |
| 设置 | **保留现有十六节**；**加**实例管理一节 | 单个实例的运行配置与故障 | 项目里的角色与席位（那在右侧面板里） |

**资料分三段，但不另开栏**（拆块 11、上下文 §五、M15）：**项目资料 / 已确认决定 / 本次引用**。
项目资料就是左栏的文件与 Files tab；**本次引用**在输入框上面那一行（§13）；**已确认决定**要有 Owner 的原消息或动作、适用范围和版本——**模型的建议和草稿不能自动升级成决定**。
资料更新到 v4 时，正基于 v3 执行的任务**保留 v3**。界面不因为文件在项目里就显示「已读取」。

**项目资料不另开一栏。** 设计稿、规范、约束就是左栏按项目排下来的文件与面板的 Files tab。
唯一要守的：**不要把项目资料塞进全局设置那种大表单里**（上下文 §五）。

**项目设置与全局设置分工**（上下文 §五）：项目文件夹、允许引用的资料目录、项目规则来源 → 项目侧（面板的角色管理 tab 一起）；
跨项目的语言偏好、账号、运行实例 → 设置侧。**不在全局设置里存某个项目的业务决定。**

**那张工作树不能只能靠拖**（主路径 §9、U15／U16，W3C 硬要求）：能点、能用键盘、能切成列表、能一键适应画布、分栏能点着调宽。仅提供键盘方式也不满足这条。

**中底的收件人是「改」不是「加」。** gogoke 现在的 composer 选的是模型；改成固定收本项目主控，是替换掉一个现有语义——**本表唯一一处「改」，其余都是加**。

**不加「成果」tab。** 首版只做代码生产，成果就是 Git 和 Files 里那些东西。
「指着说这里不对」现在已经跑得通——diff 里选几行，`buildPullRequestReviewPrompt` 把选中的行拼成提示，`sendUserMessageToThread` 发出去。缺的只有两处小改：**收件人换成本项目主控**（现在发给 `reviewThreadId`），**加一个「这里不对」的自由文本意图**（现在只有四个预设审查意图）。

**没有验收页，也没有验收按钮。** 归一折起来那一行如实写改动落在哪；落点在分支上时行上带一个「并进来」的动作，**但不把它算成在等你**。

**不做独立看板，也不做归栏五列。** 这两件事都由「正在进行」承担——展开是发散的几条线，归一折起来就是带状态字的那一行，左栏显示同一个字。

**切项目的边界**（拆块 18、上下文 §四）：默认不引入别的项目的资料、记忆、目录或权限，显式引用要带出处。
要保证的是**不串**：同名文件、同席位在切项目后不串输入、不串完成记录、不串草稿。

**「先关掉运行中的席位再换数据根」是房间的实现约束，不是本设计的规矩**——它因为要换 `dataRoot` 才必须先停。
gogoke 这边**切对话、切项目都不停任何东西**（§2）；如果某个实现做不到「不停也不串」，**要如实告诉你「切过去会停掉这边正在跑的活」，不许默默停掉**。
**「侧栏换了项目名称」不算隔离证据。** 算做到的标准：同名文件、同席位在切项目后不串输入、不串完成记录、不串草稿。
另注（上下文 §四实测）：**UI 里的边界比原生会话的隔离边界更细**——实例独占不等于项目独占，HOME 隔离不等于会话隔离，**不能在界面上承诺「新目标就是干净上下文」**。

**切对话 / 切项目 = 换现场，不换状态。**

## 六、注意力规则

**只有一种东西可以主动占用你：CLI 的真实问题。** 其余一律安静。

**状态字不是打断。** §4 那个「待处理」是**行上的一个词**，它让你扫一眼知道哪条有事——**不弹窗、不提醒、不抢焦点**。

| 事件 | 表现 |
|---|---|
| 席位开始 / 结束一个回合 | 正在进行里的一行变化，不提醒 |
| 工具动作 | 折叠在席位行里，不提醒 |
| 席位有问题 / 卡住 / 失败 | 交给主控处置；界面如实显示，不提醒、不变成你的待办 |
| 主控要你定 | 就是 `userInput` 卡，固定位置，挂主控名下 |
| 材料交回 | 那一行收口，父行计数变；不提醒 |
| 一件事变成改动就绪 | 左栏行上亮「完成未看」；只在你离开那条对话时通知 |
| 断线 / 送达未知 | 就地标注，不弹窗，不自动重发；**显示最近已知状态和时间，不乐观显示「仍正常」** |

**你按下去的那几个动作，必须如实回话**（主路径 §4／§6）：

| 你做了什么 | 必须如实显示 | 不许发生 |
|---|---|---|
| 撤回一条还没开始的消息 | 原消息标 **`已撤回`** | **弹「派发失败」**——撤回不是失败；已经开始了就说撤不回来，不能假装撤成功 |
| 插话正好撞上回合结束 | 告诉你「这一轮已经结束」 | 偷偷转投下一轮或别的席位 |
| 点停止 | 分两种：**停这一轮** / **停这件事**；先写「已请求停止」，收到事实才写「已停止」 | 把「已请求」画成「已停止」；自动把已改的文件退回去；逼你填停止理由 |
| 看进度 | 有真实步骤显示步骤；没有就显示正在做什么 + 最后一条可信更新 | **拿轮数或「进程还活着」算出一个完成百分比** |

**问题出现时不抢焦点、不冲掉你正在打的字。** 主窗只有主控会问你；侧窗是你主动开的，两边各有各的 composer 与草稿——不做「待答清单」那一套。

**敏感答案不进公共 timeline、通知或普通日志**（V0.12 §9.2）。需要密码、token、验证码的场景**优先跳官方登录**；通用问答工具不得请求或收集可复用凭据。

## 七、事件到界面

**接线的依据是 `SeatEvent`，不是 Codex 的 `ConversationItem`。**

改造后是 CLI 派活给 CLI、五家并存（§8.5），各家协议不同（Codex app-server / Claude stream-json / Grok·Gemini·agy 的 ACP / OpenCode 待查）。
**归一层已经有了**：`packages/seat-runtime/src/seat.ts` 的 `Seat` 接口与 `SeatEvent` 联合类型，**厂商中立**。
gogoke 的 `ConversationItem` 是**渲染形状**——它由归一事件喂，不是接线的合同。

| `SeatEvent`（归一） | 界面 | 规矩 |
|---|---|---|
| `turn-started` | 那条线开始滚 | — |
| `assistant-delta` | 主控回复的正文流 / 席位行的最近一句 | 流式不抢焦点、不强制滚动 |
| `tool-activity`（`started` / `progress` / `output` / `completed`） | 席位行里折叠的工具动作 | 跑着写最近一个动作；不提醒；过程默认折叠 |
| `turn-completed`（带 `status`） | 那条线收口 | 收口后写**它交回的第一句结论**，不写状态词 |
| `cli-input-requested` | **唯一**的「要你定」卡 | 原题原选项，先选后提交，收起不代答。**上游没给跳过就不许造一个** |
| `cli-input-resolved`（`answered` / `cancelled` / `unknown`） | 卡的两维状态 | `unknown` 如实写 `待核对`；`response_fact` 与 `execution_control` 不许互相覆盖 |
| `delivery-received`（带 `evidence`） | 就地送达标注 | 「已登记」只等于第一步；没回执写 `待核对` |
| `error`（带 `willRetry`） | 安静的说明行 | 不弹窗；`willRetry` 如实显示，不自动重发已可能执行的动作 |
| 派活与发散结构 | 「正在进行」的几条线 | **来源换成宿主自己的 CLI→CLI 派活**；父子关系来自派出去的那一组，不另立分叉标识。现有 `collabToolCall` 的**渲染可复用，来源要换掉** |
| 材料（commit + 改动文件） | 席位行展开 | `tool.changes[]` 有路径与 diff，**缺 SHA**——回合↔commit 的归属要宿主补 |
| 权限请求 | 走 gogoke 现有的 `ApprovalToasts`，不另造 | 原始选项的语义不许改写——`allow_once` 与 `allow_always` 是两回事，不能把后者缩窄或扩大成项目权限 |

**`Seat` 接口里已经写死了两条与本设计同向的规矩**，接线时照着用、不要另写一套：

- `interject(expectedTurnId, text)` —— 注释原文：**必须拒绝空闲或过期的回合，而不是去猜**。这正是 §6「插话撞上回合结束要返回事实，不能偷偷转投下一个」。
- `answerCliInput(expected, answers)` —— 注释原文：**在厂商原本的请求通道上回答；绝不开启或插入一个回合**。这正是「原题原通道、收起不代答」。

房间的 `NOTE / RESPONSE / ACTIVITY / SYSTEM_STATUS / CONTROL / CLI_INPUT` 那套词**一个都不用**。

## 八、席位、角色、实例、厂商

### 8.1 四层解耦

**角色**（主控／审计／施工／秘书长）→ **席位**（项目里担这个角色的一位）→ **实例**（一个账号加一份 CLI 安装）→ **进程**。

现成可搬：`packages/room/src/role-policy.ts`（26 行：四个角色的中英别名、歧义判 null、`defaultAccessForRole` —— 主控与施工可写工作区，审计与秘书只读）。

### 8.2 厂商准入：不存在「半支持」

沿用老 GOGO `31-product-design.md` §7.1：**配置层与运行层都做完、隔离过反向验收，才进注册表**；条目 `seat` 字段必填，没适配器加不进来。第一屏如实说支持范围。

**上架一家的九步**（同文 §7.4）：①核实分发方式 ②手动跑状态命令的两种情形 ③判据 + 双向用例 ④实测隔离变量 ⑤空目录反向验收 ⑥查跨实例共享与能放宽沙箱的环境变量 ⑦写适配器 ⑧能力边界映射成启动参数 + 反向用例 ⑨席位启停与流式测试。

**从 `31` 取来的一条，带一个已知反对意见**（`docs/audit/2026-08-23-product-design-audit.md`，2026-08-23 对 `31` 的双身份审计）。
那份审计整体属 GOGO PARTY 时期、针对房间的实现，**不整片适用于 gogoke**；但下面这条是**因为我们取了对应条款才跟过来的**，要处置：

| 取来的条款 | 跟过来的反对意见 |
|---|---|
| §7.1 不存在半支持 | 用户手上**有第六家的账号**（比如 Gemini），产品当他没有账号、让他"再去开通一个"——他会直接关掉。**规则本身对，但要有一句如实的话**：说清现在支持哪几家、他那家在不在路上 |

其余条目（装 Node、npm 实时输出、无窗口 OAuth、免费状态命令、本机 CLI 与自建实例的边界）针对的是房间的安装与登录实现，**gogoke 没有那套，不并入**。
原本还有一条打在「一席一实例」上（加席位要再登一次）——**那条规则本身已被 Owner 判为不适用于 gogoke**，反对意见随之作废。

### 8.3 首版五家的实际状态（2026-09-17 逐个核过本机）

| CLI | 本机版本 | 适配 | 通道 |
|---|---|---|---|
| Codex | `0.149.0` | **已有** `PersistentCodexSeat` | `codex app-server --stdio` |
| Claude Code | `2.1.196` | **已有** `PersistentClaudeSeat` | `claude -p --input-format stream-json --output-format stream-json --verbose` |
| Grok Build | `1.0.30` | **已有** `PersistentGrokSeat` | `grok agent`，ACP stdio |
| OpenCode | `1.17.18` | **要写**（老 GOGO §7.3 已列为候选 `opencode-ai`） | 待查；注意它污染过全局 `~/.local/share/opencode` 与 `~/.config/opencode` |
| Antigravity | IDE `1.107.0`；无头 CLI 是 **`agy`，本机未装** | **要写；若确为一次一进程，只能当审计／检查那种一次性席位，当不了主控与施工** | agy，事件流与 ACP 同形 |

**三家的垫片形状都不一样**（实测记录在 `docs/audit/2026-08-24-first-run-known-unverified.md`；那份属 GOGO PARTY 时期，但**这是 Windows 上认二进制的事实，适配层照样要面对**）：
**Claude 是 `.exe`，Codex 是 `.js`，Grok 是无扩展名跳板。** 干净机首次引导当时**只走通了 Grok**——**不能从一家外推到另一家**。
开发机上有 `grok.exe`，所以「只有 `grok.cmd`、没有 exe」那条真实 spawn 路径当时没被测试强制覆盖。五家各自的垫片解析要逐家实测（§8.2 九步的第 ①⑨ 步）。

**三家已有**：`packages/seat-runtime`，4987 行，零运行时依赖，不 import 房间，带隔离测试、关闭测试和两个 fake 一致性件。`detectProviders()` 用 `where`/`which` 探测——可用性是探出来的，不是写死的。

**适配器可以抽成通用的**（老 GOGO `32-gemini-adaptation.md` 实测）：Gemini `--acp` 的握手形状与 Grok **完全一致**，包括 `authMethods` 数组（`PersistentGrokSeat` 的 `selectAuthMethod` 正是读它）。
所以路线是**把 grok-acp 抽成通用 ACP 适配器 + 每家一份参数与认证偏好**，不是每家从零写。Antigravity 的 agy 事件流也与 ACP 同形，大概率同路。

**探测的两条硬规矩**（同文档）：
- **`--help` 才是权威，不是官方文档。** Gemini 官方文档只提 `--output-format stream-json`、没提 `--acp`，照文档做会得出「只能一次性调用、做不了持久席位」的**错误结论**。
  → **这条直接适用于 agy**：本机没装，下面那条「一次一个进程」来自 AionUi 的源码注释，**是它的集成选择，未必是 agy 的能力上限**。装上跑 `agy --help` 之前不下定论。
- **只有否定用例就写判据是不允许的**（INV-PROBE-2）。必须同时观测到已登录与未登录两种输出，否则 `/Logged in/i` 会匹配上 `Not logged in`。
- **探测必须始终带隔离 HOME**，跑默认 HOME 可能挂在那里等输入。

**Antigravity 直接撞 §7.1**：agy 是一次调用一个进程（AionUi 源码注释原话：agy is a direct-CLI integration, one process per turn），**中途插话纠偏不可能、上下文不累积**。所以它**只能当一次性席位**（跑一轮审计或检查），**当不了主控**。要么按这个能力边界做一份完整适配器，要么按「不存在半支持」根本不出现。

**实测状态**：`adapter-spike/01-capability-evidence.md` 测的是 Codex `0.147.0` 与 Grok `1.0.0`，都已过期；Claude Code、OpenCode、Antigravity 零实测。`instances.ts` 的 `InstanceProvider` 现在是 `claude | codex | grok`，要扩。

### 8.4 实例与安装

现成可搬：`instances.ts`（489，`InstanceStore`、凭据路径）、`accounts.ts`（1214，多账号）、`install.ts`（1045，安装与探测）、`onboard.ts`（367，首次使用）。

产品裁决沿用老 GOGO `31` §5、§6：产品自己装（先 Node 再 CLI）、装失败不阻塞但不能让人以为成了、**升级永远由人点**、装在别处的 CLI 也认、**不显示剩余额度**。

**故障四分**（V0.12 §5.3）：网络未知／登录过期／并发不足／额度耗尽，分别归因。换号期间锁配置，先停靠正在用的绑定，已排队的执行等待明确重绑定，不悄悄换身份。**不复制、不解析、不自行刷新 token。****不靠邮箱建立账号身份或额度共享关系**；**不能要求你再买一个账号来掩盖实现缺口**。

**设置每一行要说清四件事**（设置研究 §2、M18）：**管到哪**（应用／此设备／项目／任务／CLI 全局）、**什么时候生效**（立即／下次发送／新任务／重启后）、**默认从哪来**，以及——**存下的值和当前真正生效的值不一样时，要同时说**。

**不支持的能力不许画成能打开的开关。** 能力四分：支持／不支持／尚未读取／失败。连接四分：已保存／已验证／占用中／需登录，**不能混用**。

**保存失败保留你填的内容**；不能弹个「保存成功」就当它生效了。**删除、断开、公开发布这类危险操作与主题字号分开放**，不用同一套轻率交互。

**首次使用不许自作主张**（主路径 §9、M22）：不能为了降低门槛就**未经授权自动绑定、登录或发测试消息**。先让你看到一件示例工作、一段对话和一个成果；真要用到某项能力时再说明需要连什么。

**用量要如实，且不占主位**（主路径 §8、M20）：金额、token 用量、订阅额度、预算限制都**保留来源与范围**；CLI 没报就标 `未知`，**不显示零花费，也不推断余额**；**估算不能伪装成实付金额**。收件人菜单给到够用的模型／实例信息即可，**详细用量放到工作或实例详情，不让主输入区堆满技术指标**。

**首次使用的顺序**（拆块 17、31 §4、M22）：第一次打开是**项目空态和同一个底部输入框**，没有预置成果、团队或「已审查」。
引导出现在真正需要的地方：选文件夹 → 连一个助手（**列出真实发现的连接与状态，点「使用此连接」才绑定**）→ 最小团队（一个主控就能先讨论）→ 发第一条请求 → 看第一条回执。
**未发现连接时保留文件夹、项目名和草稿**，发送旁写「先连接一个助手」。**U18 必须由真实非程序员完成**，能说出「改哪里、发给谁、是否开始、结果在哪」；agent 自动点击不算数。

**执行配置在首次外部调用前冻结**（V0.12 §6.3）：实例身份版本、运行配置、Harness／binary／适配器、模型与参数、工具集合摘要、范围、规则快照、工作区引用、预算。
设置页改了**只影响新执行**；在途要改走显式重新绑定。**不把未来的配置写进过去的记录。**

### 8.5 会话管理（**整件事的骨架**）

**改造之后，主控派活不是 Codex 的 sub-agent，是 CLI 派活给 CLI**（Owner 2026-09-17）——两个独立进程、两份独立会话。
**所以隔离不是靠某家厂商的子 agent 语义，是靠会话怎么管。** 这一节是骨架，前面所有隔离条款都落在它上面。

**一、一个席位 = 一个 CLI 进程 + 它自己的一份会话。** 进程之间不共享会话，`credentialHome` 各自独立（`seat-runtime` 已经这么做）。

**二、会话里装什么，是建的时候决定的，不是事后过滤的。**

| 席位 | 它的会话里装什么 | 绝不装 |
|---|---|---|
| 主控 | 你和它的对话、项目资料引用、已确认决定 | 别的项目的任何东西 |
| 施工 | **只有主控构造的那个任务包**：目标、允许改的范围、禁止事项、资料引用、成功条件 | **你和主控的对话**、别的施工的会话、整段历史 |
| 审计（主控委托的正式审查） | 任务标准 + 被审的那个精确版本 + 本次获准材料 | 施工的会话、你的私聊、上一次审查的结论 |
| 审计（你在侧窗问的） | 冻结的可观察主控上下文（§9.2 的一致读点） | 不回流主控，除非你递 |
| 秘书长 | 全局私有 | 不因为选了项目就改归项目 |

**三、派活这条路上不经过主对话。** 主控通过工具调用把任务包交给宿主，宿主起一个（或续一个）施工席位的进程，**把任务包作为它那一轮的输入送进去**。你和主控说的话不走这条路。

**四、什么时候能续、什么时候必须新建：**

| 场景 | 规矩 |
|---|---|
| 主控 | 续。你要能接着上次说，它得记得 |
| 施工 | 可以续（它要累积这件事的上下文），但**换一件工作就换一份会话** |
| 正式审计 | **必须新建干净会话。** 老 GOGO 的 `ensureSeat` 按席位复用进程与会话——**那条路不能照抄**，这就是第 19 块那个缺口的本质 |
| 你侧窗问的审计 | 可以续（日常咨询），但**和上面那份正式审查是两份**（§9.1 分室） |

**五、会话身份要能查，模式要如实写。** 这一轮跑在哪份会话、它之前装过什么、是新建的还是续的——都要记，界面按需能看到。
续接模式沿用老 GOGO `06-context-session-governance.md` §5.2 已命名的三种：`原生续接` / `原生分叉` / `冷重建`。**不许把冷重建说成续接。**

**六、跨项目：同一个实例可以服务不同项目的席位，但会话不跨项目复用。** 实例独占不等于项目独占，家目录隔离不等于会话隔离。

**七、这一整节必须实测，不能推定。** 办法：**在主对话里说一句只在那里出现过的话，然后去问施工席位。它答得上来，就是没隔离。**
五家各测一遍（§8.2 九步的第 ④⑤ 步）。**测出来之前，界面上不许写「施工看不到」**——按 §1.9，不知道就写不知道。

### 8.6 容量

**项目隔离 ≠ 独立物理容量**（老 GOGO `21`）：共享稀缺资源要先拿到原子、可恢复的许可。

**同一实例能不能同时服务几个席位，要实测。** 各家 CLI 对同账号并发的支持不同（`adapter-spike/01-capability-evidence.md` 里 Codex 与 Grok 的隔离配置行为就不一样），按 §8.2 九步的第 ⑥ 步「查跨实例共享与能放宽沙箱的环境变量」逐家量，**不假设、不写死**。

**以下两条是后端规矩，不出现在界面上：** 容量 ≥2 且预算允许时保留 1 个活动槽位给直接交互与主控控制（容量为 1 时明说不能同时推理）；主控登记等待子任务后结束当前回合，让出活动容量。

## 九、旁聊与递话

### 9.1 分室（收 V0.12 §4.4）

审计是**一个职责身份**，但 **Owner 私聊与主控委托的审查用不同逻辑会话、不同原生历史、不同可见域、不同缓存键**。

私聊只能回 Owner；公开审查只拿本次获准材料；两边不自动互相摘要。秘书长的记忆属于全局私有，不因为选了项目就改归项目。

**施工看不到你和主控的对话**（Owner 2026-09-17）。这是分室的第二半，和审计那一半同等硬：

- **施工拿到的是主控构造的任务包**——目标、允许修改的范围、禁止事项、相关资料的引用、成功条件。**不是你和主控的对话历史**，也不附带整段上下文（上下文研究 §二：「当前任务」的共享范围只到「主控和本任务执行者」）。
- 主控回复里写的 `@施工`，**只是它输出的几个字**；真派活走结构化的工具调用，**派出去的是那个任务包**。
- **隔离靠的是会话怎么管，不是靠某家的子 agent 语义**——改造之后是 CLI 派活给 CLI，两个独立进程、两份独立会话。整套规矩在 **§8.5 会话管理**，那一节是这件事的骨架。
- **必须实测，不能推定**：在主对话里说一句只在那里出现过的话，然后去问施工席位；答得上来就是没隔离。测出来之前界面上不许写「施工看不到」。

**独立审计就是项目审计**，首版就有。独立性是**结构性的**——另一个席位、另一个线程、可能另一家 CLI，不是要算出来的标记，界面上没有「独立性未确认」这种字。

要守住的两条：**审计不与施工共用会话**（房间按席位复用 `ensureSeat`，那条路不能照抄）；**你私下说的不进主控委托的那份审查**。

撤销观察立即停止后续取材、推送与缓存复用，**但不保证模型忘记**；要强撤销就停掉相关绑定，只用仍获准的材料重建。

### 9.2 依据与新鲜度（收 V0.12 §14）

开始观察时在**一致读点**生成上下文包与 source cursor，之后重放可见事件。材料用不可变引用，不用「当前某文件路径」。

默认文案：**「依据：这条回答开始时的现场」「之后主控已更新」「关键材料不足」**。**「看最新」是另一个动作**，点开引用不许默默换成最新文件。

**打开侧栏不自动调模型**，你发问才生成这一轮的包。

**普通侧聊观察不得为了取快照自动暂停主控**——优先用最近已冻结的材料，并标出实时未冻结的部分。

V0.12 §14.2 那套预算编译（`CONTEXT_INSUFFICIENT`、mandatory 优先级）**首版不做**。

### 9.3 递话（用老 GOGO 已实现的那套，不用 Directive 协议）

房间已实现并在跑：`POST /api/conversations/:id/transfer`，`{ sidechatSourceCardId, transferMode: "queue" | "interject" }`，包一层【Owner 从 @X 旁聊投递】。

旁聊本身有独立的系统提示：只回答 Owner 当前的问题、不可接力、不可修改工作区、不可改变目标锚点。sidechat 派发不触发待处理控制。

**两种时机就够**：排队，或插进主控正在跑的这一轮。**不做 V0.12 §15 那套 Directive 状态机**（PREVIEWED／QUIESCING／DELIVERING／ACK_PENDING／APPLIED）——闸门已砍，方向切换不需要独立协议。

**主舞台与旁聊各用各的**：不同 composer、不同草稿、不同附件、不同发送状态。每个编辑器绑死收件人，**不许从全局焦点、最近席位或 `activeThreadId` 推断**。切项目后旧草稿留原处；旁聊还停在别的项目时，面板顶上用显眼标签说明。

## 十、改动、材料与落点

**几种事实分开**（收 V0.12 §10.1，去掉验收那一层）：原生回合结束 → 席位交回成果 → 检查／审查通过 → **改动落到哪里**。每一层都不代表下一层。

**材料属于回合。** `tool.changes[]` 已有路径与 diff，**缺 commit SHA**——派活时记基线、收工时记产生的 SHA，这是「回合 ↔ commit」的归属记录，只能由 gogoke 自己产生。

**交接交的是材料引用**，不是上一位的转述。房间的接力已经这么做：交出去的是工作区、commit、改动文件，并明写不要只依据那段话下判断。

**落点由主控定夺。** 直接改工作区，还是开分支交回来，产品不定死；产品只如实写落在哪。

**「把改动并进来」是改动就绪那一行上的一个动作**，不是在等你的状态——它不让行上写「待处理」，也不提醒你。真要动你的仓库之前当然要你点，但那是**你主动去点，不是它来催你**。

**在途没结算完就不许说完了**（收 V0.12 §10.7 的内核，去掉 CLOSING 那套状态机）：终结意图已登记但还有在途工作时，如实写「N 项在途待结算」，不显示全部结束。

**成果核验的三条**（收 V0.12 §10.2）：`.git` 不直接给模型，模型看的是受管工作副本；检查命令、参数与环境用**受批准的声明**固定，项目内脚本属于不可信代码；**测试 stdout 里的 PASS 不替代退出状态和实际检查记录**。

**一次交接要留四样**（主路径 §7）：谁接的、给了它哪些边界、核对的是哪个版本、交回了什么。**这是数据，不是新界面**——给你看的地方就是「正在进行」展开那条线，里面同时看得到「施工接到了什么」「审计在核对哪一份成果」。

**审计说的「通过」会过期**（主路径 §7、五家 §8、U13）：结论绑成果版本。通过之后被审的文件又改了，**那个「通过」不能继续挂着**——旧结论保留为历史，当前这一版要重新确认适用性。

**资料是哪一版要标清**（上下文 §六）：你把设计从 v3 改成 v4，正在按 v3 审的那位**不会自动知道**，它手上收到的还是 v3。界面标清它用的是哪一版，**不许用「已同步」把这个差别盖掉**。

**项目规则快照**（收 V0.12 §14.5）：执行详情要能看到「本次加载了哪些项目规则、哪个版本、适用哪些目录、缺了什么」。缺必需规则时相关动作返回未就绪，**不是静默少装载**。候选修改规范文件仍可作为成果被审，但**本次检查用旧的批准版本**。

## 十一、安全与收口

### 11.1 工具收口：照现成做法，不建网关

按 `GOGO-V012审计.md` B-1：V0.12 §11.1 的 Managed-Tools **降级**为六样，照 `<local>\Grok Worker Provider`（生产中，源码已核）：

1. **启动契约当数据，spawn 前逐条断言**：`terminalDenied` **`subagentsDenied`（改造后这条更要紧——派活由宿主做 CLI→CLI，各家自带的子 agent 必须关掉，否则会长出我们管不到的第二套派活）** `compatHooksDisabled` `folderTrustEnabled` `trustFlagAbsent`，并**老实写 `windowsSandboxEnforcement: false`**
2. **两级家目录**：持久的按账号装认证与模型缓存，临时的按每次调用装 HOME／USERPROFILE／LOCALAPPDATA —— 这条解掉「隔离 `CODEX_HOME` 就丢登录态」
3. **硬拒默认家目录**及其父子路径
4. **路径围栏**：拒符号链接与 junction，限死在允许根内
5. **项目权威预检**：拒绝把席位派进带 `.claude/settings.local.json` 这类可授权配置的目录
6. **剩余工具边界一个钩子**：`bash`／`run_terminal_cmd` 直接拒；`edit`／`write` 比对允许写入根；每条决定追加一行审计

**不建统一工具网关，不建 LPAC ToolWorker 子系统。** 厂商自己维护的沙箱照用，能力如实标注，**不宣称 OS 级强制**。

保留 V0.12 §11.1 那条：**一家收不了口，则通用自动执行配置整体不发布。**

**不做「完全隔离」总开关**（上下文研究 §三）：项目之间、任务之间、旁聊与主聊、写入之间、施工与正式审计、账号与会话——**这是六种不同种类的边界，不需要做成六组开关**，尤其不能给一个「完全隔离」总开关却只是改了 cwd。工作区约束、只读策略和操作系统级隔离能保证的范围不同，**按实际机制描述**。

**还缺实测**：grok-worker 全篇写死 Grok。Codex、Claude、OpenCode 的等价开关是哪几个、关不关得住，要在目标机器上量一遍——这是施工任务，不是读文档。

### 11.2 进程与来源归属：不做步骤隔离

**进程由谁起：保留 `seat-runtime` 现状**（Owner 2026-09-17 定）。V0.12 §7.1 要求 Rust 宿主创建所有受控进程、Node 不许自己拼启动路径——**那条降级为「宿主持有 Job 句柄与停止权」，谁 `spawn` 不作硬约束**。
理由：`packages/seat-runtime` 的 `close.ts` 已经实现了进程身份与关闭协议，**是跑过的**——它记的是 `pid + processStartTicks`（Windows 上进程号会被回收再用，只记号会认错人）。把起进程那部分搬到 Rust，等于重写那 4987 行里最难的一块。

按审计 B-2：**主控与施工席位保持常驻**——因为这两种要能被你中途纠偏、要累积上下文。
**只跑一轮就交结论的席位（审计、检查）可以是一次性的**，那种用法本来就不需要插话和累积；这跟「不每回合冷启动」不矛盾，后者说的是**不要把常驻席位退化成每回合重开**。

来源归属用**不可复用的进程身份**（`pid + processStartTicks`，`packages/seat-runtime/src/close.ts:188` 已实现）加 **terminal receipt fence**（把「进程结束了」和「回执提交了」分成两件事）。

**不把常驻席位退化成每回合重开。** 一次性进程中途插话纠偏不可能、上下文不累积——所以它当不了主控与施工，这是本项目已经付钱掉过头的路。

来源不可改绑的**原则**照收（V0.12 §8.4）：工具来源由启动前固定的记录决定，**不由「谁现在活跃」反查**。

### 11.3 前端安全（收 V0.12 §12）

- **CSP**：正式发行关闭任意文件 asset protocol；`tauri.conf.json:33` 的 `"csp": null` **至今未修**，这是当前事实不是历史
- **Markdown 禁原始 HTML**；代码、diff、文件名、工具输出转义渲染
- **SVG/HTML 当文本展示**，或在隔离解码器里转成静态栅格；图片解码后重新编码，剥主动内容与非必要元数据
- **外链只允许规范化后的 http(s)**，显示真实主机；禁止 `javascript:`、`file:`；模型内容不能调 IPC
- **终端限制 OSC 52 剪贴板写入**与自动超链接
- **真正的审批、采用控件由可信组件从宿主对象渲染**，不从 Markdown、远端 HTML 或工具返回的按钮定义生成

### 11.3.5 终端与手工修改（V0.12 §17.4）

终端固定到项目与工作区，默认与模型工具同在受控剖面；**手工 shell 也不获得 Owner API token**。
对在途执行的工作区请求写入时，**要么等待，要么显式接管并先停止原 writer**——不是靠终端提示语约束路径。
Owner 在产品外另开编辑器或管理员终端超出托管边界；**关键封存与落点之前要验证受管材料／基线有没有漂移，并拒绝漂移**。

**产物耐久次序**（§17.3）：先写受限临时文件、同步、核对摘要，再原子发布到内容库，最后提交引用事务。**不允许已确认的消息指向尚未完整写出的文件。**

### 11.4 信任边界

沿用 V0.12 §11.2 的七行访问矩阵与 §7.2 的三通道分离（Owner UI 通道、Agent 通道、协议 worker 通道各自 principal 赋权，Agent 连自己的管道不可能通过 payload 变成 Owner）。

路径与文件身份可搬 `crates/gogo-win32-authority`（7484 行：canonical parent、file identity、reparse tag、硬链接、no-clobber 发布）。

## 十二、不知道就说不知道

`待核对`（送达没回执）、`未知`（用量没返回）、`已请求停止`（还没收到停止事实）。

**给你的只有两样**（Owner 2026-09-17）：**如实告诉你不知道**，和**一个「去查」**——读同一次执行的进程、原生状态、工具与产物证据，不发第二次原请求，可重复只读核对。

V0.12 §16.4 另外两个动作（恢复上下文、作为新执行继续）**是主控与宿主的事，不摆到你面前**；「确认停止」并进第五条那两种停止里。后端仍按这四类处理：

| 后端动作 | 处理 | 何时可用 |
|---|---|---|
| 核对原执行 | 读同一执行的进程、原生状态、工具与产物证据 | 不发第二次原请求 |
| 确认停止 | 冻结工具与派工，原生停靠或授权终止并验证 | 需要停止授权，保留所有产物 |
| 恢复上下文 | 原生 resume 或明确冷重建，提升绑定世代 | 旧写入已收敛 |
| 作为新执行继续 | 建 successor，带未重复事项清单与旧结果引用 | 外部未决影响已明确处置 |

**「已登记」只等于第一步**（V0.12 §13.1）：登记 → 预留 → 明确未发／送达不确定／对方已接收 → 终态。原生拒绝、取消、限额、截断、失败和未知**不能压成一个「完成」**。
同一幂等键 + 同一规范化请求返回原结果；**同键不同内容拒绝**；你两次有意发同样的话，是**两个消息身份**。

**循环保护不是可选项**（V0.12 §16.3、老 GOGO `22` §4.3）：席位互相 `@` 到第 N 跳自动暂停，**人类消息始终放行**。
只防同一条消息重复是不够的——**不断生成新 ID 的循环委托也要拦**。预算耗尽先阻止新增调用，保留在途处理和结果；主控可以提出调整，**不能自增预算**。

**新执行不把旧 UNKNOWN 改成「从未发生」。** 不能确认停止时，不允许向重叠写空间重派。

**断线与恢复**（拆块 15、主路径 §6、U10／U11／U12）：断线保留正文、草稿、当前成果和最后更新时间，文案是「连接中断，最后更新于……」；**发送结果未知单独标示**。
重连后**先读服务端的真实任务与回执，不自动重发**。**停止不回退文件。** 查看旧版不等于恢复；**恢复只覆盖声明的范围**，并同时列明聊天、外部数据库、发布状态**不随文件一起回退**。
**导出成果与对外发布是两件事**——导出选定原件／版本／必要证据，**不带凭据**（S05）。

**六种现场的处置**（收 V0.12 §3.4，每行都带「不允许的捷径」）：CLI 等回答／资源占满／投递未知／改向停靠失败／成果有冲突／私聊依据落后。

## 十三、输入、草稿、附件、无障碍（收 V0.12 §4）

- **收件人固定**，不从焦点或 `activeThreadId` 推断；草稿按作用域／对话／隐私域分键，恢复页面、切角色、开设置、看 diff 都不丢
- **中文输入法 composing 时 Enter 不发送**；快捷键只作用于当前编辑器
- **流式输出不抢焦点、不强制滚动**；回到最新由你选择；长日志虚拟化，终态与控制卡不被流量淹没
- **所有状态有文字与屏幕阅读标签，错误不只靠颜色**；系统通知默认不显示私人正文
- **断线时显示最近已知状态和时间**，不乐观显示「仍正常」
- **「本次引用」要分清三件事**（上下文 §五、M15）：输入框上面一行写清这次带上了什么；**能查阅 ≠ 已经放进这次输入 ≠ 模型真的读了**。删掉一个引用只影响还没发出去的那条，**不能假装把模型之前已经看过的东西也删掉了**
- **附件四态**：`IMPORTING → FROZEN → ATTACHED → SENT`；发送前必需附件必须冻结；导入复制到受限内容库并算摘要，不只记原路径；超限不静默截断
- **共同附件合同**：各家对同一附件取得相同的文本或图像语义；某家过不了就整体不发布该能力，不为一家单独放行
- 现成可搬：`input-references.ts`（343 行，本次引用）

## 十四、一次完整使用

1. 左栏点开一条对话 → 中央就是它，答话的是这个项目的主控，最后一块是「正在进行」。
2. 你说要什么 → 底部标着「发给 主控」，默认排队；有活动回合时才出现插话选项。
3. 主控回复里 @ 出去 → 「正在进行」分出几条线，各自跑动，动作在行上滚。
4. 施工有问题 → 交主控 → 主控知道答案，正文里一句说明，你不用动（施工从不直接找你）。
5. 审计有问题 → 交主控 → 主控定不了 → `userInput` 卡出现在固定位置，挂主控名下。
6. 施工交回材料 → 那条线收口，行上显示它交回的第一句结论，展开是 commit 和改动文件。
7. 本项目审计按被审版本独立核对 → 结论回到这条对话。
8. 材料齐、检查通过 → 折起来那一行写 `改动就绪 · 3 个 commit · 已在你的工作区`，左栏亮「完成未看」。你看过就完了。
   若主控选的是开分支交回，则写 `改动就绪 · 3 个 commit · 在 feat/x 上`，行上带一个「并进来」的动作——**不催你**。
9. 想追问 → 右侧面板开旁聊问本项目审计或秘书长；听完把那一句递给主控（排队或插话），带出处。

## 十五、分批

**顺序原则**：每一批先定宿主要产生哪几条事实，再把界面绑上去。界面不领先于事实，事实不领先于用途。

**第 1 批开工前先写一张表**（不单列一批）：真缺的那几条事实——改动就绪与 commit 归属、旁聊与递话、角色管理、秘书长的位置、未读——逐条写清谁产生、什么形状、界面读哪里。**没有一条可以写「沿用某处已有的」。**

| 批 | 宿主要先产生 | 你能拿到什么 | 这一批算完的条件 |
|---|---|---|---|
| **1 主路径骨架** | 回合与席位任务、活动、CLI 原问题、权限请求、席位行的动作与结论、材料↔回合归属 | 正在进行（含收起来的第一层）、`userInput` 卡、输入与发送、草稿 | 跟主控说一句话，真起一个席位回合，动作在行上滚；席位的问题不直达你 |
| **2 项目与对话立起来** | 项目与主控／审计的固定绑定、状态字的三样事实、在途结算 | 秘书长位置、项目工作区与其下的对话、每行带状态字、左栏筛选、未读 | 昨天那条今天找得回；一条对话只占一行；切走不丢草稿也不停活 |
| **3 席位与实例** | 角色与席位（含主控自主拉席位）、实例与登录、项目级隔离、容量许可 | 面板里的角色管理 tab、设置里新增的实例管理节 | 五家按 §8.2 九步逐一上架；不存在「半支持」 |
| **4 改动闭环** | 交接记录、交付集合、改动落点、项目规则快照 | 材料展开、改动落在哪、规则版本 | 一件事从开工走到改动就绪，全程在 gogoke 里；落点如实，不需要你盖章 |
| **5 旁聊** | 第二条对话通道、分室隔离、一致读点与出处、递话（排队／插话） | 旁聊 tab、递话 | 只递选中的一句，带出处；私聊不回流 |
| **6 收口** | 断线与进程身份、停止、设置、项目边界 | 断线恢复、首次使用、项目边界 | UNKNOWN 四个动作可用；不假装 |

## 十六点五、可参考的旧账（**GOGO PARTY 时期，不是 gogoke 的清单**）

以下来自 GOGO PARTY 时期、服务已搁置那条内核线的材料。**架构不同，不整片适用**；列在这里只作检查时的参照。

**三条方法论**（`docs/audit/2026-08-24-triple-identity-audit.md` §四）——与架构无关，是写判据和写"已实现"时的通用教训：

1. **判据本身必须有反向用例，而且逐维度断言。** 「验法通过但不变量没成立」出现过三次。与 `32-gemini-adaptation` 的 INV-PROBE-2 同源：只有否定用例不许写判据。
2. **设计稿里「有测试」曾经是编的。** 某稿给六条不变量各写了一句「怎么验」，读起来像既成事实，**实际一条都不存在**。**写「已实现」之前先 grep。**
3. **拿源码正则钉一行代码的测试是脆的**——有一个断言匹配到了注释里解释历史的文字而变红。
