## 一、缺的十三条（说人话；原十九条，按 Owner 立场砍两条、改四条）

每条先说**不做会怎样**，再说**该怎样**。括号里是出处。

### 关于你按下去的那些操作

**1. 撤回不该显示成"派发失败"**（主路径 §4、U03）
你跟主控说了句话，它还没开始干，你反悔了点撤回——现在会弹一个红色的"派发失败"，看着像出错了。应该写「已撤回」。如果它已经开始干了，就老实说撤不回来，不能假装撤成功。

**2. 插话正好撞上回合结束**（主路径 §4、U04）
你趁它正在跑插一句"价格别改"，可你按下去那一刻它刚好跑完了。这句话不能被偷偷塞给下一轮或者别的席位，要告诉你"这一轮已经结束了"。

**3. 不许凭空造一个"跳过"**（主路径 §4、U06）
CLI 弹问题给你，它本身只给了"是／否"两个选项。界面不能自作主张多加一个「跳过，继续」——按了之后没地方送，等于骗你。请求已经过期了，就直接显示过期。

**4. 「一堆待答挤在一个队列里」这个场景不成立 —— 收窄**（Owner 2026-09-17）
研究设想的是多个 Agent 同时找你，所以要一个待答清单，点开一条在固定位置作答、其他条不冲草稿。
**你这边不是这个形状**：**主窗里只有主控会问你**；侧窗是你主动开的，问审计还是问秘书长由你决定。**两边各有各的 composer、各有各的草稿**（整合设计 §9.3 已定）。
所以不做"待答清单"。保留的是：**问题出现时不抢焦点、不冲你正在打的字**；主窗侧窗的草稿互不干扰。

**5. "停止"是两种，不是三种**（主路径 §4／§6、U11；Owner 2026-09-17 收窄）
从你的立场只有**停这一轮**和**停这件事**；研究里那个"以后别再派活"是主控内部的事，不摆到你面前。
真正要守的三句：**点了停止不等于真的停了**（"已请求停止"和"确认停下来了"分开写）、**已经改过的文件不会自己退回去**、**普通停止不逼你填理由**。

**6. 跑了八轮不等于完成 80%**（主路径 §9）
不能拿轮数、拿"进程还活着"推出一个进度百分比。有真实步骤就显示步骤；没有就显示"正在做什么"和最后一条可信的更新。

### 关于界面上该有而没有的位置

**7. 项目资料不另开一栏，用左栏已有的文件**（上下文 §五；Owner 2026-09-17 收窄）
研究要的是一个轻的项目资料入口。**gogoke 左栏本来就按项目排、下面有文件，Files 也已经是面板的一个 tab**——不再另开"项目资料栏"。
保留的规矩：**不要把项目资料塞进全局设置那种大表单里**。

**8. 「本次引用」要分清三件事**（上下文 §五、M15）
输入框上面要有一行写清这次带上了什么。而且必须分清：**能查阅 ≠ 已经放进这次输入 ≠ 模型真的读了**。你删掉一个引用，只影响还没发出去的那条；不能假装把模型之前已经看过的东西也删掉了。

**9. 接手记录放在「正在进行」展开里，不另开地方**（上下文 §五；Owner 2026-09-17 收窄）
「施工接到了什么」「审计在核对哪一份成果」——这些是你展开那条线时看到的内容，**不是一个新界面**。不用你去翻它们的完整聊天。

**10. 项目设置和全局设置分开**（上下文 §五）
项目文件夹、允许引用的资料目录、项目规则来源 → 项目那边。语言偏好、账号、运行实例 → 全局那边。**不要把某个项目的业务决定存进全局设置。**

**11. 那张图不能只能靠拖**（主路径 §9、U15／U16）
工作树那种图，必须**不拖拽也能用**：能点、能用键盘、能切成列表、能一键适应画布、分栏能点着调宽。这是无障碍的硬要求，不是加分项。

### 关于交出去和收回来

**12. 一次交接要留四样（是数据，不是新界面）**（主路径 §7）
谁接的、给了它哪些边界、核对的是哪个版本、交回了什么。**记录必须有**；给你看的地方就是第 9 条那个展开，不另开。

**13. 审计说的"通过"会过期**（主路径 §7、五家 §8、U13）
审计通过之后，如果被审的那些文件又改了，那个"通过"**不能继续挂着**。旧结论变成历史记录，当前这一版要重新确认适用不适用。

**14. ~~三种审计不是一回事~~ —— 首版砍掉**（Owner 2026-09-17）
研究说审设计、审计划、审代码的对象不同。**首版只做代码生产，只有代码审计一种**，没有要区分的对象。
真做通用生产时再回来看这条。

**15. 资料是哪一版要标清**（上下文 §六）
你把设计从 v3 改成 v4，正在按 v3 审的那位**不会自动知道**——它手上收到的还是 v3。界面要标清它用的是哪一版，不能显示「已同步」把这个差别盖掉。

### 关于设置

**16. 每条设置要说清四件事**（设置研究 §2、M18）
管到哪（这台机器／这个项目／这次任务／CLI 全局）、什么时候生效（马上／下次发送／新任务／重启后）、默认是从哪来的，以及——**存下的值和当前真正生效的值不一样时，要同时说**。

**17. 不支持的能力不许画成能打开的开关**（设置研究 §2）
某家 CLI 不支持某个能力，就不要给它画一个看起来能开的开关。能力分四种：支持／不支持／还没读到／读失败。连接状态也分四种：已保存／已验证／占用中／需登录，**不能混着说**。

**18. 保存失败别把你写的东西弄没了**（设置研究 §2）
保存失败要保留你填的内容；不能弹个「保存成功」就当它真生效了。删除、断开、公开发布这类**危险操作要和改主题字号分开放**，不用同一套轻率的交互。

**19. 第一次打开不许自作主张**（主路径 §9、M22）
不能为了让你少点两下，就偷偷替你绑账号、替你登录、或者发一条测试消息出去。先让你看到一件示例工作、一段对话和一个成果；真的要用到某项能力时，再说明需要连什么。

### 另外三条视觉规矩（进 `kit/index.json`）

- **鼠标移上去、按下去、聚焦时，控件尺寸不许变** —— 一变点击目标就跑了，容易点错。
- **正在提交时按钮宽度保持不变、挡住重复点击**；失败保留草稿；成功就地反馈，不弹大窗。
- **强颜色只用来表达真实状态或焦点**，不要把整个任务、整列或每条确认都染上色；"次要信息"不等于小到看不清、淡到看不见。

## 二、研究里三条已经被裁决覆盖的（**不是待定，已定**）

这三条我一度写成「要 Owner 定」，是把已有裁决丢了。**已定，不要再问。**

### 1. 成果本体：Git／Files 就是首版的成果

**研究说**（主路径 §5、UI 拆解 C08/C09、五家 §8）：成果区要显示用户能判断的**本体**；「通用地把所有成果换成文件路径清单，会把判断成本重新推给普通用户」；成果查看器要省去「先要求用户会读代码」。

**已定**（Owner 2026-09-16）：**首版只做代码生产**。代码生产的成果就是 diff 与改动文件，Git／Files 两个 tab 已经在做这件事；另开「成果」tab 是同一批字节的第二套真相。
研究那条面向非程序员的要求，对应的是通用成果（M10–M14：Markdown／PDF／DOCX、图片区域反馈、表格、音视频），**全部标着「设计未实现」，属于首版之外**。

不是冲突，是**同一条要求在首版范围之外**。等首版之后做通用成果时再回来看研究 §5 那张六行交互表。

### 2. 验收归属：没有验收动作，也不补记录

**研究说**（五家 §9 第三条）：重复确认可以去掉，但「真实失败、问题原文、证据版本和最终验收归属不能去掉」。

**已定**（Owner 2026-09-16）：「什么最终可验收还要点一下？不用那么麻烦的，你看 ClaudeCode 以及 Codex 完成一个项目是输出文字，哪里还要点什么验收还是什么的。」

同一份研究的 §7 本身就支持：三种「完成」的边界「可以留在后台和按需查看的记录中，**不必变成主对话中反复出现的阶段标签或确认卡**」。
留下的是**事实**：折起来那一行如实写 `改动就绪 · N 个 commit · 落在哪`，未读打开就清。**「谁接受过」这件事由你接着说或不说来表达，不由产品记一笔。**

### 3. 组件顺序：第 1 批不挑任何组件

**研究说**（UI 拆解）：先把输入框、收件人菜单、CLI 问题、就地反馈、成果入口、侧栏统一成一组，再处理卡片与画布。

**已定**（Owner 2026-09-16）：**组件点选挪到最后**——「后端还没有就挑组件太早」。而且工作树的 `chosen` 已经是我们那个八版演示，不是待选项。

所以第 1 批做的是**宿主要产生的事实**，不是挑组件；研究那条排序针对的是「挑组件」这个动作，两边不在同一件事上。
研究那条仍然有效的部分已经在 `kit/index.json` 的规矩里：同一用途只出现一个 chosen，不许每加一个功能就长出一种新确认框。

## 三、U01–U18 现在有定义了

出处 `工作主路径研究.md` §11。整合设计 §16 引用它们，之前没有定义在手。全部**当前均为待验证**，不是已通过。

| 编号 | 成功条件（摘要） |
|---|---|
| U01 | 两件工作切换，文字、附件、收件人各自保留 |
| U02 | 新目标同一主控席，如实表达会话连续性，不假称空上下文 |
| U03 | 排队后撤回：原消息标已撤回，**没有派发失败卡** |
| U04 | 回合结束边界点插话：按实际回合归属处理，不跨目标 |
| U05 | 两席同发相同题目：每个答案只回原请求；切题保留草稿 |
| U06 | CLI 没有跳过选项：UI 不自动补出跳过/默认继续 |
| U07 | 中文输入法选词按 Enter：不意外发送 |
| U08 | 选旧预览元素后出现新版本：草稿保留，反馈仍标旧版本，**定位不被暗换** |
| U09 | 选择模式点页面提交按钮：只选择，不提交真实表单 |
| U10 | 服务器收到但浏览器丢回执：重连核对原任务，不重复派发 |
| U11 | 点停止但上游未停：先显示停止请求，直到收到实际停止事实 |

| U13 | 审计通过后修改被审代码：旧结论标明对应旧成果 |
| U14 | Provider 没返回用量：未知有明确标记，**不显示零花费或推断余额** |
| U15 | 点看板空白、缩放、切列表：取消选中可达；布局不改变任务状态 |
| U16 | 不拖动仅点击或键盘：仍能定位、调整布局与发送 |
| U17 | 200% 缩放或窄分栏下回答问题：文案可读、焦点可见、不被遮挡 |
| U18 | 初次使用者完成一次反馈任务：能解释「改哪里、发给谁、是否开始」，**不需术语辅导** |

**U18 必须真人验。** 自动化点击或 Agent 觉得简单，只能证明交互可执行。

## 四、M01–M22 的状态：没有一条是已验收

`研究覆盖与缺口.md` §M01–M22 逐条给了实现路径、测试与证据。**二十二条的判定全是「实现待审／证据不足」「部分实现」或「设计未实现」，没有一条标为已通过。**

对整合设计有直接影响的五条：

- **M16**：`ensureSeat` 复用席位进程，`auditSeatFor` 只查 provider family ——「主控会话连续性真实存在；**正式 fresh 运行和原生记忆隔离未被强制保证**」。这就是整合 §9.1 要做的事，不是已有的。
- **M17**：halt/verify/acceptedAt 存在，但「**localhost Owner 操作不是强身份鉴权**」。
- **M05**：队列、撤回、插话、暂停派发存在，但「**不能由 Room 暂停推断上游 CLI 已停止**」。
- **M20**：保留 unknown 与原生问题语义，但「**无覆盖各 Provider 的完整费用/额度界面证据**」。
- **M10–M14**：通用成果（Markdown/PDF/DOCX、图片区域反馈、表格、音视频）**全部设计未实现**。首版只做代码生产，正好不碰这一摊。

**注意**：M01–M22 的编号出处是 `改版研究总图.md`，那是 Owner 2026-09-14 冻结的三份之一。**编号可以用来查证据，但那份稿子本身不作为施工依据。**
