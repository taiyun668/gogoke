# GOGO 统筹设计

**先读 `GOGO-要做的和不做的.md`**——那份是入口，写着已经砍掉的东西和 gogoke 已经有的东西，不要再发明一遍。

把《GOGO-拆块清单》的 19 块统成一个东西。顺序是：**对象 → 词汇 → 状态字判定 → 窗口职责 → 注意力规则 → 事件映射 → 一次完整使用 → 分批**。
前六节是硬约定，任何一块开工都不得绕过；第七节是串起来的样子；第八节是施工怎么切。

---

## 〇、事实来源（先读这条）

**界面永远只做只读投影；被投影的事实一律由 gogoke 自己的宿主产生。没有第二个后端。**

**gogoke 已经有的是界面形状，不是能力。** `src-tauri/src/` 只有 `codex/` 模块，别家零引用（2026-09-17 核）——下面这些全是给 Codex app-server 写的渲染层，换一家就都不存在。**界面可复用，能力为零；不要把一家的协议当成产品本体。**
席位 = 带角色的线程（`ThreadSummary.isSubagent / subagentNickname / subagentRole`）；
左栏按项目排（`ThreadListOrganizeMode`）；派活发散收敛（`collabSender / collabReceivers[] / collabStatuses[]`）；
CLI 问题（`RequestUserInputParams`）；权限请求（`ApprovalRequest`）；改动文件（`tool.changes[]`）。
**缺的是产生这些事实的后端，不是界面形状。**

**真正一点都没有的，只有这几条**：未读、行上的状态字、旁聊与递话、角色管理、commit 归属（`changes` 有路径和 diff，没有 SHA）、秘书长的全局位置。

`packages/room` 是**参考实现**：那边的判定规则和接口形状可以照抄，但它不是 gogoke 的后端——
两边底层不是一个东西（Owner 2026-09-16）。**本文任何地方都不存在"接上房间"这条路。**

## 一、对象模型

```
秘书长                        ← 全局，左栏独一个位置；跨项目，服务 Owner 本人

项目（工作区）── 资料 · 已确认决定 · 角色与席位名册 · 文件
 ├ 主控 / 审计                ← 固定绑定，各一个；绑在项目上，不绑在对话上
 ├ 对话（= 一件工作 / 一个目标，多条；左栏点开的就是它）
 │    ├ 回合 ── 席位任务 ── 动作 ── 材料（commit / 改动文件）
 │    └ 交付集合          （本轮的精确版本集合 + 审查结论 + 改动落在哪）
 └ 旁聊                    ← 在侧边窗口里；只找秘书长或本项目审计

设置 ── 实例（账号 + CLI 安装 + 登录），跨项目共用
```

**定死的几条：**

- **一条对话就是一件工作。** 左栏点开的是对话，不是项目——跟 Codex、Claude Code 一样。一个项目下可以有多条对话，**都由同一个主控答**。
- **主控和审计绑在项目上。** 一个项目固定一个主控、一个审计。目标不跨项目：同一个主控管本项目下的多个目标，别的项目一概不碰。
- **角色不绑 CLI。** 四层解耦：**角色**（主控／审计／施工／秘书长）→ **席位**（项目里担这个角色的一位）→ **实例**（一个账号加一份 CLI）→ **进程**。同一个实例可以服务不同项目的席位，**项目级隔离照做**：别的项目的资料、记忆、执行权一概不共享。
- **主控在授权范围内自己拉席位、拉角色**，不必回来问 Owner。它不能自增权限，不能删监督者，不能改他人的审计记录。
- **秘书长是全局对象**，不属于任何项目。它可以被拉进某个项目的旁聊，但记忆和归属仍在全局，不因此改归项目。
- **施工抓不到。** 旁聊只对秘书长和本项目审计开；施工的事一律走主控。
- **席位向主控负责，你只是监督查看**（Owner 2026-09-16）。席位的卡住、失败、重试都由主控处置；界面如实显示，不生成你的待办。
- **切走不等于停下。** 切到别的对话或别的项目，原来那条的草稿和正在跑的活全部保留。
- **ID**：项目沿用 gogoke 的工作区登记，对话沿用 gogoke 现有的 thread id。不新增会漂移的第二个身份，不引入 `roomId`。
- **材料属于回合**，不是属于对话。交接交的是材料引用，不是上一位的转述。
- **没有验收动作。** 席位怎么干活——直接在工作区里改，还是开分支／worktree 交回来——**由主控定夺，产品不定死**（Owner 2026-09-16）。产品只如实写改动落在哪；**只有当真有一个会改你仓库、又只能你授权的动作没做时**，那一下才出现，并写清是什么动作。
- **你接着说就是继续，不说就是到此为止。** 跟 Claude Code、Codex 一样，不用点任何东西来结束一件事。

**长期愿景（不是首版要求）**：说一句"做一个生产级系统"就一路跑到交付。首版不按这个尺度设计，但任何一处都不得做出"必须 Owner 一直看着"的假设。

## 二、词汇（对外只用这一套）

| 用这个 | 意思 | 不要用 |
|---|---|---|
| 对话（= 一件工作 / 一个目标） | 你要的一个结果，左栏点开的那一条 | 房间、thread、任务 |
| 项目（工作区） | 一个主控和一个审计固定服务的那一摊，下面挂着它的对话 | 空间、workspace（对外） |
| 秘书长 | 全局那一位，服务你本人，不属于任何项目 | 助理、管家 |
| 状态字 | 折起来那一行和左栏对话行上的那个词，五选一，由事实推出 | 归栏、阶段、进度、看板列 |
| 右侧面板 | 现有 Git／Files／Prompts 之外再加成果／旁聊／角色管理 | 侧边窗口、抽屉、drawer |
| 角色 | 主控／审计／施工／秘书长 | agent 类型、模型 |
| 实例 | 一个账号加一份 CLI 安装 | 模型、厂商、provider |
| 主控 | 组织这件事的那一个 | leader、orchestrator |
| 席位 | 项目里担某个角色的一位 | agent、worker、成员实例 |
| 回合 | 一位席位的一次执行 | turn、迭代 |
| 材料 | 这一轮真留在仓库里的东西 | 产出、结果 |
| 旁聊 · 递话 | 侧边问秘书长或本项目审计；把选中的一句给主控 | 私聊、转发 |

**这几个"完成"永不混用（这是措辞规矩，不是几个按钮）：**
`回合结束`（一位席位跑完了）→ `改动就绪`（材料交回了）→ 改动落在哪（`已在你的工作区` 或 `还在 xxx 分支`）。
界面上禁止出现光秃秃的"完成""通过"，也禁止出现"待验收"这种等你盖章的说法。

**不知道就写不知道**：`待核对`（送达没回执）、`未知`（用量没返回）、`已请求停止`（还没收到停止事实）。

## 三、折起来那一行写什么（从上往下命中首条）

「正在进行」归一折成一行之后，那一行右边写一个状态字（演示 `gogo-work-tree.html` 里折起来写的是 `可验收 · …`；**2026-09-16 起改成 `改动就绪 · N 个 commit · 已在你的工作区`**——不再有等你盖章的说法，也不再提对账和独立性）。
**左栏那条对话行显示的就是同一个字。没有五列，没有看板，没有第二个投影。**

这个字是三样真事实的只读投影，不新增状态机：**有没有待答的 `userInput`**（gogoke 已有 `pendingUserInputKeys`）、**有没有在跑的回合**（已有）、**改动交回了没有、落在哪**（这条要后端补，见第〇节）。

| 优先 | 条件 | 状态字 | 这一行还写什么 |
|---:|---|---|---|
| 1 | CLI 有真实问题在等你答 | 待处理 | 原题来自哪一位、哪一回合 |
| 2 | 有一个会改你仓库、只能你授权的落地动作没做 | 待处理 | 写清是什么动作：「3 个 commit 还在 `feat/x` 上，没并进来」 |
| 3 | 本轮有排队或运行记录 | 在运行 | 真实动作："排队中 / 制作中 / 审计中" |
| 4 | 材料齐、verify=ok、无待答问题、无待授权动作 | 改动就绪 | 「N 个 commit · 已在你的工作区」或「N 个 commit · 在 `feat/x` 上」 |
| 5 | 其余 | 不写字 | 没活动就是没活动，不用一个词去描述它 |

**状态字挂在对话上，不挂在项目上。** 工作区那一行显示的是它下面最要紧的那条（按上表优先级，命中最靠前的那个字）。

**状态字只出现在归一折起来的那一行，席位那几行一个都没有。**
席位向主控负责，你只是看得见——所以席位行上不摆面向你的状态机：跑着写它最近做了什么，收口写它交回的第一句结论。
它卡住了、失败了，是主控去处理；界面如实显示，不把它变成你的待办。

**"完成未看"是另一维**，不占状态字：**打开那条对话就清**，不因筛选或悬停清除。这就是"一眼看全"——哪条你还没看过。

## 四、窗口职责

| 位置 | 第一眼 | 你主动展开 | 永远不放 |
|---|---|---|---|
| 左栏 | **秘书长（独一个位置）**、项目工作区；工作区下面是它的对话，**每行带状态字**；搜索、新建 | 项目资料、文件、归档、"只看待处理" | 主控拆出的内部任务、每个审计进程、阶段横条 |
| 中顶 | **保留 gogoke 现有的**：工作区名、分支、worktree 信息弹层（改名／upstream／复制命令）；**加**当前对话名与开右侧面板的按钮 | 现有弹层照旧 | 常驻的"设计中／施工中"标签、对话／看板切换 |
| 中正文 | 你的原话、主控的结论、成果入口（点开到 Git／Files） | 本轮过程、原始依据、更多操作 | 每条消息一个大卡、堆栈、反复确认卡 |
| 中正文末尾 | **正在进行**（永远最后一块）；收起来就是第一层，发散、收敛、归一都在这里 | 某席位的动作、材料、交接原文 | 把它插在历史中间、另开一个看板页 |
| 中底 | 输入、收件人固定是本项目主控、附件与"本次引用"、发送 | 发送方式、真实待答问题 | 一排要你管理的成员 chip、阶段向导 |
| 右侧面板 | **保留现有三个 tab**：Git / Files / Prompts；**只加两个**：旁聊、**角色管理** | 版本、反馈、固定查看 | 悄悄改变主输入的收件人、**施工席位的旁聊入口**、**另开一个"成果"tab** |
| 设置 | **保留现有 16 节**（Agents／Codex／Composer／Dictation／Display／Environments／Features／Git／OpenApps／Projects／Server／Shortcuts／About…）；**加**实例管理一节 | 单个实例的运行配置与故障 | 项目里的角色与席位（那在右侧面板里） |

**状态字就在折起来那一行和左栏的对话行上**，三选一：待处理／在运行／改动就绪；其余不写字。由事实推出，不手填、不能拖。没有第三个地方显示它，也没有看板页。

**角色管理是右侧面板的一个 tab**（Owner 2026-09-16），跟现有的 Git／Files／Prompts 并排，不是设置里的一节，也不是中顶的展开。入口是中顶靠右开面板的按钮。**实例管理才在设置里**，作为新增的一节——那是全局的、跨项目共用的。

**不加"成果"tab。** 首版只做代码生产，成果就是 Git 和 Files 里那些东西，再开一个 tab 就是同一批字节的第二套真相。
「指着说这里不对」现在已经跑得通——diff 里选几行，`buildPullRequestReviewPrompt` 把选中的行拼成提示，`sendUserMessageToThread` 发出去。缺的只有两处小改：**收件人换成本项目主控**（现在发给 `reviewThreadId`），**加一个"这里不对"的自由文本意图**（现在只有 Review PR／Risk Scan／Test Plan／Summarize 四个预设）。

**没有验收页，也没有验收按钮。** 归一折起来那一行如实写改动落在哪；只有真有一个需要你授权的落地动作时，那一行上才出现它，并写清是什么动作。

**这张表只说加什么、不动什么。** gogoke 现有的中顶、设置各节、面板三个 tab 一律保留；本表没写"加"的地方就是不动。

**切对话 / 切项目 = 换现场，不换状态。** 原来那条的草稿、对话和正在跑的活全部保留，切走不等于停下。左栏能看出哪条有东西等你。

**不做独立看板，也不做归栏五列**（Owner 2026-09-16）：这两件事都由「正在进行」承担——展开是发散的几条线，归一折起来就是带状态字的那一行，左栏显示同一个字。没有第三个页面。

**固定查看 B、主对话仍是 A 时**：浏览和写批注都不动 A；"加入此对话草稿"明确以 B 为对象并打开 B，A 的草稿完整保留。

## 五、注意力规则

**只有一种东西可以主动占用你：CLI 的真实问题。** 其余一律安静。

对账、花费上限这些闸门**首版不做**（Owner 2026-09-16）。

| 事件 | 表现 |
|---|---|
| 席位开始 / 结束一个回合 | 正在进行里的一行变化，不提醒 |
| 工具动作 | 折叠在席位行里，不提醒 |
| 席位有问题 / 卡住 / 失败 | 交给主控处置；界面如实显示，不提醒、不变成你的待办 |
| 主控要你定 | 选择卡，挂主控名下，固定位置 |
| 材料交回 | 那一行收口，父行计数变；不提醒 |
| 一件事变成改动就绪 | 左栏行上亮"完成未看"；只在你离开那条对话时通知 |
| 断线 / 送达未知 | 就地标注，不弹窗，不自动重发 |

**产品永不自己出题**：暂停、开工、把改动并进来都是动作，不是系统生成的选择题。**验收和闸门都整个取消了。**

## 六、事件到界面的映射

事件到界面，一一对应。这张表是接线时的唯一依据。**左栏是 gogoke 宿主要产生的事件**，来源是 gogoke 自己记的。

| gogoke 的 `ConversationItem` | 界面 | 规矩 |
|---|---|---|
| `message`（user / assistant） | 你的消息、主控回复 | 递话来的那一条要标出处，可点回原处 |
| `userInput` | **唯一**的"要你定"卡 | 主控要你定和 CLI 原问题走的是同一条路（`RequestUserInputRequest` 绑 thread + turn + item）。原题原选项，先选后提交，收起不代答 |
| `tool`（`toolType: "collabToolCall"`） | 正在进行的那几条线 | 发散结构就是 `collabReceivers[]`；每条线跑着写最近一个动作，收口写交回的第一句 |
| `tool`（其余） | 折在席位行里的工具动作 | 不提醒、默认折叠 |
| `explore` | 席位行里的读／搜／列／跑 | 跟工具动作同级，不单独占位 |
| `reasoning` | 默认折叠 | 不占正文重心 |
| `diff` / `tool.changes[]` | 席位行展开里的改动文件 | **缺 commit SHA**——交接交的是精确版本，这条要后端补 |
| `review` | 审计那一位的结论回来 | 结论交主控；主控定不了才走 `userInput` 问你 |
| `ApprovalRequest` | 权限请求 | 走 gogoke 现有的 `ApprovalToasts` 那条路，不另造 |

**这张表只认 gogoke 自己的类型。** 房间的 `NOTE / RESPONSE / ACTIVITY / SYSTEM_STATUS / CONTROL / CLI_INPUT` 那套词一个都不用——它们在 gogoke 里不存在。

## 七、一次完整使用（把七样串起来）

1. 左栏点开一条对话 → 中央就是它，答话的是这个项目的主控，最后一块是"正在进行"。
2. 你说要什么 → 底部标着"发给 主控"，默认排队；有活动回合时才出现插话选项。
3. 主控回复里 @ 出去 → "正在进行"分出几条线，各自跑动，动作在行上滚。
4. 施工有问题 → 交主控 → 主控知道答案，正文里一句说明，你不用动（施工从不直接找你）。
5. 审计有问题 → 交主控 → 主控定不了 → 选择卡出现在固定位置，挂主控名下。
6. 施工交回材料 → 那条线收口，写"改动就绪"，展开是 commit 和改动文件。
7. 本项目审计按被审版本独立核对 → 结论回到这条对话，带独立性标记。
8. 材料齐、verify=ok → 这条对话的状态字变成"改动就绪"，左栏亮"完成未看"；切到别处也还在那儿。
9. 折起来那一行写 `改动就绪 · 3 个 commit · 已在你的工作区` → 你看过就完了。若主控选的是开分支交回，则写 `待处理 · 3 个 commit 还在 feat/x 上`，并给出并进来的动作。
10. 想追问 → 右侧面板开旁聊问本项目审计，或问秘书长；听完把那一句递给主控（排队或插话），带出处。

## 八、分批（事实合同在最前，组件点选在最后）

**顺序原则**：每一批先定宿主要产生哪几条事实，再把界面绑上去。界面不领先于事实，事实不领先于用途。

**第 1 批开工前先写一张表**（不单列一批，就是第 1 批的前置）：真缺的那几条事实——改动就绪与 commit 归属、旁聊与递话、角色管理、秘书长的位置、未读——逐条写清谁产生、什么形状、界面读哪里。**没有一条可以写"沿用某处已有的"。**

| 批 | 宿主要先产生 | 你能拿到什么 | 块 | 这一批算完的条件 |
|---|---|---|---|---|
