## Purpose and bounded scope

For each of `claude`, `codex`, and `opencode`, native code shall enumerate the complete finite set of original historical resources that can affect the driver's selected managed copy or any instance participating in its version action. The proposal covers all three drivers in one scope inventory. Each actual action remains a separate authenticated USER operation for one original physical Root/database, one driver, one request ID, one operation, and one compiled target version. It is not a bulk three-driver transaction.

The permitted exception is a read-only qualification view for that version action. Complete original producer association and an original StopFact/StopProof or an existing complete exact-identity/kernel-reboot fact may re-evaluate the corresponding historical execution occupancy. Only if Owner explicitly approves D-NOLAUNCH may its distinct sealed original-unstarted-boundary fact re-evaluate the exact corresponding H resource; that fact settles no pre-boundary or other execution/F effect. None of these facts changes the original success, failure, UNKNOWN, delivery, claim, HOME or stop outcome.

The caller may identify the requested driver and action through the existing USER frame. It may not choose a subset of historical blockers, supply a process list, SID, path, count, proof boolean, or claimed absence. Native code derives membership, identities, associations, and proof sources from the original verified authority and trusted producers. Missing, ambiguous, unowned, or unrecognized members refuse qualification. A query failure is not an empty result.

### T07: old occupancy and new version output

The legacy first-copy/four-field managed probe could persist a C row without a version-action row: after the exact custody tuple and writer fence, `mark_stopped` could persist STOPPED and the original StopProof hash before the probe examined `--version` stdout/exit and marked the copy PROBED. The old C row did not persist the original request, complete StopProof preimage, durable confirmation receipt or stdout/exit. Its operation string, STOPPED label and hash cannot reconstruct those facts. An absent action row cannot prove that a C never belonged to an action when no durable association survives. The approved B boundary qualifies only that original C resource's future execution occupancy, without certifying old command class, old probe success, NoLaunch or retry eligibility. Missing old stdout remains `NOT_RETAINED`, never a successful historical version result or proof of the new target version.

For this one resource reevaluation, use the authenticated USER entry, original RootLock and same verified physical Root/DB. Read every original C column and NULL exactly: operation key, ticket, nonce, nonzero PID/full creation FILETIME, image path/digest, exact `managed-cli-{driver}` profile, global domain, positive generation, STOPPED state and original stop hash in its writer/schema shape. Keep the operation and hash as uninterpreted stored data. Verify the C image/digest against the exact same-Root official stage, compiled catalog and archive/image pin, plus the original registration, SOURCE and F switch relations of the selected copy and participating instances. Reject a removed old stage, wrong or ambiguous current file/reparse/source, or any missing relation; a current matching hash does not prove that the historical file was never replaced. ## Permitted proof composition

The F qualification view may compose the following three existing evidence kinds. The distinct proposed fourth kind below remains ineffective unless Owner explicitly approves D-NOLAUNCH and this same reviewed proposal is merged and exactly read back:

1. `ORIGINAL_STOP`: the original producer's complete StopFact/StopProof and exact C/H/F/identity associations. A stored STOPPED label or proof-shaped string alone is insufficient.
2. `EXACT_GONE`: an existing sealed `NativeProcessHoldersGone` observation, after trusted native source association proves that its exact PID/full-creation identity set covers the complete affected execution.
