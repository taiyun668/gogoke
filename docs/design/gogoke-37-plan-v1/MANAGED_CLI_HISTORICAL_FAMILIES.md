## Purpose and bounded scope

For each of `claude`, `codex`, and `opencode`, native code shall enumerate the complete finite set of original historical resources that can affect the driver's selected managed copy or any instance participating in its version action. The proposal covers all three drivers in one scope inventory. Each actual action remains a separate authenticated USER operation for one original physical Root/database, one driver, one request ID, one operation, and one compiled target version. It is not a bulk three-driver transaction.

The permitted exception is a read-only qualification view for that version action. Complete original producer association and an original StopFact/StopProof or an existing complete exact-identity/kernel-reboot fact may re-evaluate the corresponding historical execution occupancy. Only if Owner explicitly approves D-NOLAUNCH may its distinct sealed original-unstarted-boundary fact re-evaluate the exact corresponding H resource; that fact settles no pre-boundary or other execution/F effect. None of these facts changes the original success, failure, UNKNOWN, delivery, claim, HOME or stop outcome.

The caller may identify the requested driver and action through the existing USER frame. It may not choose a subset of historical blockers, supply a process list, SID, path, count, proof boolean, or claimed absence. Native code derives membership, identities, associations, and proof sources from the original verified authority and trusted producers. Missing, ambiguous, unowned, or unrecognized members refuse qualification. A query failure is not an empty result.

## Permitted proof composition

The F qualification view may compose the following three existing evidence kinds. The distinct proposed fourth kind below remains ineffective unless Owner explicitly approves D-NOLAUNCH and this same reviewed proposal is merged and exactly read back:

1. `ORIGINAL_STOP`: the original producer's complete StopFact/StopProof and exact C/H/F/identity associations. A stored STOPPED label or proof-shaped string alone is insufficient.
2. `EXACT_GONE`: an existing sealed `NativeProcessHoldersGone` observation, after trusted native source association proves that its exact PID/full-creation identity set covers the complete affected execution. It must be revalidated against the same set. It does not independently prove unknown descendants, namespace retirement, ACL revocation, or admission release.
3. `KERNEL_REBOOT`: an existing sealed `NativeLegacyHoldersGone` observation whose direct kernel cutoff covers the original execution, with complete original source association and fresh native validation. No wall-clock age, timeout, grace period, or requested reboot is a substitute.

These labels describe F's consumption of existing proofs; they do not create new proof producers or permit reconstruction of sealed native facts from serialized bytes. Persisted action bytes are a source binding and reconciliation record. Every later operational qualification must rebuild the current associations and obtain or validate the applicable original/native evidence.

The existing single-unit COLD representation shall not be silently reinterpreted as an arbitrary family. The internal F representation and codec must explicitly identify every member and proof kind, preserve original associations, reject duplicates or ambiguous membership, distinguish null from empty, and reject unknown encodings. Members are ordered canonically by original identity, not caller order. An empty list must never be accepted as a gone proof. A family relying solely on original StopProofs must remain explicitly typed as such; it must not claim a kernel or exact-disappearance observation it did not perform.

D-NOLAUNCH below proposes a fourth, separately Owner-gated original-boundary fact. It is not currently authorized or observed. Existing unstarted-release APIs remain effectful and may not be called to manufacture a read-only proof. No old-namespace-disappearance or other new OS proof is proposed: the existing alias observer only verifies a present same-namespace mapping and cannot be relabeled as absence. Missing namespace or complete child provenance stays refused; a conditional gap entry is not permission to invent a producer.
