**日期：2026-09-18｜状态：施工规划，未执行代码修改或真实 CLI 测试**

“全量”指覆盖整个产品能力面及 UI、状态、服务、协议、进程、存储、权限、远程、构建发行的改造闭环；不把本次抽查的文件数冒充最终变更文件数。WP00 必须生成逐入口、逐符号、逐数据键的机器清单，补入本表未命名但扫描发现的能力。不能用“后续扫描”省略本文已经确定的责任、顺序与验收。

## 1. 完成后应得到什么

得到的仍是可用的 gogoke：原有屏幕、编辑与开发工具继续工作；会话、消息、队列、状态、资源和机器管理成为产品公共能力；Codex 可以作为可选执行接入，但不再是壳的默认身份、公共存储根、唯一协议和启动前提。

必须同时成立：

1. **有 Codex 时不退化**：既有有用能力继续可用，不能用“通用化”将其削成最小共同集。
2. **没有 Codex 时不空壳**：公共工具、已导入历史、资源和设置可用；经真实非 Codex CLI 完成模型工作流，不能只展示空页面和 mock。
3. **屏幕归产品**：分屏、副屏、侧栏、Session 不因哪个 CLI 实现而被删除；职责与窗口、原生线程、PID 分离。
4. **原生差异有边界**：必要的 Codex 协议、登录和配置封装在可选适配器；没有公共用途的专属 UI/默认项退出公共本体。
5. **迁移不伤数据与机器**：旧历史/草稿/提示词/设置可核对、可恢复；没有两条链同时控制一个会话，没有清空用户家目录或卸载官方 CLI 的步骤。

### 本专项不扩张的范围

不重画整个 UI，不更换 Tauri/React/Rust/现有终端与 Git 栈，不整体引入 Codex Core，不新造多 Agent 编排引擎，不恢复老 Room 或旧内核，不借去专属化接入一套新的付费 API/统一账号体系。主控如何派工仍归主控；本专项提供可承载不同职责的会话、实例、作用域和机器能力，不把目标管理全栈施工捆绑为前置条件。

既有语音使用的 Whisper 等资产不能仅因出自 OpenAI 就误删。“剥离 Codex”也不等于清除开发仓库中的 `AGENTS.md`、`.codex` 或第三方来源声明。

## 3. 取舍方法：五种处理，不按文件名字删除

| 处理 | 含义 | 删除条件 |
|---|---|---|
| 保留 | 已经通用，保持实现和体验。 | 无删除理由。 |
| 内化 | 实现可复用，只将身份、数据、入口和依赖改归 gogoke。 | 只删除替换后失效的专属接线。 |
| 替换 | 需求有公共价值，但当前实现仅适用于 Codex。 | 新实现通过能力等价与故障回归之后删除旧实现。 |
| 适配保留 | CLI 协议/登录/参数等必须存在，但仅为 Codex 服务。 | 退出公共层，留在可选适配模块；不等于删掉 Codex 接入。 |
| 移除 | 仅为 Codex 专属、无公共需求，或已经无剩余调用。 | 确认没有能力、数据、迁移或开发用途，并有差异说明。 |

`thread`、`turn`、`session` 不是一看到就得消灭的词；真正要检查的是语义、依赖和权限。代码移目录、批量改名、按钮隐藏、返回 unsupported，均不能独立证明完成内化。

## 4. 目标结构：在现有机器上拆接线，不另造整台机器

逻辑方向为：**现有 UI/工具 → gogoke 公共服务与会话存储 → 公共宿主/进程工具 → 可选 Codex 或其他 CLI 适配器**。本地 Git/文件等无模型动作可继续走已有本地桥，但模型控制统一进公共执行服务，不能从 UI 绕开它。

### 4.1 复用优先的文件安排

| 现有区域 | 处理与拟增落点 |
|---|---|
| `src/types.ts` 与 `src-tauri/src/types.rs` | 保留公共片段；按需要拆公共 Session/Execution/Resource 合同，原生类型进提供方命名空间。 |
| `src/services/tauri.ts` | 保留文件选择/窗口/系统工具等公共桥；模型操作逐步转 `src/services/agentClient.ts`（拟新增）。 |
| `src/services/events.ts` | 保留单监听分发；输入改为公共事件，原生帧不再进入公共 hooks。 |
| `features/threads/messages/composer/layout` | 优先改 hooks 和数据绑定，保留组件/CSS/编辑行为；不要求整目录改名。 |
| `shared/*` | 继续是桌面与 daemon 的公共实现；拟增 `sessions_core`、`execution_core`、`capabilities_core` 与小型 `session_store`。 |
| `codex/*`、`backend/app_server.rs`、`shared/codex_*` | 收拢到拟定 `providers/codex/*`；成熟函数可逐步迁移，短期薄包装明确归属，禁止反向污染公共服务。 |
| `shared/process_core.rs`、terminal、daemon | 内化已有进程和传输能力；只补实例归属、恢复、停止、世代与单所有者，不另造一套总控。 |
| 现有 settings/workspaces JSON | 保留并版本化；新增事务存储不要求重做全部配置。 |

拟增路径是责任分区，不声称已经存在；Builder 可以用更少文件实现，但不能改变边界或少做能力。

### 4.2 最小公共对象与操作

| 对象 | 最低字段/语义 |
|---|---|
| Session | 产品 sessionId、作用域、可选 seatRef、隐私域、标题、生命周期；不等于 PID 或原生线程。 |
| NativeBinding | driverId、instanceId、profileId、nativeSessionId、bindingGeneration、恢复方式；原生 ID 不能全局裸用。 |
| ViewBinding / ComposeTarget | paneId 与固定 scope/session/隐私/意图；提交时后端重新核验，不相信 UI 当前活动项目。 |
| Execution / Delivery | 产品 executionId、operationId、目标、状态、原生关联及必要核对信息；投递回执与实际执行分开。 |
| PublicEvent | schemaVersion、eventId/顺序、Session/Execution/世代、类型与受控 payload；内容和机器状态分开。 |
| Resource / HumanAction | 资源来源/版本/作用域；请求目标、有效期、允许回答和许可范围。 |
| CapabilityDescriptor | 实例与版本绑定的能力、限制、原生/宿主实现方式；unknown 不等于支持。 |

公共操作包含创建/读取/归档会话、提交/排队/补充、请求停止、回答原请求、查询实例能力、订阅/恢复事件、资源管理和受控辅助生成。命名可贴合现有代码，不要求再写一套通用 SDK。

登录凭据、原生协议帧和任意扩展配置不进入公共消息对象。公共前端不能出现“Codex 就 steer，其他就 send”的业务分支。提供方专属设置可以有隔离的高级区，但不能因此赋予 Codex 独有的公共产品入口。

## 6. 保留能力的语义底线：不能用弱实现冒充等价替换

### 6.1 发送、插话与停止

排队意味着稍后消费；原生 steer 意味着对当前活动执行补充输入。公共服务必须保留意图差异；驱动不支持时不能悄悄改成排队并报“已插话”。同样，RPC 接受停止请求只证明请求已受理，实际停止要有执行状态证据。官方当前文档也将 turn/start、turn/steer 与 turn/interrupt 区分，协议能力随 CLI 版本核对。[S18]

响应丢失时记录“接受结果未知/待核对”，先查原生状态或要求安全恢复；不能为让页面变绿自动重发。产品保证持久登记、可核对与不盲重放，不虚构能对任意 CLI/外部工具副作用做到绝对 exactly-once。

### 6.2 分支、压缩、审查与侧聊

产品分支先固定来源和可见内容。跨 CLI 新建会话＋附带历史材料是一种快照续聊，不是复制全部原生隐藏状态。历史复制要重新核验权限，不能把 Owner 私聊自动带进公开审查。实际 context compact、摘要和界面折叠是三件事；都可以有用途，但不能互相冒名。

Review 保留为公共能力：选材料、固定版本、选实例、执行、展示结果。原生 Codex review 可留为实现之一，但不是公共审计身份、目标验收或合并许可。侧边屏/侧聊由 gogoke 会话与视图实现，不以 `/side` 的存在作为前提。

### 6.3 工具、权限、资源与附件

公共批准卡必须对应实际约束。驱动只提供弱权限机制时，不得把同名枚举或提示词当作等价隔离。仅给公共 UI 接上“只读”字样不够。新增 OS 沙箱不是本计划默认大工程；应复用并验证既有边界，无法满足承诺的执行仍列为缺口且不越权放行。

同一图片/文件在不同 CLI 必须维持已承诺的内容语义；支持格式、转换损失、长度限制需显式。未知格式保留为资产，不默默把文件名当内容。模型的推理摘要展示只能使用原生实际提供的内容，不能制造不可获得的内部推理。

### 6.4 能力对等不等于删成最低共同集

先确定 gogoke 公共需求，再选择复用、适配或宿主替代。不能因为某个 CLI 暂不支持，就把有用公共功能从产品删除。未补齐的共同能力记入缺口并阻止本项完成；原生特有能力可以隔离为扩展，但不能伪装成公共通用能力。三家目标接入地位对等，功能是否已交付取决于实际证据，不由静态 capabilities=true 决定。

## 7. 施工工作包（14 个，全部有输入、输出、验收与退路）

每个工作包是实施责任，不代表要创建 14 套治理卡、分支或审批流程。可以合并紧密相关的小改动，但不能合并后丢失验收。一次普通交付记录足够说明能力变化、测试和剩余项，不另建“审计的审计”。

### WP00｜锁基线与能力保全账本

**依赖：** 无。

**主要落点：** 仓库只读扫描、全部产品入口、现有测试、设置键、IPC/RPC、子进程与外部命令。

**施工：** 固定开工 commit 和本地未提交差异；按 C01–C40 做 UI→hook→service→command→shared→native/磁盘的全调用链登记。对每一行填现状、来源文件/符号、现有证据、替代责任、验收用例。补全 README 未列出的入口；发现新增能力就增加行，不能挤入“其他”后遗漏。先录基线截图、键盘路径、无害 fixture、历史样本和构建表现。

**交付：** 保全账本、入口/依赖清单、基线测试记录；未验证项明确标注，不用旧 README 的功能描述冒充运行通过。

**通过条件：** 每个已存在入口有处置项；每个声称保留的能力有前后对照测试。没有实际证据的项目列为待测，而非删除候选。

**保全与回退：** 只新增测试/记录，不改产品执行行为；遇到历史缺陷单独登记，不能把缺陷顺手变成大重构。

### WP01｜公共边界与最小合同

**依赖：** WP00。

**主要落点：** src/types.ts、services/tauri.ts、services/events.ts、Rust types/lib/shared。

**施工：** 从现有类型中挑出通用部分原位保留；新增 SessionRef、NativeBinding、公共命令/事件、CapabilityDescriptor。公共 UI 不接收 Codex 原生 payload。Tauri 保留系统功能桥，模型操作进入一个公共服务。新增小型依赖边界检查，识别导入、命令注册和运行入口，不以 grep 零 codex 为目标。

**交付：** 可编译的公共类型/API、版本与错误约定、适配器接口以及两种不同形状的测试驱动。

**通过条件：** 测试驱动不用 thread/turn 命名仍能走消息全链；公共 UI 不分支判断 provider 字符串；协议异常不能穿透成任意权限动作。

**保全与回退：** 新边界先包住旧实现；不更换打包器/测试框架、不批量移动全部类型。

### WP02｜产品 Session 与最小持久存储

**依赖：** WP01。

**主要落点：** threadStorage、thread reducer、Rust state/storage、拟增 sessions_core 与 session_store。

**施工：** 给公共会话稳定产品 ID，原生 ID 保存在复合映射中；补 scope、seatRef、privacyDomain 和 bindingGeneration。保留现有消息展示及 UI 元数据。新增小型事务存储保存会话映射、投递记录、事件游标和迁移进度；本计划优先选 SQLite，仅用于这些数据，不重做 settings/workspaces。P0 若发现可直接复用的事务存储，以同样故障验收证明后复用。

**交付：** Session 存取、只读历史投影、独立草稿/别名、可重复迁移工具和小样本导入。SQLite 是拟新增选型，不声称当前依赖已存在。

**通过条件：** 关闭重开仍是原产品会话；两个实例原生 ID 相同不碰撞；同一账号多会话隔离；迁移重跑不重复；本地缓存损坏不丢权威绑定。

**保全与回退：** 原 settings/workspace 文件保留；原生历史不改写。旧新索引对照只读，不做两边同时可写。

### WP03｜内化机器并封装 Codex 接入

**依赖：** WP01/WP02。

**主要落点：** backend/app_server.rs、codex/*、shared/codex_*、process_core、state、gogoke_daemon。

**施工：** 将原生客户端、启动参数、握手、ID、history/auth/config/usage 封入 Codex 适配模块。保留成熟进程工具；长期模型执行优先复用现有 daemon 承载，桌面不再独立持有另一份相同会话执行权。共享代码不等于共享所有者：启动、重连、退出均校验宿主身份与世代。同一数据域只有一个 writer/执行宿主。

**交付：** 可独立启用/停用的 CodexDriver；通用实例生命周期；子进程归属、健康状态和停止接口。

**通过条件：** 原 Codex 正常会话仍可用；无 Codex 时壳启动；切换/关闭一个 Session 不杀其他实例；桌面与 daemon 不能双发。进程崩溃/超时后不虚报完成。

**保全与回退：** 先保持原原生协议与可用版本，不边搬迁边升级 CLI；不另建第二套 Python/Node 总控，不整体引入 Codex Core。

### WP04｜打通发送、流式、队列、批准和停止

**依赖：** WP02/WP03。

**主要落点：** useThreadMessaging、thread event hooks/reducer、AppServerEvents、公共 execution_core。

**施工：** 公共 UI 提交固定收件对象的意图，宿主持久登记后再调用驱动；分开队列、立即补充、中断等操作。原生事件在适配器内归一化，公共事件有序号、投递 ID 和世代。批准/追问保留原请求绑定；控制请求不排在普通聊天队列后。处理乱序、重复、迟到、断流与接受结果未知。

**交付：** 首条可用纵向链：旧界面→公共服务→CodexDriver→归一化事件→旧消息组件；并有失败路径。

**通过条件：** 发一条只产生一个受控投递记录；失联重启不盲重放模型调用；过期批准不可生效；停止请求成功和实际停止分开；未知事件不丢已知附件/工具结果。

**保全与回退：** 每个 Session 只选新链或旧链的一个执行所有者；灰度按数据副本/会话路由，绝不把真实请求双发以比较结果。

### WP05｜内化屏幕、导航与多会话交互

**依赖：** WP04。

**主要落点：** MainApp、AppLayout、Desktop/Tablet/PhoneLayout、composer/messages、sidebar、notifications。

**施工：** 保留原视觉组件和尺寸逻辑；改数据接线。每个 pane 有独立 ViewBinding、焦点与 ComposeTarget；双输入框独立草稿/附件。保留 chat+diff，同时补公共会话绑定。主控/审计/秘书长作为职责与作用域引用，不借用 Codex agent role。修复托盘/深链接/快捷键的原生 ID 假设。

**交付：** 界面前后对照；双会话和项目切换样例；窗口恢复、键盘导航与隐私显示测试。

**通过条件：** A 屏输入绝不发给 B 屏；切项目不改变全局秘书长的历史归属；关侧栏不终止模型；同一 Session 多视图不重复执行；既有布局视觉不退化。

**保全与回退：** 不同时重做设计系统/导航架构；没有独立证据的副屏能力明确为本次必要补齐，不当作旧功能已经完成。

### WP06｜替换有公共价值的高级工作流

**依赖：** WP04/WP05。

**主要落点：** review、fork、compact、plan、collaboration 与模型活动入口。

**施工：** 将 Review 改为固定材料＋指定公共会话；将产品分支、上下文整理、侧聊的意图和记录内化。保留原生可实现效果作为适配能力；无法等价的地方给出明确差异和补齐任务。原生 subagent 的内部事件不产生公共席位的权限或调度权。

**交付：** 每项原入口→新工作流→结果与限制对照；对应的正向、负向和跨驱动测试。

**通过条件：** Queue/Steer、折叠/Compact、快照续聊/Native Fork 均被区分；审查不偷换材料；隐藏某按钮不算保留能力。公共功能缺口未闭合时不能签最终完成。

**保全与回退：** 原功能在新实现同样可用前不删；原生特有能力可留有边界的“提供方扩展”，不伪装成通用合同。

### WP09｜实例、模型、登录、额度与设置分层

**保全与回退：** 不统一跨厂商凭据，不按邮箱合并账号；不静默更新 CLI 或替用户登录。

### WP10｜贯通 daemon、远程、移动和恢复

**依赖：** WP03/WP04/WP05/WP09。

**主要落点：** daemon rpc/*、remote_backend、events、mobile、tray、daemonctl/退出路径。

**施工：** 桌面/远程统一命令语义与会话所有者。补协议协商、授权范围、事件游标、缺口快照恢复；对 broadcast lag 等情况显示重同步。关闭 UI 与宿主退出策略明确，沿用并验证 keepDaemonRunningAfterAppClose。旧客户端拒绝执行或薄转发同一公共入口。

**交付：** 本地/远程合同测试、断线重连演示、旧客户端行为表、移动遗产回归范围。

**通过条件：** 远程不能绕过新边界；旧请求不创建第二运行时；UI 重连不重发已执行消息；未测试平台保持既有 WIP 标记，不报跨平台完成。

**保全与回退：** 平台无法测试要公开列为未验证；既有已承诺远程能力不能通过永久关闭来完成“保留”。切换前可在隔离测试环境暂停旧入口。

### WP11｜无 Codex 与真实异构接入验证

**依赖：** WP04/WP05/WP07/WP08/WP09；远程部分依赖 WP10。

**主要落点：** 拟新增 feature/依赖边界测试、驱动 conformance、Windows 应用演示。

**交付：** 无 Codex 运行证据；真实非 Codex 发送/工具/追问/恢复/辅助生成等矩阵；现有 Codex 回归。

**通过条件：** 不是回显假驱动，也不是非 Codex 按钮背后再用 Codex；未通过的共同能力仍记缺口，不为“最低共同集”删产品功能。

### WP12｜全量数据迁移、安装更新与回滚

**依赖：** WP02/WP05/WP07/WP09/WP10/WP11。

**主要落点：** 旧 localStorage、settings/workspaces、原生历史索引、安装包/更新器/发行脚本。

**交付：** 旧数据升级样本、失败恢复记录、安装/升级/回滚包和 README；新旧数据 schema 兼容声明。

**通过条件：** 历史/草稿/名称/置顶/提示词/权限映射不丢；旧原生资料未破坏；回滚不会把升级后新数据静默丢掉；无 Codex 的干净安装可用。

**保全与回退：** 备份不含不必要凭据；新 schema 不兼容不能直接换旧 exe 开新库。已有新写入须保全导出或经验证逆迁移，不得直接覆盖恢复。

**主要落点：** 旧原生公共入口、无调用代码、公共默认配置、CI、docs、NOTICE 与迁移薄层。

**交付：** 最终能力保全账本、删除/保留差异表、所有测试证据、已知限制与可运行安装包。

**通过条件：** 没有孤儿入口、隐藏损失、未迁移数据写入、第二控制链或没有理由的保留专属耦合；文件数统计与实际提交一致。

## 9. 数据迁移施工细则

### 9.1 必须盘点的数据

| 数据 | 迁移方法 | 必须保留 |
|---|---|---|
| workspace/settings JSON | 版本化读取与增量字段映射，不重建目录。 | 项目 ID、路径、分组、脚本、窗口/外观等原设置。 |
| 旧 localStorage | 导出后逐键映射产品 Session；允许保留只读兼容 alias。 | 名称、置顶、活动时间、草稿、附件引用和原参数。 |
| 原生会话与历史 | 先只读索引/预览；仅导入获准内容并建立来源引用。 | 原生文件、账号/实例来源、未导入项与原因。 |
| 全局/项目 prompts 与 rules | 同名冲突显式处理；公共副本写 gogoke 根。 | 原文/版本/作用域；默认不删除 Codex 原文件。 |
| Agent 配置 | 提取可公共化模板；专属字段进 provider extension。 | 原配置备份、无法映射的字段，不 silently drop。 |
| Usage | 标记历史来源和导入边界，与实时事件去重。 | 原单位、时间范围、账号范围、未知值。 |
| 待发送和在途动作 | 先停新入口，再核对到可切换状态。 | 未知接受结果，不能迁移成“待重试”自动执行。 |
| 账号凭据 | 不迁移秘密，仅迁移经过验证的引用/标识。 | 官方登录状态不被修改、泄露或合并。 |

### 9.2 实际顺序

备份与完整性校验 → 只读预览及冲突清单 → 停止该数据域的新写入/新执行 → 核对或安全停靠在途任务 → 建立映射和事务提交 → 校验会话/关系/内容 → 切换唯一所有者 → 使用新路径验证 → 保留旧数据和迁移报告。

导入不能把所有旧 Codex 历史默认分给主控，也不能自动分享给审计或秘书长。原生历史不应被额外改写。未导入历史保持可列出与可解释；无 Codex 时应能读已导入公共历史，但没有原生绑定不意味着可无损恢复其模型状态。

### 9.3 故障与回滚

至少在备份后、映射开始、部分记录写入、事务提交、索引生成、所有权切换、首次启动七个点注入故障。每次重启须识别迁移状态并恢复或退回安全旧路径；不能用“读失败则返回空对象”掩盖数据损坏。

切换前回退可恢复旧版本与原数据；切换后若有新增数据，先保全新数据，再用验证过的逆迁移/兼容导出回退。旧程序不认识新 schema 时，不允许直接拿旧 exe 打开新库。回滚不允许静默覆盖新会话、草稿和结果。

## 10. 桌面、daemon 与真实进程的边界

长期执行优先复用现有 gogoke daemon；公共服务和进程工具是同一套实现。Tauri 命令是入口而非另一份长期会话权威。本地/远程模式可以保留，但同一数据域的会话、队列和原生执行只有一个宿主所有者。

宿主需记录实例/配置/会话归属与有效世代；对启停、重连、退出核对实际子进程状态。显示 PID 只是诊断，不是长期席位身份。桌面关闭后继续运行由明确设置控制；选择继续运行要由独立宿主真实承载，不能凭前端状态承诺。

Windows argv、cwd、env、标准输入、编码和进程树处理优先继承成熟实现。为重构统一接口而改成 shell 字符串拼接、整树乱杀或继承用户全部环境，均不允许。用户终端可以有自主操作，但不能给受限 Agent 提供绕过路径。

重连恢复先订阅状态和缺口补齐，不自动重放所有 UI 命令。新的公共事件需要游标/序号与快照恢复；不能只把旧 `app-server-event` 改名就认为具备可靠恢复。

## 12. 旧入口退出与删除准则

一个删除项必须同时回答：原能力是否还需要；需要则由谁替代；旧数据由谁读取；本地和远程还有没有调用；回归证据是什么；回滚是否还需要它。

符合以下全部条件才删除：对应公共能力已通过；该入口无剩余调用；原生专属能力已在适配器或确实不再需要；数据迁移已验证；旧客户端不会绕回；删除后公共构建及完整回归通过。

临时兼容 wrapper 可以保留，但只能调用同一公共服务，不得另行 spawn/resume/send。每个 wrapper 有明确使用者和退出条件。不能用新的 Session ID 与旧原生 ID 两套入口同时拥有写权。旧原生代码即使保留在仓库，也不能继续占据公共默认产品身份。

### 残留字符串/依赖允许表

允许位于已隔离 Codex 适配器、其诊断/高级设置、原生 schema/fixture、历史迁移兼容、许可证/来源与开发文档。公共服务可以通过注册表解析 driverId，但不得包含原生协议分支。命中搜索只是待分类线索，不是自动删除授权。

不允许留在公共启动前提、默认模型硬编码、公共资源根、公共事件解析、公共运行状态、UI 原生调用或未迁移 daemon RPC 旁路中。

### 明确不做的破坏性清理

不删除 Owner 的 `.codex`/`CODEX_HOME`，不卸载官方 CLI，不清空聊天或工作区，不清理用户 worktree，不删除许可证和第三方来源，不为了干净构建删除未备份用户数据，不擅自改仓库设置或发布安装包。
