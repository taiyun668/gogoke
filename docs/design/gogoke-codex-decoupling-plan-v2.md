# gogoke：Codex 去专属化与公共能力内化全量施工计划 V2.0

**日期：2026-09-18｜状态：审计复核后的施工规划，不是代码实现或运行验收完成声明。**

**目标：公共能力留在 gogoke；可复用的原位内化；必须替换的先交付替代实现；Codex 原生差异收进适配边界；最后才删失效接线。不能把机器拆空，也不能把旧机器的错误假设一起继承。**

本文件完整替代 V1 的施工安排，可独立阅读。保留 V1 和 Claude 审计原件，便于追踪，不需要把三份文档拼起来才能开工。本文包含 41 个能力族、17 个责任工作包、64 个验收场景族；这些是计划编号，不是变更文件数、已通过测试数或工作量估算。

### 0.2 本专项采用的产品边界

直接用户要求优先：保留能力，内化公共项，替换专属实现，不做单纯删除。在不冲突的部分，采用已定位仓库记录的具体范围：

- 目标接入为 **Codex、Claude Code、Grok Build、OpenCode、Antigravity CLI** 五家。按实际版本逐家验收，不能用“至少一家非 Codex 能跑”冒充五家完成。
- **远程访问和语音输入首版暂时关闭，封入口但不删代码、配置和缓存。** 这是产品暂缓，不是它们属于 Codex，也不是“永久禁用就完成内化”。本地宿主必须继续工作。[R03]
- Owner 的直接对接面是项目主控、项目审计、全局秘书长；施工席位向主控负责。主控与 Owner 的私有对话不能自动下发给施工席位。项目审计的私人侧聊与正式干净审查分别管理。[R03][R04]
- 保持现有 UI 与工具体验；首版以代码生产为范围。不增加通用成果页、例行验收按钮、费用／低进展闸门、老 Room 调度权威或一实例一席位规则。[R03][R04]
- 本专项只补齐承载这些功能所需的会话、资源、投递、进程和权限边界，不重做多 Agent 编排引擎，不整体引入 Codex Core，不重写 React/Tauri/Git/PTY，不新建统一工具网关。

仓库记录中“界面形状可复用、产品能力为零”“三家已经做完”等概括不能直接作为工程事实。应分别核验已有组件、公共机器能力、原生协议能力及尚缺的产品能力。也不能把“另一个进程／另一家模型”直接当成审计独立性的充分证明。

## 2. 完成终点与取舍规则

### 2.1 三个同时成立的终点

**保能力：** 原有有用能力有逐入口对照，公共功能不因某家能力弱就被删成最低共同集；已有缺陷单独标注，不冒称功能保全。

**去专属：** 不启用 Codex 适配器、没有 Codex 二进制和登录时，公共工具、已导入历史、设置及资源可工作；其他目标 CLI 经同一产品合同运行，不在后台借 Codex 完成。

**可迁移：** 旧历史、草稿、提示词、设置、缓存与运行归属可核对、可恢复；不存在两套链路控制同一原生会话；没有静默改账号／模型／权限或清用户家目录的步骤。

五家是目标清单，不是本轮已支持声明。首版暂缓项保持封存状态且不阻塞非依赖它们的本地施工；五家能力未验完时不得宣布“五家全部适配完成”。

### 2.2 六种处置

| 处置 | 含义 |
|---|---|
| 保留 | 已通用的实现原位保留，只补回归。 |
| 内化 | 保留可用实现，将身份、数据、权限和入口改归 gogoke。 |
| 替换 | 公共需求有价值，但旧实现专属或不满足边界；先实现替代，再退旧路。 |
| 适配保留 | 原生协议、登录、参数等留在可选驱动，退出公共本体。 |
| 封存保留 | 由明确产品范围决定暂不开放；保留代码、数据、说明和恢复条件，不算活跃功能验收通过。 |
| 移除 | 无公共价值、无剩余用途或已被可靠替代的接线／代码；须完成删除对账。 |

改名、搬目录、隐藏按钮、返回 unsupported、grep 零 Codex 命中都不是完成标准。不得为了让删除表“有数字”删除能力。开发用 AGENTS.md、.codex、第三方声明和 Whisper 等非 Codex 资产不作连带清理。

## 3. 资产复用账本：先利用，再补齐，不整体照搬

### 3.1 扫描边界

WP00 必须扫描 `apps/desktop/`、`packages/seat-runtime/`、`packages/room/src/`、`packages/protocol/`，以及被它们实际调用的 `crates/`、`tools/`、根构建与发行配置。研究／演示与生产代码分别登记，不因同仓存在就成为生产依赖。

审计称有十三个不依赖 server.ts 的 Room 模块；本轮没有把“十三个”和约 4,700 行当作逐模块已验证结果。开工扫描须输出实际模块名、直接和传递依赖、运行副作用、许可证、测试以及取舍，不能用“不 import server.ts”推定没有 Room 语义耦合。

`@gogo/seat-runtime` 的 package.json 声明 Node >=24、导出 dist、许可证 AGPL-3.0-or-later。[R12] “自有旧仓库”和“无 npm 运行依赖”都不能替代权利、贡献和分发范围核对。本计划不作重新许可结论，也不将未解决来源问题的代码悄悄混入桌面包。

### 3.3 跨语言实现决定

沿用现有 Rust daemon 作为产品会话与机器管理的唯一权威。**优先让成熟 Rust Codex 适配留在 Rust，让值得复用的 Claude/Grok TypeScript 协议代码通过受限的协议 worker 接入同一合同。** 这不是启动第二个 Room 服务，也不是再写一个 Node 总控。

worker 只做已分配连接的协议编解码和受控原生操作，不自行选实例、持久化产品队列、跨项目寻址或决定授权。Rust 宿主管理 root、binding、lease、投递与停止；原生进程只能由已登记路径启动，worker 创建的子进程也须登记并纳入真实收尾。

WP03 必须做最小可运行样本，核对 Node 固定版本、bundle、启动成本、stdin/stdout 帧、进程回收、Windows 路径、许可证和安装包。能够复用的尽量复用；若某段因打包／权利／隔离不可接受，保留协议 fixture，仅局部移植必要逻辑到 Rust并做相同语义测试。不得两套生产驱动同时控制一个绑定，也不得仅因语言不同就全量重写已有资产。

## 4. 公共结构与五家适配边界

### 4.1 依赖方向

**现有 UI/公共工具 → 公共 Session/资源/投递服务 → 现有 Rust 宿主 → 可选原生适配器。**

Tauri 继续负责窗口、选择文件、系统通知及本地命令桥；`src/services/events.ts` 继续承担单监听分发。模型控制进入一个公共服务，而不是散落在多个 UI hook 中。已有 shared 核心是优先落点，不要求整目录改名或新增通用 SDK。

| 接缝 | 具体落点和改变 |
|---|---|
| 公共类型 | 保留 `src/types.ts`、Rust `types.rs` 的可用片段；拟增公共 Session/Delivery/Capability 类型，原生类型按适配器隔离。 |
| UI 调用 | `useThreadMessaging`、AppServerEvents、thread reducer 改接公共服务；拟增 `src/services/agentClient.ts`，系统工具仍用 `tauri.ts`。 |
| UI 组成 | MainApp/AppLayout/layout/messages/composer/侧栏保持现有组件和 CSS；只按能力需要补绑定及少量入口。 |
| 公共后端 | `shared/sessions_core`、`execution_core`、`capabilities_core`、最小事务存储是拟增职责，可复用已有文件实现。 |
| 原生后端 | `codex/*`、`backend/app_server.rs`、`shared/codex_*` 可逐步归入提供方边界；短期 wrapper 仅转发同一实现。 |
| 旧 TS 接入 | `packages/seat-runtime` 中被选中的模块进入受限 worker；具体目录名由 WP03 锁定，不整体 import Room。 |
| 进程与传输 | 复用 daemon/process_core/terminal；补唯一所有者、实例和配置键、真实停止、版本协商及本地重连。 |

### 4.2 最小公共对象

| 对象 | 必须表达的含义 |
|---|---|
| Session | gogoke 长期会话 ID、scope、可选职责引用、privacyDomain、标题和生命周期；不等于 PID、原生 thread 或窗口。 |
| NativeBinding | driverId、instanceId、profileRevision、authRevision、nativeSessionId、generation、continuationMode；原生 ID 不能裸作全局键。 |
| Execution/Delivery | executionId、operationId、固定目标、状态事实、原生关联、必要核对证据；一次投递和一次执行不是同一个确认。 |
| ViewBinding/ComposeTarget | paneId、固定 Session/作用域/隐私域/意图、版本；后端再鉴权，不相信前端当前活动项目。 |
| PublicEvent | schemaVersion、受控对象引用、序号或游标、generation、事件类型、来源与裁剪后的 payload。 |
| CapabilitySnapshot | 二进制来源/摘要/版本、运行模式、平台、实例和认证配置版本、测得能力、限制、证据时间与 unknown。 |
| ContextPackage | 接收者、获准材料及固定版本、用途、可见性、来源引用和权限；不自动包含父对话。 |
| HumanActionRequest | 原请求及 continuation、目标、世代、有效期、可选答案／许可范围；回答不等于普通发送。 |

复合键至少包含数据域、产品 Session 和绑定世代。共享账号不等于共享上下文；多 Session 服务端也不等于同一个 Session；一轮一进程也不等于没有长期会话。原生 thread/turn 词语不必在适配层消灭，但不能决定公共产品语义。

### 4.3 五家协议摸底与真实验收

| 目标 | 已知资产／当前官方线索 | 实施前必须固定 | 禁止预设 |
|---|---|---|---|
| Codex | Rust app-server 客户端与旧 PersistentCodexSeat 两处候选 | 实际 binary、版本、app-server handshake、可用方法、原生历史、权限、恢复和接受证据 | 不因有两处代码就维护两条执行路径；不借搬迁静默升级。 |
| Claude Code | 旧 stream-json 解析、输入验证与 fake | 实际 stdin/stdout 控制形状、请求回答、收据、停止、可恢复性、环境入口及版本 | capabilities=true 不作生产证据；写 stdin 成功不等于模型已接收。 |
| Grok Build | 旧 ACP 适配；官方有 headless/ACP 模式。[W03] | 实际命令参数与 ACP 版本、会话、工具/批准、恢复、权限和用量范围 | 不把旧默认参数当所有版本通用；不与 OpenCode ACP 不经协商共用解析。 |
| OpenCode | 官方当前有 ACP stdio 与多会话机制。[W02] | 用户实际安装版本是否支持所需 ACP、模型/agent/权限、Session 隔离及服务生命周期 | 不把当前 v2 文档直接套在记录中的旧版；不把多模型提供商当多个独立 CLI 身份。 |
| Antigravity CLI | 当前官方支持单次 headless、指定会话续接及 stream-json 常驻多轮。[W01] | `agy` 的实际安装、模式、帧、内容类型、错误/控制限制、原生继续和权限 | 不预先定为一次性，不将 JSONL 自动当 ACP，不因有文本流就宣称所有附件／插话均支持。 |

每家探测分两层：无害本机版本／帮助／配置观察；另有经授权的真实模型调用与受控工具测试。探测不得借机登录、更新、下载模型或产生未授权费用。没安装／没授权／版本不匹配记 `unverified`，不能填 `supported`。

合同定型前，五家都要有形状记录或具体未知清单与可容纳该未知的接口；不能以等第五家装好为理由停止无关工作，也不能不管未知先把公共对象写死。至少覆盖原生常驻多轮、跨进程原生续接、多会话服务端、来源不含 thread/turn 的事件样本。

WP11a 的单条真实非 Codex通路解除早期循环；WP11b 才对五家完整矩阵负责。每个公共功能按“原生支持／宿主补齐／受限但已说明／未实现”记录，保留强实现，不用最弱一家的能力砍掉整个产品。目标范围未全部满足时，不宣布五家完整交付。

## 5. 数据根、身份、隐私和执行边界先落地

### 5.1 数据根的明确决定

保留现有产品 identifier `app.gogoke.desktop` 和 Tauri app_data_dir 作为默认产品根，不因为去 Codex 化又换一次产品目录。[R14][R15][W04]

| 平台 | 默认根的说明 |
|---|---|
| Windows 首发 | 已知文件夹 RoamingAppData 下的 `app.gogoke.desktop`，通常为 `%APPDATA%\\app.gogoke.desktop`。以系统解析结果为准，不手拼用户名称。 |
| macOS 兼容对象 | `$HOME/Library/Application Support/app.gogoke.desktop`，仍以平台 API 为准。 |
| Linux 兼容对象 | `${XDG_DATA_HOME:-$HOME/.local/share}/app.gogoke.desktop`，仍以平台 API 为准。 |
| 显式自定义根 | 沿用明确配置的绝对路径，记录来源和 rootId；移动根走迁移，不接受工作区内容或模型消息暗改。 |

新增最小目录合同：`root.manifest.json`（rootId/schema）、`core.db`（Session/投递/游标/迁移）、`runtime/`（宿主和绑定信息）、`resources/`（公共提示词与模板）、`content/`（按可见性管理的内容）、`profiles/`（非秘密运行配置）、`migration/`（核对与备份元数据）。已有 settings/workspaces JSON 保留，不强制搬成全数据库。

daemon 使用客户端传入并由宿主核验的同一绝对根，独立启动也调用同一个解析器；不得各自从 cwd 推导。对同一实际根的别名、大小写或 junction 不能产生第二所有者。持有 OS 级排他锁并记录 rootId；只创建一个锁文件不算锁已生效。

根解析失败、旧数据库损坏、未知 schema、网络／云同步导致无法保证单写者时，停止写入并给出诊断及显式迁移恢复入口，不静默换到 cwd、空池或新的目录。已位于重定向目录的旧用户数据必须保留，不能未经迁移自动挪走。

运行状态与秘密不能放进项目代码根；对私有内容的访问经服务端授权。缓存位置优先保留已有实际路径并登记引用，尤其语音模型不因新增根合同就重新下载或复制数 GB。更新策略、公钥、允许域名不由导入数据覆盖。

### 5.2 一份身份合同，不继承旧 Room 权威

角色、项目会话、登录实例、运行配置、原生绑定和进程分别记录。一个实例可服务多个席位，物理并发容量与会话隔离分别验证；不能复制凭据来假造多个账号，也不能以同邮箱自动合并身份。

复用连接必须匹配 driver、instance、认证版本、配置版本、作用域与原生隔离能力。旧 connect.rs 的“找到任意活连接就登记新 workspace”不能继续作为公共策略。[R10] 配置变化只作用于新的执行或明确的安全重绑，不改变在途执行。

宿主租约／数据库 generation 不是万能撤权。切换 writer 之前，须封闭旧输入与控制路径，核实旧进程和持有的工具执行；旧执行仍可能写入时，新链不得接管同一写域。不能用租约过期或 heartbeat 丢失证明原 CLI 已经停止。

### 5.3 上下行隐私都属于机器能力

Owner 与主控的主对话默认只对其授权域可见。派工只发送本次明确任务及获准材料，不发送父 transcript、原生 fork、全局记忆或隐含摘要。施工结果回主控，施工席位的问题按既定规则交主控；真正的原生权限／输入请求仍保留原 continuation，不能丢弃或假回答。

项目审计的 Owner 私聊与正式审查保持不同内容域与原生历史；正式独立审查使用干净、可说明来源的材料和会话。秘书长是全局身份，但“全局”不代表默认可读所有私聊或凭据。分享只携带选定文字／附件及来源，不携带整段侧聊。

隔离需要同时覆盖：prompt/stdin、原生历史、规则加载、cwd、HOME/profile、可读文件、缓存、日志、通知、导出、MCP/插件与恢复。换一个进程或另一个模型并不会自动封闭这些路径。

T49 使用每轮随机高熵标记和明确的可见／不可见材料，检查实际发送的字节和可达资源，另设获准共享正向对照。模型能答出未授权标记是失败证据；模型答不出不是通过的充分证据。测试记录本身亦不得泄漏真实私聊。

### 5.4 环境、权限、进程与前端内容

统一声明驱动所需环境与授权来源，并在实际 spawn 后用受控假件核对最终 env/cwd/加载根。秘密名称过滤只能作为一层：URL 中的密码、认证代理、NODE_OPTIONS／启动钩子、provider endpoint、Git 额外配置与逃逸变量都需按用途审查。合法用户代理、工具链 PATH 和显式 endpoint 有受控保留路径，不能把“安全”做成网络全部断掉。[R07][R08]

两级配置应分开长期认证／模型资产与会话运行 HOME/缓存。不能假设所有 CLI 都允许安全拆开；某家不支持时，明确其并发与隔离限制并实现可验的替代，不复制 refresh token 或暗用真实 HOME。

关闭结果必须区分请求受理、原生退出、强制停止、部分停止和无法核对。身份未知或创建时间不匹配时禁止裸 PID 树杀；采用可验证的 OS 进程归属及现有平台能力，避免查时间与发 kill 间的竞态。POSIX 未覆盖子孙时如实记缺口，不用 Windows 测试替它背书。[R06]

“只读”必须对应真实限制，而不是提示词或强行转换枚举。优先复用 CLI/OS 现有边界与路径工具，不默认新建大沙箱或统一工具网关；无法实现承诺时记录具体缺口，禁止以扩大权限凑通过。

检查最终 Tauri 合并配置，修正过宽资源访问；Markdown/文件/终端输出不能生成真正批准控件或随意 invoke。CSP、asset scope、外链协议、HTML/SVG、OSC52、附件预览均有负测，同时保留正常 Diff、图片、字体、主题与终端体验。仅关 devtools 或移除一个字符串不是安全验收。[R15]

## 7. 不允许偷换的语义

| 用户能力 | 必须区分 | 失败／缺口处理 |
|---|---|---|
| 发送与补充 | 已登记、已交给原生、原生有接受证据、模型执行完成是不同事实；不必全部变成 UI 状态标签。 | 网络或进程断开先查原操作，不自动重新执行。 |
| Queue 与即时插话 | 下一可执行点消费，不等于当前步骤已经采用。 | 不支持或 stale turn 明确返回，不改动作再报成功。 |
| 停止 | 请求受理、原生退出、工具停止、宿主退出不同。 | 原生/子孙未知时保留“待核对／部分停止”，不宣布全停。 |
| 回复批准／追问 | 回复原请求，不是另发聊天或解除所有暂停。 | 请求过期、已答、目标／世代不符时拒绝；敏感答案不入普通日志。 |
| Fork 与长期记忆 | 原生 fork、固定材料续聊、冷重建是不同连续性。 | 保留来源与损失说明，不伪造相同原生状态。 |
| Compact | 折叠显示、摘要材料、实际减少原生上下文不是一回事。 | 原生未执行压缩就不能显示已压缩。 |
| 审查与采用 | 审查绑定具体版本，主控决定后续工作；不存在新增例行验收按钮。 | 报告不授权合并、推送、发布或读取私聊。 |
| 附件 | 可见预览、冻结原件、已编码到目标协议、模型实际可读分别验证。 | 不支持格式保存为资产；必要转换明示，不暗降为文件名。 |
| 安全权限 | CLI/OS 真约束，不是提示词同义词。 | 不能把 read-only 强转为 full-access；不满足则阻止该越权动作并登记替换任务。 |
| 用量 | 本次增量、累计快照、估算费用、官方窗口额度分别表示。 | 不同来源不混加，累计快照不逐条相加，未知不写 0。 |

可靠投递的最小实现：同一 operationId+内容摘要唯一；先事务登记，再写原生通道；记录绑定与来源；接收事实只能由可验证原生事件提升。数据库提交和写 stdin 不是一个原子事务，无法核对的窗口明确记 unknown，不能承诺端到端“恰好一次”。

队列按 Session 串行规则处理，停止／回复请求不被普通消息无限阻塞；重复、乱序、迟到、撤回和配置变化有确定处理。保留取消／终态记录，防止迟到回执复活已经结束的执行。流与日志有大小／背压／保留上限，未知方法只进受限诊断，不能变成授权动作。

### 8.2 每包施工内容、验收与退路

#### WP00｜基线与能力保全、复用取舍

**落点：** 全仓实际调用链、旧设计／研究范围记录、测试、资源与安装入口。

固定 commit、分支和本地差异，导出 UI→hook→service→IPC/RPC→shared→原生／磁盘链；展开 C01–C41，包括隐藏入口、自动启动、CLI helper、托盘和远程路由。把 seat-runtime、Room 辅助模块、protocol、相关 crates 纳入同一资产账本；记录来源／许可／依赖／现状／选择及理由。

记录 Windows 界面、IME／焦点、历史样本、目录、脚本和构建基线。测试存在和测试通过分列；逐项说明原有、部分实现、本次补齐、暂缓。每个入口必须有处置与前后对照测试定义，不能以缺证据为由直接删除。

**交付／验收：** 能力、资产、数据、入口清单可追到真实符号；五家未知项有负责人；T61 的计划依赖与责任检查先建立。**退路：** 本包只读／新增记录与夹具，不改变用户执行行为。

#### WP10a｜远程和语音的封存保全

**落点：** tailscale/*、remote_backend、daemon 启动参数／命令注册、Server 设置／移动向导、dictation Rust 与前端、热键／托盘／自动任务。

统一 release policy，在 UI 与后端入口同时封住外部远程和语音；旧配置、深链接、快捷键、daemonctl 或直接 RPC 都不能偷偷重开。保留本地执行宿主；本地通信使用明确的本机身份与受控传输，不把“远程关了”变成 daemon 整体删掉。

登记现有连接数据和语音模型实际路径。未授权时不更改系统 Tailscale 登录、ACL、节点私钥，不申请麦克风或下载权重。迁移期间已存在的受管远程进程先核对和安全停止；未知外部进程不盲杀。

**交付／验收：** T56/T57：全入口关闭及资产仍在，界面说明暂不可用；没有后台偷偷恢复。**退路：** 保留可逆 feature policy 与代码，不发布恢复功能；恢复需第 9 节条件。

#### WP01｜公共合同、编解码和持续边界检查

**落点：** TS/Rust types、services/events/tauri、适配器接口、CI。

复用现有公共消息结构和旧验证资产，补第 4 节对象；声明请求／响应／错误、版本与未知字段处理。provider 原生 source/枚举不散入 UI；公共驱动注册不包含 steer/send 的品牌业务分支。

依赖／调用边界检查从本包起进入每次变更的 CI：导入、原生命令注册、直接 spawn、原生事件解析、公共存储根和有期限的兼容例外。旧违规先登记基线，不新增、不扩大；每迁一包缩小例外。保留品牌和 design-system lint，分别解释其证明范围。

**交付／验收：** 合同编译、编解码、类型对齐、协议异常拒绝、异形假帧测试通过；不要求后续包才能提供的持久全链。**退路：** 薄包装围住旧实现，不大规模改名或换测试框架。

#### WP02｜数据根、Session 与最小耐久存储

**落点：** state/storage、threadStorage/reducer、拟增 session_store/sessions_core、root 解析器。

按第 5 节实现根与排他所有者基础；保留 settings/workspaces JSON。对 Session 映射、Delivery、事件游标和迁移进度采用小型事务存储，优先 SQLite；仅当 WP00 找到同等可用资产且故障测试成立才替换选型，不重做整个 Store。

建立 Session/NativeBinding/内容域/独立草稿，原生 ID 用复合键；坏记录隔离诊断，不默认覆盖为空。实现只读旧历史预览、数据副本导入、重复迁移和崩溃恢复脚手架，秘密不进通用库。

**交付／验收：** 稳定 ID、跨实例不碰撞、scope/privacy 服务端查询、根不回落 cwd、小样本迁移可重复。**退路：** 原件与备份不变，禁止旧新同时写。

#### WP03｜复用机器、封装驱动与受控协议 worker

**落点：** Rust daemon/process_core、Codex app_server、connect/runtime args、选中 TS 驱动与 close/env 代码。

按第 3.3 节运行最小 worker 样本并锁定实际实现。宿主登记全部原生进程、绑定、配置和真实身份；控制写入只走同一入口。修复默认 home 假隔离与任意活连接复用，不用 shared HashMap 名字证明产品隔离。

实现共同环境策略与逐 spawn 校验；身份缺失时不裸杀，停止核对工具子孙。确定本地控制传输及重连策略、超时／stderr／输出背压和崩溃处置。worker 缺失、版本不匹配、无法收尾均明确报错，不悄悄降回旧 Codex 旁路。

**交付／验收：** 假原生进程链可运行，隔离和停止反例有证据，Node/package 权利与封装有结果；真实 CLI 的综合能力留给 WP11。**退路：** 以隔离数据域选择旧／新单一路径，保留成熟原生实现，不双发比较。

#### WP09a｜五家能力、版本和认证探测

**落点：** 选中 accounts/probe/helpers、提供方注册、capabilities_core、实例配置。

登记五家的实际二进制来源、摘要、版本、参数、平台、模式及认证配置版本；先无害帮助／状态观察，再按授权跑必要握手。不推定“找得到 executable”就是可用模型。能力来源包括原生宣告、版本约束与实际 conformance，unknown 独立。

启动和执行检查快照有效性；binary、认证、profile 或原生模式变化使旧快照失效。探测错误不能触发全权限、别的账号／模型／CLI 替代；登录／升级仍由人明确发起。

**交付／验收：** WP04 取得真正有来源的 CapabilitySnapshot；不支持/未知能力可拒绝对应意图。五家尚无运行条件的差距保留，不伪造静态 true。**退路：** 保持原登录，不写凭据和安装目录。

#### WP04｜安全投递、事件、输入回答与停止纵切

**落点：** useThreadMessaging、事件解析／reducer、execution_core、公共批准／追问服务。

按固定收件人／scope/世代鉴权并事务登记，驱动转换原生动作；控制请求不排在普通文本后。处理重复、未知接受、乱序、游标缺口、重连、撤回与终态竞态。批准回答绑定原请求和许可，原生 EOF 不是成功证据。

本包主责下行 ContextPackage 与上下行隐私执行策略：派工不夹带主对话，历史/缓存/资源读取也经同一可见性裁剪。为 UI、资源模块提供已经可测试的服务端策略，而不是各写一份前端过滤。

**交付／验收：** 假件支持 UI/客户端→公共服务→驱动→显示的完整失败可操作链，发送／工具／追问／停止／重连均能解释。**退路：** 接受结果不明保留 unknown，核对后再决定，不自动重发。

#### WP11a｜最小真实通路，解除辅助生成依赖环

**落点：** 现有最小 UI 入口或受控合同测试客户端、Codex 与至少一个非 Codex 驱动。

在授权、隔离工作区与可核对版本下跑两轮对话、流输出、受控工具动作、停止／断连样本；确认非 Codex 不在后台调用 Codex。使用 WP04 已有策略，不为“先通一条”绕过权限和持久投递。

**交付／验收：** 一条真实非 Codex 通路足以让 WP08 验生成后端；同时保留真实 Codex 兼容样本。不等待完整设置 UI 或全部工具页，因此没有反向依赖。**退路：** 未装／无授权记未验证，不替用户安装／付费，五家目标不因阶段样本被缩减。

#### WP05｜屏幕、输入、导航与通知的公共化

**落点：** MainApp/AppLayout/Desktop/Tablet/PhoneLayout、messages/composer/sidebar/tray/notifications。

保留视觉、尺寸和编辑器行为，改公共数据接线；每个输入框有独立目标、草稿、附件和焦点，切项目不串发。主控／审计／秘书长是职责，不从原生 subagent 名称推导。普通施工失败给主控，不把每个工人变成 Owner 待办。

保留 chat+diff 并补实际需要的公共会话视图；IME composing 时 Enter 不发，流式不抢焦点、不无条件拉滚动。深链接和托盘重新授权，不携带可猜原生裸 ID 或私聊文本。

**交付／验收：** Windows 前后视觉和操作对照、双输入与切项目测试；design-system lint 只是其中一项。**退路：** 不借本包重画导航、换组件库或批量 codemod，旧布局可恢复但不绕回旧执行链。

#### WP07｜公共资源、规则、模板与加载边界

**落点：** files_core/prompts_core/agents_config_core、resources、skills/apps/MCP。

公共资源写入 gogoke 根，旧 Codex 目录只作为明确的导入／提供方资源。保留 CRUD、提示词参数、补全、查看和移动；移动迁移先复制核对再切引用，源删除是独立授权动作。

Agent 模板和实例原生配置分开，未知字段保留于来源记录而不静默丢弃。加载的规则、插件、MCP 与 Apps 记录来源和范围；展示不等于启用，迁移不自动执行新代码或共享账号连接器。服务端使用 WP04 共同隐私策略。

**交付／验收：** 无 CODEX_HOME 的公共资源可用；同名冲突／坏文件／重复导入不损原件；公共模板不写别家 config。**退路：** 旧目录和原生加载方式作为兼容保留，不默认开启新资源。

#### WP09b｜实例与设置界面、模型、用量

**落点：** 实例设置页、useModels/account hooks、settings、local_usage_core、选择后的 Room helper。

分产品设置、实例/profile、提供方扩展三层；模型选择来自 WP09a 快照。认证归官方 CLI，产品仅存引用／公开元数据。账号共享、并发容量与项目隔离分别显示；不继承旧单项 busy 作为多 Session 限制。

用量区分累计/增量/估算/官方配额，显示来源时间；共享账号不重复加总，坏数据或网络未知不显示额度归零。敏感字段、后台探测和账户切换有严格作用范围。

**交付／验收：** 使用者能在设置里选择正确实例并看到有依据的能力和限制，失败不暗换号/模型。**退路：** 保留旧配置只读导入，不自动写原生凭据或升级 CLI。

#### WP08｜工具能力保全与辅助生成替换

**落点：** Workspace/Git/Files/PTY、helper generation、Ask PR、附件及系统桥。

本地 Git/文件/终端不依赖模型；保留 clone/worktree、脚本、分支、Diff、提交／同步和外部打开。受控临时仓库验证，不能在 Owner 真实工作区执行破坏性回归。

提交信息／运行元数据／Agent 描述／Ask PR 使用指定公共实例与固定上下文，复用已有上下文准备和按钮。依赖 WP11a 的真实通路完成非 Codex 样本，手填不算生成功能通过。附件冻结及目标编码防止错文件／变文件，语音仍按 WP10a 封存而非重新开放。

**交付／验收：** 没有模型也能用本地工具；真实生成保留草稿、错误及来源，中文/空格路径不退化。**退路：** 不替换 Git/PTY/编辑器栈，不清理用户 worktree。

#### WP06｜高级公共工作流替换

**落点：** review/fork/compact/plan/collaboration/sidechat。

按第 7 节分别实现固定材料 Review、产品分支、上下文整理和侧聊递话；复用原生强能力，但 UI 标明原生续接／材料重建的真实差异。正式审查和私人侧聊不共享原生历史，子 Agent 活动不自动变成公共派工事实。

**交付／验收：** 每个旧入口都有新流程、证据和限制，实际测试不偷换材料，不用隐藏按钮算保留。完整跨五家由 WP11b 集成，不要求本包提前获得未来全矩阵。**退路：** 新实现未等价前不删旧适配功能；必要差距明列，不减为最低共同集。

#### WP10b｜本地宿主、重连与封存遗产兼容

**落点：** daemon rpc、local transport、events、daemonctl、tray/退出、remote_backend 与移动兼容测试。

本地 UI 与 daemon 使用同一 root、身份和协议，重连先恢复快照／游标，不能重新执行全部客户端动作。明确 keepDaemonRunningAfterAppClose 的实际承载，不凭前端状态承诺关窗仍运行。

全部旧本地／远程命令要么转发同一公共服务，要么明确拒绝；外部访问仍由 WP10a 封住。远程和移动只做封存、静态/离线合同及数据保全测试，不声明完整在线服务已迁移。

**交付／验收：** UI 断连不伪报模型停止，本地重连不双发，无旧 writer 旁路。**退路：** 不恢复外部监听来“证明 daemon 存在”；未知平台如实保留待验状态。

#### WP11b｜五家全矩阵与无 Codex 证明

**落点：** conformance、真实受控样本、完整 UI/服务回归、去 Codex 构建。

逐家绑定 binary/版本/平台/模式/认证/profile，完成会话、流、工具、输入／批准、停止、恢复、生成与相应公共功能。利用旧三协议假件并补不含 thread/turn 的事件及多会话／跨进程续接样本，假件通过不计真实通过。

不启用 Codex 模块的构建，加无 Codex executable/login/home 的安装或测试环境；检查公共操作不暗读 Codex 数据根或借 Codex 驱动兜底。跨包验证上下行隐私、控制竞态、用量、素材及视觉。

**交付／验收：** 五家每个目标功能都有实际结果或明确未验／缺口；未闭合不能报五家全部完成。暂缓功能只验封存合同。**退路：** 使用授权账号与临时材料，不自动安装、付费、提权或静默切模型来补测试。

#### WP12｜迁移、安装、更新与有新数据回滚

**落点：** 数据迁移／备份工具、Windows 安装包、更新器、worker manifest 与说明。

按第 10 节在旧数据副本演练后切换。签名、允许域、公钥与 readiness 继续保留；worker/runtime 加入产品版本与校验清单。更新只在可安全停靠的执行边界切换，不能强装覆盖仍在写入的宿主。

验证 fresh install、旧安装升级、卸载默认保留数据、cache不误删、root不暗移，以及新增历史／草稿之后的回滚。初期备份与保护来自 WP02；此处做完整发行链验证。

**交付／验收：** 能交付实际可操作包和恢复说明，不靠“清空数据后正常”通过。**退路：** 备份／已验证逆迁移，保全所有新写入，旧程序不得直接开不认识的新 schema。

#### WP13｜有条件删除与最终交接

**落点：** 第 11 节退出项、兼容 wrapper、导入依赖／命令注册／启动入口、代码地图与测试记录。

逐项核对替代、调用者、数据、远程路径、回滚需求和证据再删。允许适配器、fixture、历史迁移、来源／许可及开发工具中保留 Codex 名称；公共本体不再绑定原生协议／home／启动前提。

**交付／验收：** C01–C41 和扫描新增项无孤儿能力；T01–T64 有主责和真实状态；失效接线删除后完整回归；暂缓项有恢复条件。**退路：** 普通代码回退不得恢复旧 writer 或覆盖新版数据；不以删文件数评价进度。

## 9. 暂缓功能的完成定义与恢复条件

远程和语音本次应交付的是 **“代码与数据已保留，全部入口确实关闭”**，状态 `preserved_disabled`。它既不是 `removed`，也不是 `verified_active`。

远程关闭覆盖 UI、Tauri/RPC、自动启动、daemonctl、深链接、移动向导与可通过旧配置恢复的监听。保留本地控制通路，识别已有受管连接；不注销用户系统 Tailscale，不改系统网络／ACL。保存的是 gogoke 自己的连接记录与秘密引用，不复制 Tailscale 私钥或把外部节点身份重建到新库。

语音关闭覆盖按钮、快捷键、权限请求、录音、后台模型下载与自动恢复。现有权重、模型版本/摘要/下载进度和路径保留，迁移不重复拷贝大模型，不把缓存全删来“清理依赖”。

恢复前需要明确产品范围变更，并分别通过身份／权限、设备入口、数据兼容、平台、资源占用与实际功能测试。恢复不默认启用旧 token、不自动重录音、不静默升级模型。实际在线／麦克风功能未恢复前，只报告封存合同已验，不能用关闭来宣称其迁移成功。

## 10. 全量数据迁移与回滚

### 10.1 数据台账与去向

| 数据类 | 保全和迁移方法 | 禁止行为 |
|---|---|---|
| root、settings、workspaces | 固定 identifier/实际绝对根，保留旧 JSON 与脚本配置，版本化映射。 | root 失败回落 cwd、自动换产品目录、坏数据覆盖空默认。 |
| localStorage 与 UI 元数据 | 导出并映射 Session；名称、置顶、活动、草稿、附件、尺寸、快捷键与原参数逐项核对。 | 因 codexmonitor 前缀清空，或只迁正文不迁关系。 |
| 原生历史与公共内容 | 只读预览；按获准归属导入可展示内容，保留原生来源和未导入原因。 | 全部历史默认分给主控／公开给审计，调用有副作用的 resume 冒充只读。 |
| Session/Execution/Delivery/事件 | 原操作和世代、接受证据、游标／终态、未决请求按事务迁移并核对。 | unknown 变成待重试自动执行，恢复旧批准使其再次有效。 |
| 实例和运行配置 | 保存公开标识、来源、认证引用、profile版本、容量与未知占用。 | 按邮箱合并身份、复制 token、把旧坏池或无法查进程当作空闲。 |
| prompts、rules、模板、资源 | 保留原文/版本/作用域，同名冲突预览；公共副本写 resources。 | 覆写原生 config，删除源件，迁移后自动启用脚本／插件。 |
| MCP/Apps 等连接 | 配置与秘密引用分开，迁后默认核验授权；提供方资源归各自适配器。 | 导出秘密或假称另一 CLI 已连接同一私有账号资源。 |
| 用量与额度 | 保留时间、单位、账号窗口、累计/增量和来源；历史与实时去重。 | 把估算当官方剩额，累计值反复相加。 |
| 远程连接与设备记录 | 仅迁 gogoke 自有数据与秘密引用，保留封存状态和兼容读取。 | 复制系统 Tailscale 身份、自动恢复监听或复用过期授权。 |
| 语音权重与缓存 | 记录实际路径、版本、摘要、完整性与引用；默认原位保留可复用文件。 | 每次备份全量复制巨型缓存、回滚强制重下、开启麦克风。 |
| 产品更新与已准备安装 | 保留 PreparedUpdateState、安装包标识、摘要、readiness/失败记录；升级前重新验证来源与版本。 | 旧状态注入新公钥／允许域、绕签名或回放旧 readiness。 |
| worker/runtime/适配器资产 | 固定版本与校验清单，区分代码与用户内容，缺失能诊断恢复。 | 启动时临时从网络拉 latest 或执行工作区中的同名 worker。 |
| 临时文件、日志、导出及备份 | 内容域与保留期限明确；清理只针对可证明由产品拥有且不再引用的对象。 | 把私聊/秘密留到公共日志，删用户工作区或无法证明归属的文件。 |

更新器的 `ALLOWED_HOSTS`、公钥和协调器在所读源码里属于发布代码／嵌入资源。[R13] 迁移应该保留这条信任边界，而不是建立一个“从旧库导入允许主机”的可写后门。

### 10.2 切换步骤

**备份与一致性校验 → 只读预览和冲突处理 → 停止该数据域的新写入／新执行 → 核对或安全停靠在途任务 → 建立映射并事务提交 → 校验关系／内容／权限 → 切换唯一所有者 → 验证新链 → 保留旧原件与迁移报告。**

备份包含一致数据库状态及必要内容引用，不单独漏掉事务日志；大缓存可用校验后的原位引用，不必无差别复制。临时／测试根与生产根明确分离，迁移工具默认 dry-run，不允许在收到未核验路径时批量改数据。

旧新链只在隔离夹具上比较，生产操作不得双跑。旧入口即使仍编译存在，也必须在首次新写入前检查同一所有者；不能等 WP13 删除时才禁止旧发送。

### 10.3 故障与回滚

至少注入七个点：备份后、映射开始、部分记录写入、事务提交、索引生成、所有权切换、首次新启动。另测磁盘不足、损坏记录、重复迁移、根别名、模型缓存缺失和更新进程失败。

切换前可按备份回退；切换后存在新数据时，先保全新增会话／草稿／产物，再执行验证过的逆迁移或兼容导出。旧 exe 不认识新 schema 时不得直接打开新库。无法核对旧执行时，不启动新的写者来“验证回滚”。

卸载默认保留数据和原生 CLI；删除用户数据必须另有明确授权与预览。任何恢复结果必须能说明保留了什么、未恢复什么、是否还有原生执行，而不是用“启动成功”覆盖数据差错。

### 12.1 测试执行与状态记录

沿用现有 `npm run typecheck`、`lint`、`test`、`test:localization`、`check:product-identity`、`build` 及 Rust check/test；design-system 检查按当前脚本使用。旧 seat-runtime 测试和假件进入选择后的适配回归。实际开工须以 package.json/Cargo 和脚本文件核定命令，不把拟议 no-Codex／故障测试命令写成已存在。

状态至少区分 `planned`、`implemented_not_verified`、`verified_fixture`、`verified_native`、`gap`、`preserved_disabled`。每份记录带 commit、平台、binary/版本、driver/profile、数据集、操作、结果和证据位置。测试作者不能只写 PASS 文本代替退出结果与原生证据。

“全部通过”只适用于已定义的实际执行集，不能把未安装驱动、暂缓功能和未测平台算作绿色。平台策略以 Windows 首发为主；macOS/Linux/mobile 的真实能力单列，不凭条件编译推定已支持。

## 13. 施工账本、交接与终局条件

### 13.1 最小账本

每个入口一行：`capability_id / user_entry / original_path_symbol / evidence_level / original_behavior / disposition / replacement / data_keys_root / callers_local_remote / primary_wp / test_ids / result / remaining_gap`。

每个复用模块另有：`source_commit / path / license / dependencies / side_effects / reuse_or_repair_or_rewrite_or_reject / rationale / conformance_evidence`。每个删除项绑定 D 编号和六问结果。

主控负责组织和集成，施工者负责本包实现，复核者核证据；不因本文件有 17 个工作包再建立 17 套审批流程。普通交付记录即可说明实际 commit、能力变化、数据影响、测试、剩余缺口和下一依赖。

### 13.2 终局验收

只有以下同时成立，才报告本专项完成：

1. C01–C41 与扫描新增入口逐项保全、内化、替换或按记录封存，无隐藏退化；不是空壳或代码搬家。
2. 公共层没有 Codex 协议／home／默认身份硬依赖；Codex 仍作为可选接入保留有用能力。
3. 五家目标逐家完成实际承诺的支持矩阵；阶段样本、未安装、unknown、假件不得冒充真实全部支持。
4. 分屏／侧栏／输入／Session／职责／隐私域不串；主对话不漏给施工席位，私聊不混正式审查。
5. 进程、输入、队列、数据和工具写域只有一个有效所有者；旧入口无绕行；接受不明不盲重放。
6. 权限、内容渲染、环境、凭据与路径边界不因适配而放宽；原生差异不被改名掩盖。
7. 数据迁移、失败恢复、有新数据回滚与安装更新均有证据；自有发行策略不被导入数据改变。
8. 远程与语音明确作为暂缓资产封存，代码／数据／恢复条件均在，不宣布其在线功能已经完成迁移。
9. 删除只发生于替代与回归之后；用户 CLI、原生历史、工作区、许可证和开发资产未被破坏。

**终局不是“Codex 文件消失”，而是“能力归 gogoke、原生差异归适配、旧依赖退出以后机器仍能工作”。**
