### 2.1 派工与升级

先由 Sol/high 定清不确定的合同，再按形状派施工。代码少但涉及权限/并发仍是高风险；代码多且规则明确可用 Luna/max。Grok 不是必须分配的配额，只用于独立可验整包。相同失败两次、需要修改 schema/API/授权/范围、存在矛盾证据或无法确认实际执行身份时，返回 Controller；最难的问题可直接交 Astra/high，不强制逐级试错。[R02]

同一工作包可包含多个 Task Capsule，但一次共享文件写入只归一个集成人。`MainApp.tsx`、`types.ts`、`tauri.ts`、`lib.rs`、`state.rs` 和 daemon dispatcher 是热点；Controller 指定单一合并所有者。模块施工在独立 worktree 提交，禁止多个工人各自合并主控分支、覆盖同名文件或用额外独立会话绕过运行时容量限制。

### 2.2 Grok 整包施工的可执行条件

Owner 指定它承接整包是路由意图，不证明当前 Provider 已可写。派发前必须有本次可核对的模型/profile、允许路径、worktree、文件写入、终端/子进程及所需测试能力记录。既有配置仍只读时，不发要求写代码或运行测试的整包；Controller 将任务按复杂度改派 Luna/max 或 Sol/high并记录原因，不让 Grok 仅输出建议却报整包完成。

可候选包包括已定 schema 的 fixture 套件、独立历史格式导入器、原生纯解析模块或既定公共接口下的独立工具适配。每包必须有固定输入合同和验收用例；需要它自行决定权限、共享数据库 schema、整体 UI 或供应链策略的，不符合独立整包条件。Grok 的自测只作为施工证据，由 fresh Sol/high复核；高风险包还走 Astra 流程。

**本稿不修改 Grok 服务安装/权限，不开启旧路由明确禁止的真实请求，也不改变其它项目 held 工作包。** WP00 交付新旧路由差异与实际能力检查，Controller 在本专项任务卡记录最新 Owner 指令和有效工具边界。

### 2.3 高风险审计与最终裁决

高风险任务在第一次拟集成候选上由 fresh Astra/xhigh 做全轴风险审计；相关技术方案不清时提前请求 Astra/high Specialist。首次审计应在进入真实私有材料、生产根或不可逆操作前完成，不能把“尚未实现的行为未验证”写成通过。

缺陷由原施工角色集中修复；fresh Sol/high 对已知缺陷、相关回归和受影响 invariant 做聚焦复核；然后 fresh Astra/xhigh 对最新候选做最终全轴审计。只要不污染证据或越权，首个缺陷发现后继续检查其它独立轴，一次返回缺陷批次；不能以“第一处已失败”掩盖未查范围。[R02]

普通 PR 不需要全部跑 Astra/Claude。最终全产品候选在 WP13 清理、打包和回归之后，完成 Astra 全轴、外部 Claude 异构审查；Controller 处理矛盾和技术结论，Owner 最终裁决。审查导致代码/配置/构建改变时生成新候选，重跑受影响检查并重新绑定最终审查，不能沿用旧 SHA 的通过。

## 3. 施工范围与能力保全原则

产品目标接入为 **Codex、Claude Code、Grok Build、OpenCode、Antigravity CLI**。它们的配置、协议、认证、运行拓扑和实际能力按二进制/版本/平台/模式逐项固定。先打通一家非 Codex 是阶段成果，不是把五家目标缩成两家。[B01]

分屏、侧栏、输入、历史、Git、Diff、Files、PTY、工作区、提示词和资源管理等保留；公共身份、控制和数据归 gogoke；原生协议、登录、参数、目录规则保留在对应适配器。远程访问和语音输入按已记录范围**暂关保留**：封全部生产入口，不删代码、配置或模型缓存，不暗中重开。[B01]

不重画 UI，不替换 React/Tauri/Rust/Git/终端技术栈，不整体引入 Codex Core，不重新接上 Room 总服务，不新造多 Agent 编排引擎或统一工具网关，不增加被取消的看板/成果页/例行产品验收按钮。工程审计关卡不是用户产品里的新按钮。C42 只是把既定 CLI→CLI 委托接缝及权限单独列清，不新增调度权。

六种处置分别登记：保留、内化、替换、适配保留、封存保留、移除。能力状态与发布状态分开；缺乏原生等价能力不是砍掉公共需求的理由。需要替代就实现并验证，不用返回 unsupported、隐藏按钮、改名或全仓零 Codex 字符串冒充完成。

### 3.2 Rust 与 TS 的具体取舍

现有 Rust daemon 是产品身份、持久化、授权、队列、绑定和停止的唯一权威。值得复用的 TS 协议代码可由受限 worker 承载；worker 只处理分配给它的原生连接，不自行选账号、不持有第二产品队列、不做 Room 调度。原生进程启动必须登记归属，worker 派生子进程同样受控。

WP03 先做固定 Node/编译产物/帧格式/Windows 路径/进程收尾/安装打包样本。能复用就复用；若具体片段的权限、打包或权利边界不成立，保留其 fixture，仅局部移植必要逻辑，不全重写。不能运行工作区里的同名 worker、启动时下载 latest、假设 TS 源码无需 Node 或额外依赖。

许可走来源账本：文件、commit、原许可、贡献、分发义务和采用方式明确。AGPL 不是“禁止二进制进入安装包”，但按许可分发需满足适用条件；仓库归属不能直接推出所有版权归属。未经授权不换标注，worker 进程隔离也不能自动推出许可义务消失。权利/分发疑义需 Owner 及必要的专业审核决定，不阻塞无关原生资产的盘点和假件开发。[W01]

## 4. 必须保住的公共技术合同

### 4.1 对象与依赖

依赖方向：**现有 UI/工具 → 公共服务 → Rust 宿主 → 可选驱动/受限协议 worker**。Tauri 保留系统桥；新公共服务职责可原位实现，不要求为改名新增一套框架。

| 对象 | 最小语义 |
|---|---|
| Session | 产品稳定 ID、作用域、隐私域、可选职责、标题和生命周期；不是 PID、原生 thread 或视图。 |
| NativeBinding | driver/instance/profileRevision/authRevision/nativeSessionId/generation/continuationMode；原生 ID 只在明确绑定内有意义。 |
| Execution 与 Delivery | 一次执行与一次投递分开；operationId、请求指纹、固定目标、接受证据、原生关联和终态。 |
| ViewBinding/ComposeTarget | 屏幕及输入框的固定 Session、域、版本和意图；后端再鉴权，不信任前端当前活动项目。 |
| PublicEvent | schema、来源、受控对象、generation、序号/游标和受限 payload；未知帧不能授权或虚报完成。 |
| CapabilitySnapshot | 二进制路径/摘要/版本、平台、模式、实例、认证/配置版本、证据时间和 unknown。 |
| ContextPackage/委托 | 明确接收者、任务、固定材料、来源、可见性与权限；宿主路由，不自带父对话全文。 |
| HumanActionRequest | 原请求及 continuation、目标、世代、有效期、允许答案/许可；回答不等于另发一轮聊天。 |

### 4.2 数据根与所有者

保留 identifier `app.gogoke.desktop`，默认由平台 app_data_dir 解析。Windows 通常为 `%APPDATA%\app.gogoke.desktop`，macOS 为 `$HOME/Library/Application Support/app.gogoke.desktop`，Linux 为 `${XDG_DATA_HOME:-$HOME/.local/share}/app.gogoke.desktop`；具体以当前系统 API 结果为准。自定义根固定为经过确认的绝对路径，迁根走显式迁移。[B01]

新增职责目录：`root.manifest.json`（rootId/schema）、`core.db`（Session/Delivery/游标/迁移）、`runtime/`、`resources/`、`content/`、`profiles/`、`migration/`。保留已用 settings/workspaces JSON，不重做整个 Store。最小事务数据优先 SQLite，若 WP00 找到等价现成实现则经同等故障验证再采用。

桌面与 daemon 使用同一经过核验的实际根和 OS 排他锁。目录别名、大小写、junction 不能产生第二所有者；只写锁文件不算取得锁。解析失败、坏 schema、损坏数据或无法保障单写者时停止相关写入，保留诊断与恢复入口，不回落 cwd、不默建空池。

数据库租约不是原生撤权。切换前封旧输入、核旧进程和工具写域；旧进程尚能写时不能启动新写者。认证、配置及绑定版本变化不能暗改在途执行。同账号可共享实际容量，但上下文和读写域仍隔离；不复制 token 来造多账号，不强制一实例一席位。

### 4.3 投递与非等价行为

先事务登记，再写原生通道；记录 operationId+指纹和绑定。不把数据库提交与 stdin 写入当原子事务。原生未提供幂等收据时不承诺端到端“恰好一次”；接受不明保留 unknown 并核对，不能自动重放。乱序、重复、终态、取消和迟到回执有确定规则，流和日志有帧/字节/背压预算。

Queue 不冒充 steer；停止请求受理不冒充实际停止；exit 0 不冒充工具或任务全部成功；原生 fork 不等于复制可见材料；折叠/摘要不等于实际 compact；附件文件名/OCR摘要不冒充原件送达；模型计划和原生 subagent 状态不自动成为宿主派工事实。

### 4.4 隐私、工具与安全

Owner↔主控对话不自动下发施工。任务包、stdin、规则、原生历史、可读目录、缓存、索引、日志、导出、插件/MCP和恢复都要验证。只改 HOME、另起进程或换模型不足以证明隔离。T49 使用随机高熵标记及获准共享正反对照，检查实际字节与可达资源；模型答不出标记不是通过充分证据。

正式审查使用干净 Session 和固定材料，不能混入 Owner 与项目审计的私人侧聊；秘书长全局身份不表示可默认读取所有私域。施工向主控回报，真实原生权限/问题仍保留 continuation；不通过模型文本伪造 Owner 授权，不让原生派生子 Agent 绕开公共委托边界。

每家真实 spawn 验最终 env/cwd/配置/工具。秘密过滤需看实际值和用途：数据库 URL、认证代理、agent socket、endpoint、动态加载选项、hooks 不能只凭变量名判断；合法代理、工具链和显式端点有受控保留路径。认证目录与会话 HOME/缓存能否拆开按 CLI 实测，不复制 refresh token 或暗用真实 Home。

只读必须有真实原生/OS边界，缺等价时不得扩大权限。进程身份未知不得裸 PID 树杀；进程退出、子孙存活和无法核对分别报告，分平台测试。CSP、asset、Markdown、HTML/SVG、外链、IPC、终端 OSC52和批准控件来源一起验证，正常 UI/文件/PTY功能同时回归。

## 7. 每个工作包怎么施工、交付和复核

通用规则：Controller 为每个子任务发限定 Task Capsule；施工者提交代码、自测和未验项，不能自己标记独立验收通过。下述高风险包由 fresh Sol/high 做普通证据核验/修复聚焦复核，并按 §2.3 进入 fresh Astra/xhigh 首次及最终全轴审计。专项咨询走 Astra/high Specialist，咨询结论不替代审计。

### WP00｜基线、复用、行为与权限盘点

**输入/落点：** 固定 V2/审计/路由提交与 Owner 最新指令；检查本地 dirty tree、desktop、seat-runtime、Room 辅助模块、protocol、相关 crates、脚本及测试。Luna/medium 只读收集，Sol/high 完成取舍和缺口判定，Controller 收口 P00。

**必须交付：** 每个入口的 UI→hook→service→IPC/RPC→shared→原生/磁盘链；现状/签名/源码/测试存在/实际运行分级；旧数据副本和行为样本；资产依赖、来源许可及“不用”的理由；Grok 路由与实际权限差异；Windows 性能比较方法。对所有 T 的预期输入和输出做人工初核，不声称已运行校验器。

**本包结束条件：** P00 能让后续任务固定路径与行为，未知项都有负责人，不把缺证据当无用资产。fresh Sol/high 复核盘点的可追溯性；高风险机制的初始轴交后续 Astra。无生产行为改动，不触动用户 CLI、历史或工作区。

### WP10a｜远程与语音封存保全

**施工：** Luna/high 处理明确 UI/热键入口；完整长链由 Luna/max；后端策略/本地与远程边界由 Sol/high。范围包括 tailscale、remote_backend、server 设置、移动向导、daemon 启动参数、dictation 前后端及后台恢复。

**必须实现：** release policy 同时检查 UI 和服务入口；旧配置/深链/直接 RPC/自动启动不得重开；本地宿主正常。保留代码、设置、缓存、已有语音权重和恢复说明。既有受管远程进程先核归属与状态，未知外部进程不能盲杀；不注销系统 Tailscale。

**本包结束条件：** T56.L/T57.L 只验当前入口封存和现存资产保持。新宿主集成另在 I、完整升级回滚另在 M，不能等 WP12 才让本包交付。fresh Sol 复核，Astra 审计权限相关边界。退路是保留可逆策略，但恢复入口仍须明确范围授权。

**施工：** Sol/high 定公共 schema、错误和版本语义；Luna/max 按固定输入输出编写 TS/Rust 编解码、依赖检查和测试；简单配置由 Luna/high。范围为公共 types/services 合同、拟增公共 core 接口、CI 和追踪文件。

**本包结束条件：** T05.L/T61.L 的编解码、异常拒绝和计划负测，支持未知或不含原生 thread/turn 的形状。不要求发消息全链、真实五家或最终 UI。P00 是校验输入，P01 是可执行合同和校验器。fresh Sol 复核；身份/授权合同做 Astra 首次风险审计。
