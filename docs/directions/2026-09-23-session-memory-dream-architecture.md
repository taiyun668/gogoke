# gogoke 会话、记忆与做梦架构（候选报告）

- 日期：2026-09-23
- 来源：Owner 与 Claude（审计席）的讨论，以及当天对开源项目、闭源产品和论文的检索
- 状态：**候选，不是决定。**本报告有意从零推导，不沿用原有设计；不改变 S1-R4 计划、授权或施工。Owner 定稿后，交主控进入后续计划。

## 1. 为什么要做

gogoke 要让 Owner 不在环内：日常判断由系统完成，Owner 只定边界、叫停、看结果。

会话管理是其中必须自己做的一块，因为各家 CLI 只管自己的会话，不会替我们管：什么时候复用、续接、分叉或新开会话，给它装什么上下文，什么时候换窗、换厂商。

这和模型厂商管理 KV 缓存是同一个问题，只是发生在系统层：
- 算过的东西尽量复用；
- 复用不了才重算；
- 存不下就压缩、挑选。

会话管理、记忆管理和做梦是同一件事的三部分：
- 会话管理管正在用的记忆；
- 记忆管理管长期记住的东西；
- 做梦负责把前者整理成后者。

## 2. 三条原则

1. **会话是缓存，席位是身份，事实在 Git。**会话可以复用、复制、丢弃；长期存在的是席位；只有进入 Git 的才算数。
2. **切换是决策，不是阈值。**每次都在"复用缓存"和"重算"之间算账。复用几乎免费；重算要付三样代价：重读材料的 token、交接丢失的信息、耽误的时间。只有换来的东西值这个价才重算。值得重算的情况是：
   - 需要独立视角；
   - 当前账号额度到头；
   - 需要另一家的能力；
   - 当前会话已经坏了。
3. **人不在环内。**Owner 负责三件事：定边界（可用的厂商与账号、禁止共享的内容），随时叫停，看结果。

## 3. 记忆分层

| 记忆 | 对应模型内部 | 在 gogoke 里是什么 | 管法 |
| --- | --- | --- | --- |
| 工作记忆 | KV 缓存 | 各家 CLI 的原生会话 | 厂商负责，gogoke 只决定复用、复制还是丢弃 |
| 程序记忆（固定前缀） | 锚点 / 共享缓存 | 项目章程摘要、规则、角色预设、切换标准、交接提取方式 | 按项目版本发布；所有会话、所有厂商开头一致，以吃到提示词缓存 |
| 语义记忆（外挂记忆） | 外挂记忆（Engram） | Git 中的事实、决定、坑与死路 | 按需召回，不整份塞进会话；事实带有效期和出处 |
| 情景记忆 | — | 会话登记、记账、复盘 | 每次决策与会话结束时写入，是做梦和反射学习的原料 |
| 交接包 | 压缩后的 KV | 跨会话、跨厂商搬运的精简状态 | 只在换会话时生成 |

## 4. 部件

| 部件 | 作用 | 借鉴 |
| --- | --- | --- |
| 1. 会话登记簿 | 每个会话记录：席位、厂商与账号、原生会话编号、父会话与继承档、接触过的权限等级、状态 | OpenRath 的会话谱系 |
| 2. 健康监测 | 从用量与事件读信号（token、缓存命中、压缩次数、同一失败反复、崩溃、剩余额度）；输出健康 / 观察 / 建议换 / 必须换 / 未知 | AgentBridge 的额度守卫 |
| 3. 切换决策器 | 决定何时换：子任务完成、思路收敛时换；推导中途或卡住时不动。决定怎么接、接到哪个厂商和账号 | 自我压缩 agent 的判断标准 |
| 4. 交接包工厂 | 三路来源：从提交和检查点机械提取（含死路）；另一模型围绕下一步目标提取；工具原始输出一律丢弃，只留指针 | Amp Handoff、Anthropic 上下文编辑 |
| 5. 交接验证器 | 有条件时做重叠验证：旧会话继续跑一小段，检查交接包是否漏掉它接下来用到的内容；无条件时看下游返工率 | Slipstream |
| 6. 前缀与缓存管理 | 维护固定前缀的版本与装配顺序；旧内容成批清理，避免反复破坏缓存 | TokenPilot |
| 7. 写入范围协调 | 并行会话各领写入范围，以租约互斥，不许重叠 | — |
| 8. 权限闸 | 继承哪一档受"谁能看什么"约束；审计强制零继承；跨家转录携带整段对话，必须先过闸 | — |
| 9. 记账与复盘 | 每次决策连同代价和结果记一条；会话结束后复盘问题 | Devin 会话洞察 |
| 10. 长期记忆库 | 分事实、坑与死路、做法三类存；事实带有效期；每条带出处；按需召回 | Graphiti、Mem0、Devin 知识库 |
| 11. 做梦 | 空闲时离线整理记账、复盘与记忆库，只产出提案（见第 9 节） | Anthropic Dreams、Letta 睡眠时计算 |
| 12. 用了就回写 | 记忆每被召回使用一次，按那次的结果升降可信度 | 取用驱动的记忆再巩固 |

## 5. 继承度：四档

| 档位 | 含义 | 典型用途 |
| --- | --- | --- |
| 原生复制 | 同一厂商内原样复制父会话 | 同一件事接着干 |
| 跨家转录 | 把会话记录转成目标 CLI 的原生格式后续接；思考过程、图片会丢失 | 额度到头或需要另一家的能力，同时要尽量少丢信息 |
| 交接包 | 固定前缀 + 交接包 + 最近检查点 | 拆分并行、跨家接手、故障恢复 |
| 零继承 | 只有固定前缀和任务本身 | 复核、审计（强制） |

各档是否可用，要逐家验证：原生复制各家支持不同；跨家转录的实际损失，要在 Windows 上实测。

## 6. 按对象划分

| 对象 | 例子 | 寿命 | 自有记忆 | 可读范围 |
| --- | --- | --- | --- | --- |
| 短期对象 | 施工工人、子任务 agent、一次性复核方 | 一个任务 | 无长期记忆，经历写入项目记账 | 固定前缀、任务、按需召回的项目记忆 |
| 长期对象 | 项目主控、项目审计席 | 与项目同寿 | 席位记忆：工作方式、未了事项、与 Owner 的往来；会话轮换，席位记忆沿交接链延续 | 本项目全部记忆（受权限闸约束） |
| 跨项目对象 | 秘书长 | 跨所有项目 | 全局记忆：Owner 偏好、跨项目经验、各项目总体状态 | 各项目上报的摘要，不读原始材料 |
| Owner | — | 永久 | 偏好与决定 | 全部 |

规则：
- 短期对象用完即弃，可以随需大量生成。
- 长期对象的连续性靠席位记忆，不靠同一个会话。
- 秘书长不得把一个项目的细节带进另一个项目。跨项目经验提升为全局记忆，须 Owner 授权。
- 偏好与决定只有 Owner 能改。做梦可以提议，但不能生效。

## 7. 按场景划分

| 场景 | 继承档 | 何时换 | 写回 |
| --- | --- | --- | --- |
| 连续施工 | 同家原生续接 | 任务边界、会话损坏、额度到头 | 检查点、死路、记账 |
| 派子任务 / 并行施工 | 零继承或交接包，先划写入范围 | 子任务完成即结束 | 结果交回主控，经历进记账 |
| 复核 / 审计 | 强制零继承，最好换厂商 | 一次复核一个会话 | 结论进收件箱 |
| 侧边聊天（Owner 与审计席、秘书长） | 主线的只读快照 | 可长期续聊 | Owner 选定的结论经收件箱递交主控，不直接灌入主线 |
| 同家换窗 | 原生续接或冷重建 | 按判断标准 | 交接包 |
| 跨家交接 | 跨家转录或交接包 | 额度预警、需要换能力或独立性 | 交接包与记账 |
| 故障恢复（崩溃、空转） | 交接包，以机械提取为主（旧会话不可信） | 立即 | 故障记录，经做梦提炼为坑 |
| 跨项目汇报与调度 | 各项目上报摘要 | 定期 | 全局状态 |
| 方向讨论 | 长对话续接 | Owner 决定 | 候选方向与 Owner 的决定 |
| 新项目冷启动 | 全局记忆中可跨项目使用的部分 | 开始时 | 项目第一版固定前缀 |

这两张表只是切换决策器的默认参数。哪个场景用哪一档更好，将来由记账数据检验，并作为反射学习的对象。

## 8. 主要流程

- **开新会话：**任务 → 决策器选厂商、账号和继承档 → 权限闸 → 装配固定前缀与召回的记忆 → 启动 → 登记。
- **运行中换会话：**健康监测发出信号 → 决策器判断现在换还是等 → 到安全点 → 生成交接包 → 验证 → 新会话接手 → 旧会话归档。
- **额度到边界：**额度守卫预警 → 本轮完成 → 写检查点 → 等窗口刷新后原地续接，或转录到另一家有额度的账号。
- **并行：**先发放写入范围租约，再分别开会话。
- **收尾：**复盘 → 记账 → 空闲时做梦。

## 9. 做梦机制

做梦按对象分层进行：
- 短期对象：不做梦，其经历在项目层统一整理；
- 长期对象：整理席位记忆，提议改进其固定前缀与工作方式；
- 项目层：整理反复出现的坑、有效做法、过时事实；
- 跨项目层（秘书长）：提炼通用经验，只能提案，须 Owner 授权才能提升为全局记忆。

做梦的产出：
- 合并重复记忆，替换过时记忆，标出互相矛盾的；
- 提炼坑与有效做法；
- 提议改进程序记忆：固定前缀、交接提取方式、切换标准；
- 遗忘：长期未用或已被推翻的记忆降级、归档，出处保留。

边界：
- 只出提案，经下游结果验证、分阶段放权后才生效；
- **规则、偏好、权限三类记忆，做梦永远不能改。**直接把整理结果写进 AGENTS.md 的做法（如 OpenDream）正是要避开的：AI 自写的规则文件有害；
- 可自动生效的只有低风险类别：事实、坑、提取提示词。

## 10. 度量

- 每次交接重读的 token；
- 提示词缓存命中率；
- 交接后返工率，以及重叠验证通过率；
- 额度利用率；
- 从空转出现到处置的时间；
- 记忆召回后的成功与返工比例。

## 11. 落地方式：架构要全，施工要小

1. **最小核心（R4 之后）：**
   - 会话登记簿、切换决策点（全部用规则）、记账；
   - 场景只覆盖连续施工和复核；
   - 厂商先接 Codex 和 Claude。
2. **按痛点补：**
   - 记账暴露哪里最痛就先补哪块，例如跨家交接返工多就先补交接包，额度常撞墙就先补额度守卫；
   - 随后是长期记忆库和"用了就回写"。
3. **有数据之后：**做梦、跨家转录、重叠验证、更多厂商；Jev 陪跑。
4. **校准过的类别逐类放权。**

架构图上的其余部件，等痛点出现再上，不一次建完。

## 12. 待验证

- 各家能否原生复制会话，续接是否合规（可借 Resume Means Resume 的合规测试方法逐家测）；
- 跨家转录在 Windows 上的实际损失；
- 在 Windows 上能否获取各家账号的剩余额度；
- 各家报告的缓存命中数据是否可靠；
- 重叠验证本身的成本。

## 13. 当天被推翻的判断

- "跨家只能走交接包，必然有损"：错。会话转录工具可以把整段对话转成目标 CLI 的原生格式续接，只丢思考过程和图片。
- "订阅额度看不到，只能撞墙后处理"：错。已有工具定时查询账号的 5 小时与每周额度，可以提前在边界交接。
- "接手会话复述一遍即可验证交接"：不成立。复述只能证明读过交接包，证明不了交接包完整。已改为重叠验证与下游返工率。
- "每到任务边界就冷重建"：一刀切，与成本原则矛盾。已改为按条件判断。
