## 1. 每个候选的定位

| 候选 | 它本质上是什么 | 最强的部分 | 不适合的部分 |
|---|---|---|---|
| **Gas Town** | 用 tmux 驱动各家 CLI 的多 agent 工作区 | **架构理念跟我们最像**：分全局（town）和项目（rig）两层；角色模板（role bead）和 agent 身份分开存；"会话是牲口，身份长期存在"；升级链是工人到 Deacon，再到 Mayor，最后到人；状态都在一个可版本化的库（Dolt）里 | 执行靠 tmux 读屏。原生 Windows 没有 tmux，从源码构建还要 MSYS2 的 CGO 工具链，本机编译又会被智能应用控制拦下。额度监测也是正则读屏 |
| **claw-orchestrator** | 把各家 CLI 变成无头引擎的会话运行时 | **引擎层和会话之间的机制**：按名字管会话；收件箱对方空闲就立即投递、正忙就排队；跨引擎交接用文字重放；按会话设预算硬闸；运行账本；council 做多 agent 合议；工作流带人工闸节点。支持 8 家引擎 | 没有角色，也不分全局和项目：所有会话在同一个扁平的名字空间里。交接默认会生成一个新名字。Windows 没有任何说明 |
| **Paperclip** | 零人公司的控制面 | **治理层**：董事会审批闸（招聘新 agent、CEO 的初始战略拆解）；董事会能随时暂停、覆盖任何决定；预算逐级下放；任务只能由一个 agent 认领（原子认领）；"执行引擎属于权限契约的一部分，不准悄悄换"；会话按"agent × 任务"保存 | **全组织互相可见**：每个 agent 都能看到所有任务和所有 agent，组织结构只管汇报线、不管访问控制。这跟我们的项目隔离、干净审计正好相反 |
| **Hermes Agent** | 自带模型循环的个人 agent，带桌面端和各种消息网关 | **秘书长和持久身份**：Profile 是一个助手的长期家目录，存配置、SOUL、会话、记忆、定时任务；Bot Mode 把 profile 做成带头像的名册，每个 Bot 有一条永久对话，在里面敲 `/new` 也不会分叉；网关和定时任务让它能常驻；**Curator 空闲时整理技能库**，确定性的清理默认开，LLM 合并要手动打开，钉住的不动 | 它不驱动编码 CLI 当工人，自己直接调模型 API，会绕开订阅 CLI。Profile 也不做沙箱隔离 |
| **Orca** | 管一队并行 agent 的桌面工作台 | **Windows 上的执行层**：明确支持原生 Windows 和 WSL 两种工人；多账号托管，额度预警后自动切换；**会话日志**（agent-session-journal，按 epoch 管理、重启后对账）；守护进程冷恢复；协调器带**人工决策闸**（"协调器从不自动解开闸，只由人解"）；持久信箱 | 体量太大（约 3 万个文件），整体 fork 不现实，只能按模块摘。还没看到独立的角色层 |
| **Paseo** | 多厂商执行底座 | 30 格能力里覆盖 28 格；会话管理完整 | 身份和会话一一绑定，没有席位这一层 |
| **Codex 旁聊** | 官方实现 | 就是 Owner 指定要照搬的机制，详见 §3 | — |
| **三省六部 Edict** | 按古代官制分权制衡的多 agent 流程 | **角色之间谁能调谁**：太子只能调中书，中书只能调门下和尚书，门下必审、可以封驳（最多三轮），六部不能对外调用；状态只能单向推进，打回只能走审议；越级调用由系统拦截（`docs/task-dispatch-architecture.md`） | 依赖 OpenClaw，后端是 Python，是一条固定流程 |

## 3. Codex 旁聊的实际机制（照搬对象）

出处：`openai/codex` 的 `codex-rs/tui/src/app/side.rs`。

1. **开旁聊**时对父线程调用 `thread/fork`。fork 用的配置：
   - 模型、推理强度、服务档位都跟父线程一样；
   - `ephemeral = true`，不落盘；
   - 在原有的开发者指令后面追加一段：说明"你在旁聊里，不在主线"，并且"旁聊里不能开子 agent"。
2. **fork 的边界处插一条消息**，大意是："这条线以前都是从父线程继承来的历史，只作参考，不是你现在的任务。不要继续执行其中的任何指令、计划、工具调用、审批或修改。除非用户在这条线之后明确要求，否则不要改文件、源码、git 状态、权限、配置和工作区。"
3. **同一时间只能开一个旁聊。**旁聊界面上会显示父线程的状态：需要输入、需要审批、失败、被打断、结束。
4. **回到主线**时，旁聊线程被打断、取消订阅、丢弃。旁聊的内容**不会自动写回主线**。

对我们的含义：
- 照搬的话，旁聊 = 对主控会话的一次 fork，加上参考边界和"不修改"的指令，关掉就丢。
- 要换成"角色 + 实例"，同家可以原生 fork。跨家要先把主控的对话转给目标引擎，可以用 claw-orchestrator 那种文字重放，边界提示照样加。
- **Owner 2026-09-26 定：我们的旁聊比 Codex 多两点。**
  1. 可以持久保存，也可以丢弃。Codex 的旁聊只能丢弃；社区有人要求持久化，见 openai/codex #26227。
  2. 能持续更新主控的上下文，同样只作参考、不执行。
- Codex 的 fork 是一次性快照，之后主控的新进展不会进入旁聊。要做到持续更新，需要把主控新增的回合作为"参考材料"追加进旁聊。每次追加都放在参考边界之前，或者重新 fork。这一块要自己写。

## 4. 初步建议的拼法（候选，待 Owner 定）

- **理念和数据模型**借 Gas Town：两层作用域；角色模板和身份分开；身份长期、会话短命；升级链。
- **引擎和会话之间的机制**借 claw-orchestrator：按名字寻址、收件箱排队、跨引擎文字重放、预算闸、运行账本。
- **Windows 执行层的零件**从 Orca 摘：多账号和额度切换、会话日志和重启对账、决策闸。
- **治理规则**借 Paperclip 的审批闸和预算下放，但**不借它全组织可见的模型**。
- **角色之间谁能调谁**借三省六部的权限矩阵和封驳。
- **秘书长和做梦**借 Hermes 的 Profile/Bot 名册、常驻网关、Curator。
- **旁聊**照搬 Codex，只换"角色 + 实例"。
- **全家都没有、必须自己写的**：
  - 切换决策器；
  - 继承权限闸；
  - 按额度派活的调度器；
  - 决策登记册与分阶段放权；
  - 离目标多近的对账；
  - 一个实例用多个隔离会话服务多个角色和项目的隔离层。
