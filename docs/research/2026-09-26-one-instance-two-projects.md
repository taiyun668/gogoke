# 实验 5：同一个实例开两个项目，会不会串

- 日期：2026-09-26
- 对应：设计 37 §12 实验 5。
- 方法：
  - 用本机已登录的 CLI 实例，不复制凭证、不另建家目录；
  - 在两个互不相干的空目录里各开会话，看后开的会话能不能看到别的项目的东西；
  - 用的模型：Codex `gpt-6-luna`、Claude `claude-haiku-4-5`、OpenCode 免费模型，每家调用几次；
  - Grok 和 Antigravity 这一轮没测。

## 复核（Owner 2026-09-26 指出：测试没有完全复现正式场景）

- **OpenCode 往上读到临时目录里的规则文件**：测试环境造成的。测试项目放在系统临时目录下，而那里恰好有一份旧的规则副本。正式场景里项目是 Git 仓库，放在宿主管理的固定位置。
- **OpenCode 用了继承来的 `PWD`**：测试环境造成的。`PWD` 来自启动测试脚本的命令行；正式场景里进程由 Rust 宿主从桌面程序拉起，没有这个变量。
- **Codex 记忆跨项目**：机制成立，但程度被测试放大了。测试用的是 Owner 个人的 Codex 目录，里面攒着几个月来所有项目的记忆。记忆一个实例目录只有一份，这一点跟测试方式无关：Owner 那份记忆里本来就混着多个项目的总结，这就是直接证据。只要一个实例目录同时服务多个项目，就会串，区别只是正式场景里是慢慢攒出来的。
- 所以下面第 2、3 条撤回，只保留第 1 条中关于厂商记忆的部分。

## 对设计 37 的影响（原稿，第 2、3 条已撤回）

1. **实例一级的家目录是跨项目共享的**，里面放的东西会进入所有项目的会话，包括全局指令文件和厂商自己的记忆。所以：
   - 宿主给每个会话关掉厂商自己的跨项目记忆，例如 Codex 用 `-c features.memories=false`。记忆由我们自己按"作用域 × 席位 × 会话"来管（§3a）；
   - 全局指令文件只能放不分项目的规则。
2. **会话工作区不能放在有祖先指令文件的位置**，否则会被 OpenCode 这类往上找的 CLI 读进去。宿主开会话前检查工作区的上级目录，或者放在一个固定的、确认干净的根下面。
3. **子进程的环境变量由宿主明确构造，不继承父进程的**，尤其是 `PWD`。这跟"传给 CLI 的内容一律走 stdin 或文件"是同一类规则。
4. 续接用会话 ID，不用"最近一次"。这一条设计里已经有了：寻址用席位身份。

## 还没确认的

- 关掉 Codex 记忆以后，这个会话结束时，会不会仍被总结进账号的全局记忆。也就是只关了"读"，有没有关掉"写"。
- Grok、Antigravity 没测。
- 这次测试开了一个非临时的 Codex 会话，内容只是一个无意义的暗号。它有可能被 Codex 总结进账号记忆里。
