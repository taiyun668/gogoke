# 设置与功能研究

**产品范围说明：GOGO 面向多种成果生产，软件施工与通用生产两套模式并行。软件模式保留 Git、diff 和测试等既有要求，通用模式采用对应成果的审查依据；共用基础交互，允许同项目协作。完整方向见[改版研究总图](revision-map.html)。**

设置不能只是把主界面装不下的东西放进去。它要回答四个问题：**能改什么、改谁、何时生效、失败怎么办。** 查看运行事实、修改个人偏好、管理账号连接、执行项目操作，应当分清。

[打开可搜索的设置功能地图](settings-map.html)。它是研究目录，不连接任何账号或真实配置；源码快照沿用前两份报告。

## 1. 五家的设置内容与组织

### AionUi：围绕 Agent、模型与工具展开

当前内置设置入口为 Agent、模型、Skills、工具、外观、WebUI、桌面宠物、系统、归档、关于；扩展可以插入额外设置页。桌面宠物在浏览器模式隐藏，不能把所有平台的设置看作相同。[A1](#a1)

- **Agent：** 本地 CLI 列表、检测、编辑、环境变量、关联助手与修复入口。助手身份/规则/技能与底层运行程序是不同对象，不能都叫“模型”。
- **模型：** 接入平台和模型目录；支持新增平台、模型，以及相应配置。它不是设置当前每个正在运行的成员都立刻切换。
- **Skills / 工具：** 技能导入、详情、文件与使用关系；MCP 服务、工具列表、连接与相应授权。选择服务器、配置传输和确认可用，是不同动作。[A2](#a2)
- **外观：** 主题、应用/聊天/Markdown/代码四个阅读区域的字体设置，以及缩放。局部阅读需求不必靠整个应用一起放大解决。[A3](#a3)
- **系统：** 语言、开机启动、关闭到托盘、通知、语音输入、工作/日志目录、预览大小、空闲与请求超时等；硬件加速是需要明确重启影响的例子。[A4](#a4)
- **WebUI / 消息渠道：** 开停远程访问服务、连接信息，以及多个消息渠道的配置。服务开关读取真实运行状态，而不是仅把保存的启用意图当成“已经运行”。[A5](#a5)

值得借鉴的是功能分组与按区域调整阅读；不宜照搬的是大量运行参数直接成为普通用户的默认设置。远程访问、账号操作、安装与普通外观偏好，也不应采用完全相同的保存语义。

### Cindy：统一连接，加上广泛的个人工作环境

Cindy 当前设置包含通用、个性化、模型供应商、计费、用量、语音、IM、快捷键、Agent Island、导入、远程控制、插件、内置工具、Computer Use、存储、帮助与关于等入口；有些受平台、登录身份或开发条件限制。旧的连接/API-key 标识和 Pi 扩展入口并不都仍是一级设置页。[C1](#c1)

- **通用：** 外观、语言、通知、窗口行为、发送快捷键、团队并发/资源相关设置、Git 自动快照和实验功能。
- **个性化：** 指令、记忆、联系人、压缩、终端 shell、链接打开位置和流式显示等。
- **模型供应商：** 用“连接”统一管理订阅、独立登录、API 与本地模型。品牌、连接实例、是否启用、登录/验证状态、用量分别表达。
- **工具与扩展：** 插件/Skill 目录、内置工具与 MCP，以及电脑控制能力；不是所有工具都放在一个原始 JSON 表单里。
- **跨端与外部入口：** 远程控制、IM、语音、会话导入。
- **数据与账户：** 存储管理、计费和用量历史。用量统计与账号账单不是一个数字。[C1](#c1)

最值得参考的是连接状态的表达：已保存 API 配置不等于已验证连接；用量读取失败不等于账号断开；停用连接也不意味着登录失效。详情保留一个主要动作和更多菜单，不让同一种连接因为实现方式不同就换一套界面。[C2](#c2)

它还提供“已自定义 / 恢复默认”的控件。记忆设置会区分不支持、读取中、进行中，并能明确提示新会话生效。当前模型、任务基线、待生效选择也有各自语义。[C3](#c3)

不宜整套复制其设置规模。Cindy 的业务覆盖比 GOGO 宽得多；并发参数、压缩、插件、设备和多种账号来源，不应变成开始一项普通工作的必修课。

### Orca：开发环境、工具与远程主机设置最完整

官方设置参考覆盖 General、Appearance、Git、Terminal、Quick Commands、Agents、Browser、Artifacts、Integrations、Notifications、Voice、SSH、Remote Servers、Shortcuts、Repository、Floating Workspace、Plugins 与 Experimental。它有设置搜索，也把项目相关设置从通用设置中区分。[O1](#o1)

- **开发现场：** 默认分支、仓库脚本、终端字体/shell、编辑器、文件预览、浏览器配置、快捷命令。
- **Agent：** 可用 CLI、启动参数、原生权限模式、状态 hook、账号与休眠/保活相关功能。
- **跨端：** SSH、配对的远程运行端、浏览器在哪台机器执行、命令属于哪台主机。
- **交付：** 公开成果链接、Diff、GitHub/Linear/Jira 等外部协作系统。
- **个人使用：** 主题、密度、字体、缩放、声音、通知类别、语音与快捷键。

它清楚区分了“配置存在哪”“属于哪个项目”和“执行发生在哪”。例如浏览器默认缩放只影响新页面，显示设置与运行端的设置并不总属于同一台机器。[O1](#o1)

**不能借用它的权限默认值。** Orca 的 Agent 启动参数允许很强的自主权限；公开成果发布也会产生对外可访问的内容。减少交互阻力不等于把这些都当成普通开关。GOGO 应保留自己的既有权限边界。[O2](#o2)

### Vibe Kanban：项目、仓库和 Agent 配置分层

设置文档列出 General、Projects、Repositories、Organization、Remote Projects、Agents、MCP Servers。General 包括主题/语言、默认 Agent 与配置、编辑器、Git 和通知；Agent 配置采用“左边 Agent、右边配置版本”的两列结构，编辑后显式保存。[V1](#v1)

**默认配置不是硬锁。** 默认 Agent/variant 预填到新执行入口，用户可以在具体执行时覆盖。仓库设置另管准备脚本、开发服务器和清理脚本，避免每次发消息都重新配置一遍。[V2](#v2)

一个非常重要的边界：其 MCP 设置文档明确说明会写入所选 CLI 的全局配置，服务端也解析 Agent 默认配置路径后写回。因此不能只看到“一个好用的 MCP 编辑器”就照搬到 GOGO；必须先决定写的是应用、项目还是用户全局配置。[V3](#v3)

组织和远程项目的部分文档属于历史云服务。bloop 的停运公告说明本地工作区继续、远程服务转变，不能把这些旧设置页当成今天仍有官方托管功能的证据。[V4](#v4)

### Herdr：设置页小，完整运行配置在 TOML

Herdr 不只有配置文件。当前终端内的设置面板有 Theme、Indicators、Sound、Toast、Integrations 五类；高级行为仍通过配置文件和完整配置参考说明。[H1](#h1)

它最值得学习的是**客户端与服务器的边界**：主题、侧栏和复制等显示偏好来自客户端；pane 默认行为、worktree、集成与命令归运行服务器。重载可应用多数界面设置，启动型配置仍需重新创建或重启相应对象；修改默认 shell 不改变已存在的 pane。[H2](#h2)

这类清楚的归属说明对多设备产品很有价值，但不应该要求 GOGO 的普通用户先会编辑 TOML。

## 2. 设置界面应当有哪些组件

| 组件 | 必须说清楚的内容 | 建议交互 |
|---|---|---|
| 设置搜索 | 在哪里、改什么 | 搜索具体功能和常用别名，直接定位设置行 |
| 分类导航 | 用户能理解的目的 | 使用“连接与模型”“界面与输入”，避免把内部模块名原样搬来 |
| 设置行 | 名称、简短说明、当前值 | 简单偏好直接改；有依赖关系的多字段表单显式保存 |
| 范围提示 | 应用 / 此设备 / 项目 / 任务 / CLI 全局 | 放在设置旁边，不埋在日志或说明书里 |
| 生效提示 | 立即 / 下次发送 / 新任务 / 重启后 | 保存值与当前生效值不一致时同时说明 |
| 默认与覆盖 | 默认来自哪里，哪些已改 | 按项恢复默认；恢复影响范围明确 |
| 连接条目 | 名称、来源、真实状态、主要动作 | “已保存”“已验证”“占用中”“需登录”不能混用 |
| 能力状态 | 支持 / 不支持 / 尚未读取 / 失败 | 不支持的能力不要画成一个能开启的假开关 |
| 保存反馈 | 进行中、已保存、未保存、错误 | 失败保留编辑内容；不能仅弹成功文案就认定生效 |
| 危险操作区 | 删除、断开、公开发布等真实影响 | 与主题、字号等低影响设置分开，不用同一套轻率操作 |

设置里由用户主动打开的配置控件，与对话中由 CLI 发来的工作问题，是两种场景。“不让系统额外出工作选择题”不意味着取消主题或收件人这类基本应用控件；也不意味着给设置增加一套替模型决策的业务流程。

## 3. GOGO 当前已经有什么

本节只读当前未提交工作区源码，确认入口和代码路径，不把未完成施工当成通过验收的版本。

| 当前入口 | 已看到的内容 | 当前问题 / 边界 |
|---|---|---|
| 总览 | 房间、席位、实例、运行与 Git 概况 | 主要是诊断与管理信息，作为普通设置首页负担偏重 |
| 实例管理 | CLI 环境信息、实例列表、新建与登录、检测、绑定/占用状态及管理动作 | “实例”是内部概念，应该先让用户看懂自己连接的是谁、用在哪 |
| 席位 | 角色、CLI/模型、实例与状态；可进入席位详情 | 与实例页分离，但两者关系需要用户自己拼起来 |
| 房间 | 活跃、归档、置顶与 ID 列表 | 此页主要只读；具体操作也存在于侧栏菜单 |
| 运行诊断 | 路径、进程、端口、Git HEAD 和实际运行位置 | 必须保留，但不是用户每天要看的设置 |
| 界面 | 主题、密度、阅读宽度、减少动效 | 有真实代码；目前保存于当前浏览器 localStorage，而非项目配置或跨设备设置 |
| 关于 | 产品与凭据边界说明 | 可保留为帮助与关于 |

项目菜单还提供项目信息与重命名等操作；它不是一个已经完整的项目级配置系统。现有 UI 中未找到统一的用户级 Skills/MCP 管理、通知偏好、快捷键编辑、完整数据备份等设置入口；这不等于底层 CLI 没有相应能力。

源码定位：`<gogo-party>\packages\room\public\index.html` 中 `settingsPage`、`drawInstances`、`drawSeatsPage`、`drawRoomsPage`、`drawEnvPage`、`drawAppearancePage`、`setPref` 和 `openProjectSettings`。研究未修改这些文件。

## 4. GOGO 候选设置结构

这是一份可供后续决定的组织方案，不是新增功能已经批准或实现。

| 一级分类 | 放什么 | 当前处理建议 |
|---|---|---|
| 界面与输入 | 主题、密度、字号/阅读宽度、动效；通知和快捷键在有实现后接入 | 先重组现有显示偏好；缺失能力明确标候选 |
| 连接与模型 | 已连接 CLI/账号、真实状态、模型目录与能力 | 把实例管理翻译为用户语言，保持账户/实例/席位的真实绑定 |
| 项目与团队 | 工作位置、席位角色、模型/实例绑定、项目规则入口 | 现有项目和席位配置归位；不固定所有项目的施工流程 |
| 工具与扩展 | 已发现的 CLI 能力、Skills、MCP、插件 | 先做能力与作用范围核对；没有真实读写通道就不画开关 |
| 数据与隐私 | 数据位置、凭据归属、导出/清理等明确操作 | 现有事实先展示；新操作单独设计，不自动清理或复制凭据 |
| 诊断与关于 | 运行健康、版本、进程、日志、Git 与帮助 | 承接现有总览和诊断，平时安静，需要时能迅速找到 |

开工、对账、验收、转交是工作中的动作；进程号、HEAD、日志是诊断事实。它们不应全部伪装成“设置”，更不应让用户每次操作都重新进设置页。

## 5. 优先级

**先整理已有内容：** 把偏好、连接、团队与诊断分开；把名称、状态与作用范围说清；统一设置行、说明和保存反馈。

**再补确实缺失的用户能力：** 通知、快捷键、能力目录、数据导出等逐项确认需求与真实接口，不因竞争产品有就全部加入。

**暂不照搬：** 并发阈值编辑、自动降级策略、宿主自造审批、公开分享、远程控制、全局 CLI 配置编辑、桌面宠物和复杂实验功能。它们各有独立范围与风险，不是美化设置页的附属品。
