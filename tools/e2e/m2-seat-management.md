# M2 seat management E2E package

`m2-seat-management.mjs` exports `runSeatManagementCases(product, config, journal)` and starts nothing on import. It runs only against the installed candidate through the same `window.__TAURI_INTERNALS__.invoke('gogoke_design37_user_operation', ...)` User bridge as the UI. Requests and raw receipts are saved before and after the single invocation. Unknown, denied, timed out, or disconnected calls stop the flow; the module never retries a write.

## What the case measures

The direct producer is native `K-SEAT/create-from-template`: it reads the actual domain-scoped row in `gogoke_v37_seat_templates` and creates an idle USER seat plus copied `gogoke_v37_seat_settings`. `K-SEAT/tune` updates that copied seat under its own revision. The driver creates one seat in each of two configured, actual `gogokeSeatTestbed` domains, changes only project A, and reads both seats back. The falsifier is the normally closed candidate's immutable database: the durable `seat_operations.fingerprint` must recompute from each exact original request frame and producer input, its operation snapshot must match the original receipt and persisted settings, and each state-card's request/receipt BLOB must match byte for byte. Both configured templates must match their pre-case hashes; A's settings and revision must match its tune receipt; B must still match its original copy receipt. Missing templates, preexisting targets, wrong identities/revisions, receipt drift, or changed B settings fail the evidence chain.

Optional `leadSeat` exercises the separate V06 User control over a real LEAD seat: User `tune`, state-card, then `reclaim`. Its private fixture must provide its exact `domainId`, `seatId`, `parentSeatId`, `incarnation`, `generation`, `revision`, and a non-secret string `value`; the runner copies the authoritative `config.setting` into the journaled LEAD case before issuing that exact tune. The baseline readback first compares those producer facts to the live native rows, including an IDLE LEAD and a live USER parent; it will not use the main M2 child or invent a target. Missing fixture means `USER_LEAD_TUNE_AND_RECLAIM: NOT_RUN_NOT_CONFIGURED`.

## Optional original model denial

The model case runs only when `originalSessionId` is supplied and the case has a project in the original product domain, with `originalModelAttempt` as a callback into the already running root session. The callback receives one exact `gogoke_seat tune` prompt aimed at that case's USER copy and returns `{ domainId, sessionId, sendRequestId, turnId }` from the actual H turn. It must not synthesize or copy a result. The final reader independently follows the original H send, raw A `item/tool/call`, matching H-written RPC response, and native K-SEAT DENIED receipt carried in that response. It verifies the original session's H process stop fact before normal close, and that the target's final state matches its subsequent User operation history. A model denial has no successful `seat_operations` row or K-SEAT ledger receipt; the actual H-written receipt and unchanged pre-User state are its producer evidence. If the original-session callback or same-domain target is unavailable, this case is `NOT_RUN`, never a substitute User request.

## Private fixture and reader callback

`config.seatManagement` is private and must include:

- `lifecycleOwnership: "EXCLUSIVE_M2_SEAT_MANAGEMENT"`;
- `projects`: exactly two distinct real domains, same existing `templateId`, repository ID `gogokeSeatTestbed`, and an unused, exact `seatId` in each;
- a harmless test `setting` and non-secret string `value`;
- `normalCloseReadbackRestart(phase)`, for `baseline` and `final`.

The callback must settle and natively stop every live H session, then close the same installed product normally. After `baseline`, it restarts that candidate and resumes the original root session before the optional model callback; after `final`, it restarts for the caller. A caption close is not evidence of a seat process stop. The callback invokes the signed Python reader as `m2-seat-management-readback.py STATE_ROOT OUTPUT JOURNAL baseline|final` and returns `{ file, sha256 }` for the private output. The reader resolves `STATE_ROOT` against the case journal, requires `OUTPUT` and the journal to live in the case evidence directory outside that root, and binds the latest actual candidate launch to its exit-code-zero normal close and PID. It records Python device/inode identity plus installed byte pins, resource-set ID and generation ID; final readback must match baseline root/candidate identity. Node rehashes the actual proof file against the callback's SHA-256 before using it. Each phase requires an empty or absent WAL, opens only `state.sqlite` as `mode=ro&immutable=1`, and verifies database/sidecar hashes are unchanged by measurement. The final proof and runner record keep `acceptance: false`; they are evidence for Controller/Auditor review, not acceptance.

## References and limits

Read-only precedents checked: M2 `product-cdp.mjs`, `m2-history-boundaries.mjs` and its immutable reader, `m2-rules-readback.py`, and native `v37_seat.rs` / `seat/mod.rs`; the latter establish the actual User bridge producer, K-SEAT receipts, and seat/template persistence. GOGO PARTY's `packages/seat-runtime/src/demo.ts` and `seat-runtime.ts` demonstrate a persistent user-owned seat and durable events. Searches of the historical GOGO PARTY, NaveHQ, and LoomOS trees found no equivalent installed Tauri bridge plus immutable candidate-SQLite flow, so this package follows gogoke's native request/receipt and database evidence. It does not build, sign, install, log in, start another model/session, or claim V06 complete. Template content is not copied to the readback artifact; it is represented there by a SHA-256.
