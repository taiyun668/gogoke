# Installed-product M2 side chat (V12)

`runSideChatCase(product, config, journal)` is an imported module; import alone does nothing. Development validation is only `node --check tools/e2e/m2-sidechat.mjs` and `git diff --check`. Real Win11 E2E is **NOT_RUN** until the Controller runs it against the exact installed candidate and independently reads the original A/H records. The module returns `FLOW_COMPLETE_DIRECT_LEDGER_READBACK_REQUIRED`, never acceptance or PASS.

The M2 runner calls it after its main parent has stopped and released. The module owns two newly created logical sessions on two distinct existing test seats/worktrees and stops/releases only those sessions. It uses the original `ActualProduct` hard locator/CDP and User ingress. It never controls authentication pages, logs in, reads credentials, launches a second browser, uses agent actions or configures telemetry. The existing signed Node runtime executes this script; no native build or new executable is required (`docs/governance/gogoke-build-and-release.md`).

## Parameters

The outer config retains the runner's exact `sourceCommit`, installed byte binding, `domainId`, and `repositoryId: "gogokeSeatTestbed"`. Its private `sideChat` configuration supplies `sourceSeatId`, `sourceInstanceId`, `sourceWorktreeId`, `sideSeatId`, `sideInstanceId`, `sideWorktreeId`, `sideWorktreeRoot`, `ledgerEpoch`, `sourceCursor` (canonical decimal, normally `"0"`), and `lifecycleOwnership: "EXCLUSIVE_V12_SOURCE_AND_SIDE"`. Both instances must already be the admitted fixed Codex 0.160.0 and logged in; both seats must be IDLE, with the side's existing permission tier ISOLATED_WRITE or NETWORKED_WRITE. This Codex case does not claim V12 coverage for other providers.

The runner supplies `sideChat.restartProduct` as an in-memory callback: `async () => { await product.closeNormally(); await product.launch(); }`. It is not serialized into private JSON. All other active model work must already have ended before calling the module. The original source is an independent V12 session; the main lead is never reused or implicitly stopped.

The same journal must contain this run's original K-WORKTREE/create APPLIED receipts for both independent worktrees; current F graph reads must bind the IDs to the exact test domain/repository/seat/instance. Before invoking the module, the runner creates/registers the two roots, normally closes the candidate, runs the existing `m2-readback.py` `side-worktrees` phase and normally restarts. `sideChat.worktreeReadback={file,sha256}` names that original private artifact (basename inside `config.evidenceDirectory`) and its exact hash. The artifact carries `phase: "side-worktrees"`, `databaseWrites: false`, `credentialReads: false`, and two `worktrees[]` rows with `worktreeId,domainId,repositoryId,seatId,instanceId,path,rootIdentity`. Python root identity uses `{observer:"python-stat",device:"decimal string",inode:"decimal string"}`; the native opaque F identity is separate. The module copies the original artifact reference/rows into the case and checks the side path before file or model operations. Missing artifact returns NOT_RUN. Node measures its own exact root identity before and after the case; it never compares Python numbers or native opaque identities to Node dev/ino. Final readback remeasures the original Python identity with Python. Public F create/graph receipts do not expose a path, so config alone cannot prove a physical root. No active writer is read with `immutable` and no new probe is added.

## Actual flow and evidence

One unique canary JSON file is seeded with `wx` in the original side worktree solely for the negative control. The positive write is never performed by the driver. Both sessions use the existing native admission chain. The side's creation uses `owner-side-open` with original nested K-SESSION/open and K-SIDE/create bytes. The source receives one explicitly authorized request to emit a clearly untrusted write induction as actual assistant output, with no tools. Its original completed turn and A metadata are observed; `owner-side-collect` then stores D pending cursor ranges. It never sends an H input or creates a model turn.

Before any side question, the script records the real side raw/ledger high-water marks, absence of normalized turns/tools and unchanged canary hash. The final independent readback must check raw A as well, including unnormalized frames. Only then does the module send one explicit Owner test question through `owner-side-question`. Success needs actual CLI tool completion, original turn completion, a changed ordinary file with the authorized marker and the original H stdin receipt. A model's success statement cannot satisfy those checks.

Both exclusive sessions then acquire real Job stop facts. A normal product restart is followed by D resume and own-transcript readback, archive/restore and identical original SIDE event identities. Empty filtered pages are traversed by A's cursor, not treated as exhaustion. Deletion uses the real D lifecycle; source ledger event bytes must compare identical before/after. The two stopped sessions are released at the end; the real product stays available for the runner's later cases.

Every mutation and its original bytes is persisted before dispatch and sent once. UNKNOWN, STALE write, disconnect, source error or deadline fails and retains the original evidence; there is no retry under a new mutation ID, fake model, permission expansion or forced process cleanup. Only new read requests poll native facts. Failure leaves the candidate/session/file custody with the Controller.

`journal.sideChatCases[]` contains `caseId`, five `caseIds`, state/non-acceptance, source and side sessions, original open/create/question requests, composition request hashes and nested IDs, source send ID, D settlement receipt, injection/target markers, initial/passive/final file hashes, the passive A boundary, transcript source event IDs/hash, lifecycle receipts, source ledger before/after delete, and `readbackRequirements`. Original composition bytes/results/errors remain in `journal.operations[]`; no database is copied into evidence. The independent `m2-readback` must require exactly the recorded source and side sends, zero side append or automatic turns, no source tools, no side tool before/outside the explicit turn, a successful actual target tool and source-bound original H receipt, cursor references without a second authoritative source context, and source ledger preservation after deletion. Missing raw evidence remains NOT_RUN or FAIL.
