# V11 installed file-boundary entry

`m2-stop-worktree-v11-win11.mjs` gives the existing `m2-v11-boundaries.mjs` and `m2-v11-readback.py file` one explicit installed-product entry. It invokes the original User E/F reads and H reserve, commit, open, send, output, stop and release for the selected main-source and READ_ONLY F-tree attempts. It then normally closes the same candidate and reads the original A/H/F rows and exact tool result from the immutable database. The `nativeFileChange` mode requests one native `apply_patch` Add File on a fresh, nonsecret target; the existing `execCommand` mode remains available for historical cases. A failed tool remains cause-unattributed; model prose, a missing tool, a CLI patch refusal or generic DENIED never establishes an OS/LPAC permission result.

Run with signed Node and a fresh private config, after two separate runs of `m2-stop-worktree-prepare.mjs` have produced distinct registered SINGLE worktrees and IDLE USER seats in the same `gogokeSeatTestbed` domain. Use an existing eligible `NETWORKED_WRITE` template for the main-source attempt and an existing eligible `READ_ONLY` template for the second. The V11 entry rechecks each exact seat state, tier and F graph before opening H. Do not rerun a preparer after it has mutated its original fixture.

```text
node tools/e2e/m2-stop-worktree-v11-win11.mjs PRIVATE_CONFIG.json
```

The config carries the same installed byte pins, source commit, `stateRoot`, `testbedSource`, signed `pwsh`/`python`, `domainId`, `repositoryId: "gogokeSeatTestbed"`, new `evidenceDirectory` and nonexistent `result` path required by `m2-stop-worktree-win11.mjs`, plus:

```js
v11FileBoundaries: {
  ownership: 'EXCLUSIVE_V11_FILE_BOUNDARIES',
  mainWrite: { seatId, instanceId, worktreeId, worktreePath, attemptMode: 'nativeFileChange' },
  readOnlyWrite: { seatId, instanceId, worktreeId, worktreePath, attemptMode: 'execCommand' },
}
```

For a fresh MAIN_WRITE attempt when the READ_ONLY CLI is unavailable or an outside
attempt has already been preserved, set `v11FileBoundaries.onlyMainWrite: true`.
Both original preparation bindings are still required; only MAIN_WRITE opens a
new H and sends a new turn. READ_ONLY and outside remain explicitly NOT_RUN in
this journal and the immutable reader. The default still runs all three attempts;
neither selection mode grants whole V11 or acceptance credit. Do not reuse a result
path or reissue an old input to fill missing evidence.

For a new MAIN_WRITE plus outside-file attempt while the fixed READ_ONLY pin is
unavailable, select `v11FileBoundaries.mainAndOutsideOnly: true` and leave
`onlyMainWrite` false or absent. The file helper then opens only MAIN_WRITE;
the installed entry separately runs outside against that released seat. READ_ONLY
is recorded NOT_RUN. This selection is mutually exclusive with `onlyMainWrite`;
the default and historical `onlyMainWrite` paths keep their earlier behavior.

`seatId`, `instanceId`, `worktreeId` and `worktreePath` must come from each original final preparation proof and its state-card/F graph, not a display label or guessed path. Supply the workdir in its ordinary DOS spelling for a historical CMD case; the reader verifies that it is the exact registered F object even when the host record uses extended-length spelling. `nativeFileChange` builds one exact Add File patch for the newly generated target and asks for no read, CMD, Git, network or credential action. The closed reader requires the original H body, one same-thread/turn A fileChange start/completion pair, the matching H normalized item, the attempted target path/diff, original failed status/error, absent target, physical F/source facts and real stop/release. If the fixed CLI declines the patch before a target-bound fileChange exists, that attempt remains NOT_RUN for the boundary. The old CMD failures retain their original bytes and are never replayed.

The same run then reuses the stopped and released `mainWrite` seat/F tree for one separate original H turn against a new **empty private D directory** outside the candidate, source, evidence, repository and all registered F worktrees. Add:

```js
v11OutsideTree: {
  ownership: 'EXCLUSIVE_V11_OUTSIDE_TREE',
  outsideRoot: '<fresh empty private D directory>',
  attemptMode: 'nativeFileChange',
}
```

Before candidate launch or any model input, the runner uses the existing candidate-registration check and a separate read-only process census of the exact installed `gogoke.exe` and `gogoke-native-host.exe` before and after `m2-stop-worktree-v11-readback.py preflight`. The latter reads the closed, empty-WAL database; registration alone is not process-absence evidence. That immutable read seals the complete existing F worktree and repository-source rows with their physical identities and refuses an `outsideRoot` overlapping any of them. Its private file hash is bound into the journal before launch. This package creates no F/source registration; the final closed read repeats the same inventory and requires exact equality.

The outside attempt asks for one exact native `apply_patch` Add File on a new marker; omitting `attemptMode` preserves the historical `execCommand` request. The final reader checks the complete pre/post F/source/root inventory, original E tier and F registration, H input/turn/StopFact/release, A thread/start, turn/start, typed ACK, the matched fileChange pair and normalized H item, absence of any outside file, and unchanged database/WAL/SHM bytes. It keeps raw failed, declined and other statuses distinct. `directCaseEvidence` remains false and `permissionCause` remains UNATTRIBUTED; an original CLI parser rejection or no fileChange is not an OS permission pass.

The existing `m2-mainflow.mjs` host-sealed merge and two-project MIXED graph exports remain their own entries. This script does not exercise NO_NETWORK, and its original failed command results alone cannot attribute a permission cause. The output always has `acceptance: false`; a nonzero readback or a missing original tool is `NOT_RUN` or failure, never PASS.

Reference: `artifacts/gogoke-37/checkpoints/M2-HOST-COMMIT-AND-PROVIDER-FLOW.json` records the gogo-party `commitForSeat` host-seal precedent and its difference from design 37. This entry reuses the existing H/A/F V11 boundary driver and closed reader; it adds no model Git action or host merge substitute.
