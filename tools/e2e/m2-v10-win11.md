# Independent installed M2 V10 entry

`m2-v10-win11.mjs` runs the existing `m2-history-boundaries.mjs` flow and its
independent Codex peer file-read flow against the installed candidate. This is
an executable V10 evidence entry, separate from `m2-win11.mjs` and the V04b
memory entry. It does not grant M2 or Owner acceptance.

Use the fresh private fixture shape in `m2-memory-win11.md`, with
`historyBoundary.peerRead: true` and a fresh result/evidence directory. The
configured Codex and/or Claude cases need already logged-in fixed instances,
three exclusive Host-created and registered F worktrees per provider, and two
different project domains within `gogokeSeatTestbed`. The product, not this
driver, opens all sessions through the original User bridge. The script does
not register seats, log in, inspect credentials or read Owner conversations.
The formal, memory and ledger observers run before launch and after final close.

```powershell
& $SignedNode tools/e2e/m2-v10-win11.mjs $FreshPrivateFixture
```

The original history module opens two live project WORK sessions on one fixed
instance, then a SIDE_CHAT and a fresh FORMAL_REVIEW on a third binding. Its
original H/A/D/F records and normal-close immutable readback establish the
actual source domains, native identities, input bodies and stopped processes.
After a normal restart, the module sends the real `resume`, `reconnect`,
`compact`, `renew-session` and inherited formal `open` requests. Their original
DENIED receipts must preserve the revision and every scoped H/A/D/F row.

After the `final` readback, this entry restarts the same candidate and invokes
`runHistoryPeerReadCases`. For a qualified original Codex test JSONL path only,
new project-B WORK and project-A FORMAL_REVIEW sessions each ask the native
`exec_command` tool to read that exact non-secret project-A test object. The
`peer-final` reader requires the original H/A/F identities, tool started and
completed records, exact command, nonzero exit and original `Access is denied.`
output. Missing tool use, other output, unknown custody and model prose remain
`NOT_RUN`; an actual successful read fails. No synthetic ACL or denial is
constructed. The original test object is checked again for unchanged identity
and bytes after the attempts.

The entry records `v10: NOT_RUN_FULL_V10_SCOPE` even when all above direct
facts complete. The product currently lacks an exact model history-query tool
and Owner-lead test-object locator for worker-to-Owner-lead history; the M3
global store and cited distribution flow are separate, and this M2 entry cannot
invent them. Native file ToolReceipt proof is implemented for Codex only;
Claude, OpenCode and Grok need their own fixed-provider direct provenance.
Antigravity remains `NOT_RUN` by Owner decision. The reader also leaves
effective vendor history/memory provenance `NOT_RUN` where it cannot observe
it. A successful cloud build or source parse does not replace candidate Win11
execution.

The original module and reader are described in `m2-history-boundaries.md`.
The governing V10 text is `docs/design/gogoke-37-plan-v1/PLAN.json`; its
V04b/V10 candidate-body clarification is in that plan's `PLAN.md`. The
historical context/session rule and own-history/source audit are in
`docs/design/06-context-session-governance.md`,
`docs/research/2026-09-25-own-history-rework.md`, and
`docs/research/source-audit/07-ledger-workflow-context-sources.md`.
