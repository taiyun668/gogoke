# Independent installed M2 V10 entry

`m2-v10-win11.mjs` runs the existing `m2-history-boundaries.mjs` flow and its
independent Codex peer file-read flow against the installed candidate. This is
an executable V10 evidence entry, separate from `m2-win11.mjs` and the V04b
memory entry. It does not grant M2 or Owner acceptance.

Use the fresh private fixture shape in `m2-memory-win11.md`, with
`historyBoundary.peerRead: true` and a fresh result/evidence directory. The
configured Codex and/or Claude cases need already logged-in fixed instances,
three exclusive Host-created and registered F worktrees per provider, and two
different project domains within `gogokeSeatTestbed`. The product, not this
driver, opens all sessions through the original User bridge. The script does
not register seats, log in, inspect credentials or read Owner conversations.
The formal, memory and ledger observers run before launch and after final close.

```powershell
& $SignedNode tools/e2e/m2-v10-win11.mjs $FreshPrivateFixture
```

The original history module opens two live project WORK sessions on one fixed
instance, then a SIDE_CHAT and a fresh FORMAL_REVIEW on a third binding. Its
original H/A/D/F records and normal-close immutable readback establish the
actual source domains, native identities, input bodies and stopped processes.
After a normal restart, the module sends the real `resume`, `reconnect`,
`compact`, `renew-session` and inherited formal `open` requests. Their original
DENIED receipts must preserve the revision and every scoped H/A/D/F row.

After the `final` readback, this entry restarts the same candidate, opens a
fresh WORK session on the released project-A F/E binding, and checks its fixed
CLI pin. A `K-LEDGER/scoped-query` with `scope: PROJECT` must reach A's current
cursor as a STALE positive control. The same live reader then requests
`scope: GLOBAL`; the product must return DENIED with unchanged revision. H
must give a real stop fact before release. A released or nonexistent reader
cannot satisfy this control. This checks the existing project-to-global User
route only; it is not a model tool call or global-content/delivery test.
The requests and raw receipts remain in the private journal. The entry then
invokes `runHistoryPeerReadCases`. For a qualified original Codex test JSONL path only,
new project-B WORK and project-A FORMAL_REVIEW sessions each ask the native
`exec_command` tool to read that exact non-secret project-A test object. The
`peer-final` reader requires the original H/A/F identities, tool started and
completed records, exact command, nonzero exit and original `Access is denied.`
output. Missing tool use, other output, unknown custody and model prose remain
`NOT_RUN`; an actual successful read fails. No synthetic ACL or denial is
constructed. The original test object is checked again for unchanged identity
and bytes after the attempts.

For the additional same-domain WORK boundary, set:

```js
historyBoundary.sameDomainWorkerRead = {
  sourceSeatId, sourceIncarnation, workerSeatId, workerIncarnation,
};
```

The existing Codex `projectA` binding must be the exact Owner-designated
USER-layer project lead, and its original WORK turn must contain the non-secret
marker. The existing Codex `sideBinding` must be a distinct LEAD-layer worker
seat whose E `parent_seat_id` names that lead. Both are in `projectA.domainId`,
use the same fixed Codex instance, and retain their already registered F trees.
The four incarnation fields are private fixture facts supplied by Root; the
reader verifies them against `gogoke_v37_seat_project_lead`, E seats and both
original H episodes. No new seat, permission, history tool or authorization is
created by this test.

After the existing `peer-final` close/readback, the entry restarts the same
candidate, uses original User `K-SESSION` to open one fresh WORK turn on that
worker, and asks builtin `exec_command` to `type` only the lead's exact
already verified Codex JSONL path. It stops/releases and normally closes before
`same-domain-final` immutable readback. The reader binds the original User
lead marker input, H `thread/start` ACK/path, physical `session_meta` and
marker, E designated lead/incarnations, worker H/A/F identity, and exact native
tool action. An exact successful read is FAIL. A missing original action/path
is NOT_RUN; a generic nonzero exit is unattributed. Only an original exact
`Access is denied.` command result can be reported as direct denial. The
dedicated WORK history-query capability remains NOT_RUN.

The entry records `v10: NOT_RUN_FULL_V10_SCOPE` even when all above direct
facts complete. If the extra fixture is absent, same-domain worker access
remains NOT_RUN. Production already
has a Secretary-only `gogoke_ledger` model tool, but WORK cannot register or
invoke it. The M3 global-content and cited distribution flow still needs
positive original evidence. Native file ToolReceipt proof is implemented for Codex only;
Claude, OpenCode and Grok need their own fixed-provider direct provenance.
Antigravity remains `NOT_RUN` by Owner decision. The reader also leaves
effective vendor history/memory provenance `NOT_RUN` where it cannot observe
it. A successful cloud build or source parse does not replace candidate Win11
execution.
