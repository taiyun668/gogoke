## Historical model-Git attempt: invalid premise

The earlier `m2-v11-git-boundary.mjs` asked the model to run `git --version` and then `git worktree add` through builtin `exec_command`. This was the wrong V11 test target. The controlling [F.2 plan](../../docs/design/gogoke-37-plan-v1/PLAN.md) says the seat edits files only within its authorized host-created worktree and neither runs Git nor accesses `.git` (line 264); [PLAN.json](../../docs/design/gogoke-37-plan-v1/PLAN.json) repeats that boundary in the F.2 seam and V11 observation (lines 1289 and 2064). F uses the Owner-registered fixed Git pin after original H StopFact and no active admission reservation. The existing [F implementation](../../apps/desktop/native-host/src/store/worktree/f2.rs) reads the registered source and Git pin, seals the child through host Git, and performs the source merge (lines 769–774, 913–968). The existing `runV11Merge` in `m2-mainflow.mjs` remains the installed-product path for that boundary.

Both compatibility exports, `runV11GitProbe` and `runV11GitVendorAttempt`, now return `NOT_RUN_INVALID_PREMISE` with `acceptance: false`. They do not call the product, model, Git, or readback helper and do not mutate the journal. The original failed attempt and its readback remain in Root's private evidence; no result from that attempt establishes a V11 Git boundary PASS. The separate `m2-v11-git-readback.py` is historical and must not be used to revive model-Git testing under the current plan.
